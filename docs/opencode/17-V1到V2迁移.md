# 17 V1 到 V2 迁移

> 来源：官方 `migrate-v1`、`build/plugins/migrate-v1`、`cli/config`、`permissions`、`policies`、`providers`、`models`。
> 结论：**V2 的破坏性变更只有三处**——插件 API、server API/客户端、终端客户端配置。其余受支持的 V1 配置与文件型定义应继续工作；但权限、字段命名、默认行为有不少“看起来兼容、实际语义变了”的地方，必须逐项核对。

## 1. 迁移总览

### 1.1 三个真正的破坏性变更

| 领域 | V1 | V2 | 影响 |
|---|---|---|---|
| 插件 | 旧插件 API | 新插件 API | **V1 插件实现不能在 V2 运行**，改文件名/配置项无效 |
| Server API / 客户端 | 旧 HTTP API 与客户端 | 新契约 + `@opencode/client` | 所有调用方必须迁移 |
| 终端客户端配置 | 分层 `tui.json(c)` | 单一全局 `cli.json` | 首次启动自动迁移全局设置；项目级客户端配置不迁移 |

除此之外，V1 的配置位置、Agent/Command/Skill 文件、`AGENTS.md` 等应保持兼容。若受支持的行为在 V2 失效，应视为兼容性 bug。

### 1.2 推荐迁移顺序

1. **保留现有配置与文件**，不要先重写。
2. 启动 V2，验证模型、凭据、Agent、权限、MCP。
3. 移植插件（必须重写实现）。
4. 移植调用 server API 的集成。
5. 可选：把配置转成原生 V2 形状。
6. 验证通过前保留 V1 安装与配置副本。

> V1 与 V2 使用相同的配置位置。不要把 V1 指向已经转成 V2-only 形状的文件。

### 1.3 不要一次改完

V1 与原生 V2 字段可以在顶层共存；同一 canonical 值同时存在时，**合法的 V2 值优先**，与 JSON key 顺序无关。

但嵌套混用有限制：

- `mcp`、`compaction`、`experimental` 内可识别混合成员；
- 单个 Agent、Provider、Command、Model **必须整体使用一种格式**，不会递归推断；
- 合法 V1 语法静默接受；格式错误、遗留不支持字段、V1/V2 冲突会告警，但其他合法配置继续加载。

## 2. 安装与共存

V1 与 V2 都使用 `opencode` 命令，默认不再并行安装。

- 包管理器安装的 V1 需先移除，再装 V2；
- V2 的 curl 安装器会替换 V1 二进制；
- 升级/卸载：

```bash
opencode upgrade
opencode upgrade 2.0.21 --method bun
opencode uninstall --dry-run
opencode uninstall
```

`uninstall` 不会删除 Session 数据、配置与 state。

## 3. 配置位置与合并

V2 继续读取与 V1 相同的位置：

```text
/Library/Application Support/opencode/opencode.json(c)
/etc/opencode/opencode.json(c)
%ProgramData%\opencode\opencode.json(c)
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
~/.config/opencode/opencode.json(c)
<project>/opencode.json(c)
<project>/.opencode/opencode.json(c)
```

- 系统配置与 macOS managed preferences 优先级最高；
- 它们迁移后的 `enabled_providers` / `disabled_providers` 也高于全局/项目策略；
- 覆盖普通设置**不能阻止**用户新增 Provider、MCP、Agent、插件；管理员强制限制必须写成 `policies`，不要用 `permissions` 假装强制。

合并顺序与优先级见 [03-配置体系.md](03-配置体系.md)。

## 4. 字段对照表

### 4.1 权限与工具

V1 按工具分组；V2 使用一个有序 `permissions` 数组。

```jsonc
// V1
{
  "permission": {
    "bash": { "git push *": "ask" },
    "edit": "allow"
  },
  "tools": { "websearch": false }
}

// V2
{
  "permissions": [
    { "action": "shell", "resource": "git push *", "effect": "ask" },
    { "action": "edit", "resource": "*", "effect": "allow" },
    { "action": "websearch", "resource": "*", "effect": "deny" }
  ]
}
```

Action 变化：

| V1 | V2 |
|---|---|
| `bash` | `shell` |
| `task` | `subagent` |
| `write`、`patch` | `edit` |

`tools` 的布尔开关改为对应的 `permissions` deny。

**默认行为变化**：V1 在访问项目外路径前会询问；V2 的 `external_directory` 默认 **allow**。要保留 V1 行为：

```jsonc
{
  "permissions": [
    { "action": "external_directory", "resource": "*", "effect": "ask" }
  ]
}
```

### 4.2 Agent 与 mode

```jsonc
// V1
{
  "agent": {
    "reviewer": {
      "prompt": "Review for correctness and missing tests.",
      "model": "anthropic/claude-sonnet-5-5",
      "variant": "high",
      "disable": false,
      "permission": { "edit": "deny" }
    }
  }
}

// V2
{
  "agents": {
    "reviewer": {
      "system": "Review for correctness and missing tests.",
      "model": "anthropic/claude-sonnet-5-5#high",
      "disabled": false,
      "permissions": [
        { "action": "edit", "resource": "*", "effect": "deny" }
      ]
    }
  }
}
```

| V1 | V2 |
|---|---|
| `agent` | `agents` |
| `mode`（已弃用） | `agents`；原 `mode` 条目成为 primary agent |
| `prompt` | `system` |
| `disable` | `disabled` |
| `variant`（独立字段） | 并入模型引用 `provider/model#variant` |
| `maxSteps` | `steps` |
| `permission` | `permissions` |

**注意**：Agent 的 `request.body` 保留但**不发送给模型**。V1 的 `temperature`、`top_p`、`options` 放在这里无效；应设置到模型 variant 上。

```jsonc
{
  "providers": {
    "opencode": {
      "models": {
        "deepseek-v4.1-flash": {
          "variants": [
            {
              "id": "review",
              "body": {
                "thinking": { "type": "disabled" },
                "temperature": 0.2
              }
            }
          ]
        }
      }
    }
  },
  "agents": {
    "reviewer": { "model": "opencode/deepseek-v4.1-flash#review" }
  }
}
```

Provider JSON 字段用 `body`，Provider 包选项用 `settings`。

### 4.3 快照

```jsonc
// V1
{ "snapshot": false }

// V2
{ "snapshots": false }
```

布尔值语义不变。

### 4.4 媒体 / 附件

```jsonc
// V1
{ "attachment": { "image": { "auto_resize": true } } }

// V2
{ "media": { "image": { "auto_resize": true } } }
```

嵌套图片设置名称不变。

### 4.5 MCP

```jsonc
// V1
{
  "mcp": {
    "playwright": {
      "type": "local",
      "command": ["npx", "@playwright/mcp"],
      "enabled": true,
      "timeout": 30000
    }
  }
}

// V2
{
  "mcp": {
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["npx", "@playwright/mcp"],
        "disabled": false,
        "timeout": {
          "catalog": 30000,
          "execution": 30000
        }
      }
    }
  }
}
```

| V1 | V2 |
|---|---|
| `mcp.<name>` | `mcp.servers.<name>` |
| `enabled` | 反向的 `disabled` |
| `timeout`（单值） | `timeout.catalog` / `timeout.execution` |
| `clientId` | `client_id` |
| `clientSecret` | `client_secret` |
| `callbackPort` | `callback_port` |
| `redirectUri` | `redirect_uri` |
| `experimental.mcp_timeout` | 默认 `mcp.timeout.catalog` 与 `.execution` |

### 4.6 压缩

```jsonc
// V1
{ "compaction": { "preserve_recent_tokens": 8000, "reserved": 20000 } }

// V2
{
  "compaction": {
    "keep": { "tokens": 8000 },
    "buffer": 20000
  }
}
```

| V1 | V2 |
|---|---|
| `preserve_recent_tokens` | `compaction.keep.tokens` |
| `reserved` | `compaction.buffer`（也接受 `"15%"`） |
| `auto` | `auto` |
| `tail_turns` | **无原生等价**；V2 用 token 预算保留最近上下文 |
| `prune` | **无原生等价**；忽略并告警 |

### 4.7 技能

```jsonc
// V1
{ "skills": { "paths": ["./team-skills"], "urls": ["https://example.com/skills/"] } }

// V2
{ "skills": ["./team-skills", "https://example.com/skills/"] }
```

现有技能文件与 `.opencode/skills/` 自动发现不变。

### 4.8 命令

```jsonc
// V1
{
  "command": {
    "review": {
      "template": "Review the current changes.",
      "model": "anthropic/claude-sonnet-5-5",
      "variant": "high",
      "subtask": true
    }
  }
}

// V2
{
  "commands": {
    "review": {
      "template": "Review the current changes.",
      "model": "anthropic/claude-sonnet-5-5#high",
      "subagent": true
    }
  }
}
```

| V1 | V2 |
|---|---|
| `command` | `commands` |
| `subtask` | `subagent`（旧名仍接受） |
| `variant` | 并入 `model#variant` |
| `template`、`description`、`agent` | 不变 |

委托命令现在会自动在后台运行并把结果报告回父 Session。

### 4.9 引用

```jsonc
// V1
{ "reference": { "docs": "../docs" } }

// V2
{ "references": { "docs": "../docs" } }
```

V1 已接受 `references`，无需改。

### 4.10 Provider

```jsonc
// V1
{
  "provider": {
    "acme": {
      "npm": "@ai-sdk/openai-compatible",
      "api": "https://llm.example.com/v1",
      "options": { "apiKey": "{env:ACME_API_KEY}" }
    }
  }
}

// V2
{
  "providers": {
    "acme": {
      "package": "aisdk:@ai-sdk/openai-compatible",
      "settings": {
        "baseURL": "https://llm.example.com/v1",
        "apiKey": "{env:ACME_API_KEY}"
      }
    }
  }
}
```

| V1 | V2 |
|---|---|
| `provider` | `providers` |
| `npm` | `package`；AI SDK 包加 `aisdk:` 前缀 |
| `api` | `settings.baseURL` |
| `options` | 拆到 `settings`、`headers`、`body` |
| `options.setCacheKey` | `compatibility.supportsPromptCacheKey` |

Provider ID 合并：

| V1 | V2 |
|---|---|
| `azure-cognitive-services` | `azure` |
| `google-vertex-anthropic` | `google-vertex` |

顶层 `model` 字段为保持语法有效，保留原 Provider ID；迁移旧内置 Provider 时应改成 canonical ID。

### 4.11 模型与 variant

| V1 | V2 |
|---|---|
| `id` | `modelID` |
| `tool_call`、`modalities` | `capabilities.tools`、`capabilities.input`、`capabilities.output` |
| `status: "deprecated"` | `disabled: true` |
| `cache_read`、`cache_write` | `cache.read`、`cache.write` |
| `options` | `settings` |
| `variants` 对象 | `variants` 数组，每项带 `id` |

```jsonc
// V1
{ "variants": { "high": { "reasoningEffort": "high" } } }

// V2
{
  "variants": [
    { "id": "high", "settings": { "reasoningEffort": "high" } }
  ]
}
```

### 4.12 插件

```jsonc
// V1
{ "plugin": ["opencode-example-plugin", ["./plugin/local.ts", { "enabled": true }]] }

// V2
{
  "plugins": [
    "opencode-example-plugin",
    { "package": "./plugin/local", "options": { "enabled": true } }
  ]
}
```

| V1 | V2 |
|---|---|
| `plugin` | `plugins` |
| `[包, 选项]` 元组 | `{ package, options }` 对象 |
| 本地文件 | 本地**目录**；入口 `index.ts` |

V2 同时发现 `.opencode/plugin/` 与 `.opencode/plugins/`；V2 文件建议放后者。**V1 插件实现不能直接运行**，必须按新 API 重写，见 [14-插件开发.md](14-插件开发.md)。

## 5. 行为变化（最容易被忽略）

### 5.1 默认值

| 项 | V1 | V2 |
|---|---|---|
| `external_directory` | 默认询问 | 默认 **allow** |
| Todos | 默认开启 | 默认 **关闭**，需 `experimental.todo: true` |
| LSP | 运行语言服务器 | **不运行**，不暴露 LSP 工具/诊断 |
| 更新 | `autoupdate` | `update`：`disable`/`notify`/`auto`，默认 `notify` |

### 5.2 字段迁移到策略

| V1 | V2 |
|---|---|
| `enabled_providers` | 内部 deny-by-default + 列出的 allow 策略 |
| `disabled_providers` | 内部 deny 策略 |
| `small_model` | 内置 `title` Agent 的 `model`，原生 V2 用 `agents.title.model` |
| `subagent_depth`（顶层） | `experimental.subagent_depth` |

这些 V1 字段仍可保留，OpenCode 会无警告归一化。

### 5.3 接受但不支持

以下字段 V2 会忽略并告警：

- `logLevel` → 用 `OPENCODE_LOG_LEVEL`
- `server` → 用 V2 service 与显式 server 选项
- 顶层 `subagent_depth` → 用 `experimental.subagent_depth`
- `compaction.tail_turns`、`compaction.prune`
- V1 JSON 配置中的 Agent `name`
- 没有 `type` 的 enabled-only MCP 条目
- V1 experimental：`batch_tool`、`openTelemetry`、`primary_tools`、`continue_loop_on_deny`
- V1 Provider：`id`、`whitelist`、`blacklist`
- V1 Provider-Model：`release_date`、`attachment`、`reasoning`、`temperature`、`experimental`、非 deprecated 的 `status`、布尔 `interleaved`

忽略是**有意行为**，不是兼容性回归。不要把这些字段当成仍然生效。

## 6. 文件型定义迁移

### 6.1 Agent 文件

V1 可能使用 `agent/`、`agents/`、`mode/`、`modes/`；V2 仍全部发现。推荐：

```text
.opencode/agents/<name>.md
```

- `mode/`、`modes/` 下的文件是 primary agent；移到 `agents/` 时 frontmatter 加 `mode: primary`。
- `agent/` 移到 `agents/` 不改变由路径派生的 ID。
- Markdown 正文就是 system instructions；JSON 配置里才需要 `system` 字段。
- `prompt` → `system`（仅 JSON）；`disable` → `disabled`；`permission` → `permissions`；`model` + `variant` → `provider/model#variant`。
- 一个文件只能整体使用一种格式。出现 `permissions`、`request`、`system`、`disabled` 任一即按 V2 读取；文件里的 V1 字段（`name`、`tools`、`permission`、`temperature`）会被忽略并告警。

### 6.2 Command 文件

V1 可能用 `command/` 或 `commands/`；V2 都发现。推荐：

```text
.opencode/commands/<name>.md
```

- 移到 `commands/` 下相同相对路径以保留命令名。
- Markdown 正文仍是模板；`description`、`agent` 不变。
- `subtask` → `subagent`。
- 独立 `model` + `variant` → `model: provider/model#variant`，删除 `variant`。

### 6.3 Skill 文件

V2 从 `.opencode/skill/` 与 `.opencode/skills/` 都发现。推荐：

```text
.opencode/skills/<skill-id>/SKILL.md
```

- 移动**整个技能目录**，保留相对脚本、引用等文件。
- 目录名保持稳定以保留 skill ID。
- frontmatter 与正文无需重写。

### 6.4 指令文件

- 现有 `AGENTS.md` 保留。
- V2 发现全局 `~/.config/opencode/AGENTS.md`，以及从当前目录到 home 的 ambient `AGENTS.md`；home 外的项目在项目根停止。
- **V2 只发现 `AGENTS.md`**，不自动回退 `CLAUDE.md`。依赖 V1 回退的项目需把内容迁到 `AGENTS.md`。

## 7. 终端客户端配置

V1 使用分层 `tui.json(c)`；V2 使用单一全局：

```text
~/.config/opencode/cli.json
```

- 该文件归终端客户端所有，后台 server 不加载。
- `cli.json` 不存在时，首次 V2 终端启动会迁移受支持的全局 `tui.json` 设置与持久偏好，并保留 V1 文件不变。
- **项目级客户端配置不迁移**，因为 V2 客户端配置是全局的。
- 迁移后不要同时维护两套键位/主题配置。

## 8. Server API 与认证

### 8.1 认证

V2 仍用 HTTP Basic Auth，但：

| V1 | V2 |
|---|---|
| `OPENCODE_SERVER_PASSWORD` | `OPENCODE_PASSWORD`（旧名仍兼容） |
| `OPENCODE_SERVER_USERNAME` 可自定义 | **不再支持**；用户名固定 `opencode` |

```bash
# V1
OPENCODE_SERVER_USERNAME=alice OPENCODE_SERVER_PASSWORD=secret opencode serve

# V2
OPENCODE_PASSWORD=secret opencode serve
```

### 8.2 API 契约

V1 的集成必须迁移到 V2 API：

- 端点、请求/响应包裹、错误 `_tag`、分页 cursor 都可能不同；
- 使用 `@opencode/client` 访问已发布的 V2 API；
- 以 `openapi.json` / `/api` 页面为准，不要按 V1 的路径猜；
- 事件流是 live-only，断线需重连并用快照接口对账。

详见 [12-HTTP-API参考.md](12-HTTP-API参考.md) 与 [13-客户端-SDK-ACP.md](13-客户端-SDK-ACP.md)。

## 9. 插件迁移

### 9.1 配置形状

见 4.12。补充：

- 本地插件路径必须是**目录**；把移植后的入口放到 `./plugin/local/index.ts`。
- V2 同时发现 `.opencode/plugin/` 与 `.opencode/plugins/`。
- 被 `policies` deny 的插件不会加载，无论从哪里配置。

### 9.2 实现

V1 插件不能运行。需要按 V2 API 重写：

- 入口、hooks、tools、events、package exports 全部变化；
- server 插件用 `ctx.tool.transform` 注册工具；
- transforms 同步、可重放，外部数据变化后调用 `reload()`；
- hooks 按插件顺序运行；
- `prompt` hook 在持久 inbox 准入前、只运行一次，不是 exactly-once；
- `permission.hook("evaluate")` 只对 `allow`/`ask` 运行，显式 `deny` 不调用。

完整对照见官方 `build/plugins/migrate-v1` 与 [14-插件开发.md](14-插件开发.md)。

- [ ] 需要审批外部路径的项目已加 `external_directory` 规则。

### 文件

- [ ] Agent 文件在 `agents/`，primary agent 有 `mode: primary`。

## 11. 常见坑

| 坑 | 说明 |
|---|---|
| 以为改个插件文件名就能用 | V1 插件实现与 V2 API 不兼容，必须重写 |
| 同时保留 V1/V2 客户端配置 | V2 只用全局 `cli.json`，项目级配置不会迁移 |
| 把 `tools` 布尔开关照搬 | V2 用 `permissions` 的 deny |
| 忘记 `external_directory` 默认已放开 | 敏感环境必须显式 `ask`/`deny` |
| 把 `temperature` 放在 Agent `request.body` | V2 不发送给模型，应放到模型 variant |
| 嵌套混用 V1/V2 字段 | Agent/Provider/Command/Model 必须整体一种格式 |
| 用 `enabled_providers` 做强制限制 | 应改用 `policies`；普通设置可被项目覆盖 |
| 期待 LSP 继续工作 | V2 不运行语言服务器，改用 lint/typecheck/compiler |
| 依赖 `opencode server` 配置 | V2 忽略，改用 service 与显式 server 选项 |
| 忽略告警 | 被忽略的字段不会生效，排障时先看 server 日志 |
