# 10 技能、指令与命令

> 来源：官方 `skills`、`instructions`、`commands`、`agents`、`migrate-v1`、`config`。
> 三者都是“把可复用的文本/流程注入会话”的机制，但生命周期不同：**指令常驻，技能按需加载，命令即时展开**。

## 1. 概念对比

| 机制 | 文件/位置 | 何时进入上下文 | 是否可执行代码 | 典型用途 |
|---|---|---|---|---|
| 指令（Instructions） | `AGENTS.md`、`instructions[]` | 会话开始 + 发现新目录时 | 否 | 项目规范、构建命令、架构说明 |
| 技能（Skills） | `.opencode/skills/<id>/SKILL.md` | Agent 调用 `skill` 工具时 | 可带脚本（由 Agent 再执行） | 专项流程、发布、审查 |
| 命令（Commands） | `.opencode/commands/<name>.md` | 用户输入 `/name` 时 | 可含 shell block（提交前执行） | 固定 prompt 模板、参数化任务 |

## 2. 技能（Skills）

### 2.1 创建

最小形式：

```markdown title=".opencode/skills/git-release/SKILL.md"
---
name: Git Release
description: Prepare release notes, version bumps, and GitHub releases
---

## Workflow

1. Read `references/release-policy.md`.
2. Summarize merged changes since the previous tag.
3. Propose the version bump before changing files.
4. Run `scripts/changelog.ts` only after the user approves the version.
```

目录形式推荐，因为支持文件有私有根目录：

```text
.opencode/skills/
└── git-release/
    ├── SKILL.md
    ├── scripts/
    │   └── changelog.ts
    └── references/
        └── release-policy.md
```

技能内写的路径相对于 `SKILL.md` 所在目录。

### 2.2 发现位置

| 范围 | 来源 |
|---|---|
| 全局 | `~/.config/opencode/skills` |
| 全局兼容 | `~/.claude/skills`、`~/.agents/skills` |
| 项目 | `.opencode/skills` |
| 项目兼容 | `.claude/skills`、`.agents/skills` |

项目来源从当前目录向上搜索到项目根，包含每一层的匹配目录。

每个来源可包含两种形式：

```text
skills/
├── review.md                 # 根级 Markdown
└── git-release/
    └── SKILL.md              # 嵌套，但文件名必须正好是 SKILL.md
```

规则：

- Markdown 文件必须在来源根目录，例如 `skills/review.md`。
- 只有名为 `SKILL.md` 的文件可以嵌套在分组目录中，例如 `skills/teams/release/SKILL.md`。
- 含 `SKILL.md` 的目录算一个技能；OpenCode 不会继续在它内部搜索技能。
- 跳过隐藏文件/目录与 `node_modules`。
- 最多搜索到来源根以下 6 层。

### 2.3 额外来源

```jsonc
{
  "skills": [
    "./team-skills",
    "~/shared/opencode-skills",
    "/opt/company-skills",
    "https://example.com/opencode/skills/"
  ]
}
```

| 值 | 解析 |
|---|---|
| 相对路径 | 从**当前 OpenCode 工作目录**解析，不是配置文件所在目录 |
| `~/` | 当前用户 home |
| 绝对路径 | 原样使用 |
| `http(s)://` | HTTP catalog |

所有发现的配置文件都会贡献条目；`skills` 数组是**合并**而非替换。

### 2.4 HTTP catalog

base URL 下需要 `index.json`：

```json
{
  "skills": [
    {
      "name": "git-release",
      "version": "3",
      "files": ["git-release.md", "references/release-policy.md"]
    }
  ]
}
```

OpenCode 从 `<base-url>/git-release/<file>` 下载每个文件。

| 规则 | 要求 |
|---|---|
| 路径 | 安全、相对、同源 |
| 入口文件 | 必须包含 `SKILL.md` 或 `<name>.md` |
| 更新 | 文件变化时递增 `version`，以刷新缓存 |

每个下载的技能目录成为一个来源根，因此 `git-release.md` 与 `SKILL.md` 的 ID 都是 `git-release`。

### 2.5 Frontmatter

```markdown
---
name: Git Release
description: Prepare a repository release
metadata:
  opencode/autoinvoke: false
---
```

| 字段 | 行为 |
|---|---|
| `name` | 显示名；默认由路径推导的 ID |
| `description` | 展示给模型的摘要 |
| `metadata.opencode/autoinvoke` | `false` 时不进入模型可用列表 |
| `disable-model-invocation` | `true` 等价于 `opencode/autoinvoke: false` |

- 运行时所有 frontmatter 可选；没有 `description` 的技能不会被广告给模型。
- `autoinvoke: false` 只是隐藏，技能仍注册、仍可按 ID 显式加载。
- 两者同时设置时 `opencode/autoinvoke` 优先。
- V2 接受 `license`、`compatibility` 等可移植字段，但不解释它们。

### 2.6 ID 与优先级

ID 由文件路径决定，frontmatter 的 `name` 只是显示标签：

| 文件 | ID |
|---|---|
| `<source>/git-release.md` | `git-release` |
| `<source>/git-release/SKILL.md` | `git-release` |
| `<source>/teams/release/SKILL.md` | `release` |

- ID **大小写敏感**。
- 推荐小写 kebab-case、1–64 字符：`^[a-z0-9]+(-[a-z0-9]+)*$`（V2 暂不强制）。

来源注册顺序（低 → 高）：

1. 内置技能
2. `.claude/skills`（全局，然后从最远祖先到当前目录）
3. `.agents/skills`（同上）
4. `~/.config/opencode/skills`
5. 项目 `.opencode/skills`（从项目根到当前目录）
6. 显式 `skills` 配置条目（按配置优先级与数组顺序）

后注册的同 ID 技能覆盖先注册的。

### 2.7 加载过程

每个模型 step，OpenCode 列出“有 description 且未设置 autoinvoke:false 的允许技能”，只包含 ID、name、description，不包含正文。

模型调用 `skill` 工具：

```json
{ "id": "git-release" }
```

OpenCode 随后：

1. 选择该 ID 的当前定义；
2. 检查当前 Agent 的 `skill` 权限；
3. 把 Markdown 正文（不含 frontmatter）加入对话；
4. 提供技能根目录与最多 10 个支持文件路径样本。

用户也可以在 prompt 中用 `@skill-id` 显式加载。支持文件内容不会自动加载，由 Agent 按需读取。

### 2.8 权限

```jsonc
{
  "permissions": [
    { "action": "skill", "resource": "*", "effect": "allow" },
    { "action": "skill", "resource": "internal-*", "effect": "deny" },
    { "action": "skill", "resource": "experimental-*", "effect": "ask" }
  ]
}
```

| effect | 行为 |
|---|---|
| `allow` | 广告并加载，不提示 |
| `ask` | 广告，但加载前询问 |
| `deny` | 从模型列表隐藏并拒绝加载 |

### 2.9 排障

- 确认文件是根级 `*.md` 或正好叫 `SKILL.md`。
- 检查**路径推导**的、大小写敏感的 ID，而不是 frontmatter `name`。
- 想要被发现，必须有 `description`。
- 检查 `opencode/autoinvoke` 与 Agent 的 `skill` 权限。
- 检查是否有更高优先级来源定义了同 ID。
- HTTP catalog 检查 `index.json`、同源路径、`version` 是否更新。

## 3. 指令（Instructions）

### 3.1 `AGENTS.md`

```markdown title="AGENTS.md"
# Project instructions

- Run `bun typecheck` after changing TypeScript.
- Keep database queries in `src/database`.
- Do not edit generated files directly.
```

- 放在需要生效的目录；OpenCode 加载全局文件 + 从当前 workspace 目录向 home 方向的每个 `AGENTS.md`。
- workspace 在 home 之外时，搜索停在项目根。
- 合并顺序：全局 → 更近的目录 → 更远的目录（示例中 `packages/web` 在 `packages` 之前，根目录最后）。
- 只合并不解决冲突；冲突需要人写清楚。
- workspace 在项目根之外时，只加载全局文件。
- `OPENCODE_DISABLE_PROJECT_CONFIG=1` 可跳过项目 `AGENTS.md` 发现，但不禁用全局文件。
- **V2 只识别 `AGENTS.md`，不把 `CLAUDE.md` 作为回退。**

### 3.2 动态发现

```text
my-project/                         ← 当前 workspace
├── AGENTS.md                       loaded initially
└── packages/
    └── web/
        ├── AGENTS.md               loaded when this area is read
        └── src/
            └── app.ts              read target
```

- 读取文件/列目录时，加载目标与 workspace 之间的 `AGENTS.md`。
- 嵌套文件 nearest-first、去重；只要记录仍在模型可见历史中，再次读同一区域不会重复注入。
- 压缩或 revert 移除记录后，再次读取可能重新加载。
- 嵌套文件加载后**不会自动检测编辑**；需要新会话才能立即生效。

### 3.3 组装顺序

```text
1. Agent 或 provider 的 system prompt
2. Code Mode 工具指导（启用时）
3. MCP server、reference、skill 指导
4. 全局与项目 AGENTS.md，然后配置的 instructions
5. 内置日期与环境上下文
6. 通过 API 提供的会话级 instruction entries
```

这些来源是组合，不是覆盖。后发现的嵌套 `AGENTS.md` 按发现顺序加入会话历史。

### 3.4 更新

编辑全局或向上发现的 `AGENTS.md`，会在下一次模型请求前被检测，并作为 instruction update 插入：

```text
AGENTS.md changes
→ instruction update
→ next prompt
```

- 删除所有 ambient `AGENTS.md` 会告诉会话“之前的 ambient 指令不再适用”。
- 临时读取失败会保留上一次已知指令，而不是当作删除。
- 移动会话会保留指令状态；目标位置的指导作为 update 引入。
- 提交 revert 会清除指令状态，并在下一次 prompt 前重新加载。
- 指令内容对客户端不可见（只能看到“哪个来源变了”）。

### 3.5 `instructions` 配置

```jsonc
{
  "instructions": [
    "CONTRIBUTING.md",
    "docs/guidelines/*.md",
    "~/rules/opencode.md",
    "https://example.com/instructions.md"
  ]
}
```

| 条目 | 解析 |
|---|---|
| 相对路径/glob | 从 workspace 向项目根逐目录搜索 |
| `~/` | home |
| 绝对路径 | 原样；文件名可以是 glob |
| `http(s)://` | 配置加载时抓取，5 秒超时 |

- 本地文件变化时像 `AGENTS.md` 一样更新；glob 新匹配的文件在下一次配置变化时加载。
- 缺失文件跳过；URL 抓取失败跳过或保留最后一次内容。
- `OPENCODE_DISABLE_PROJECT_CONFIG=1` 或 workspace 在项目外时，相对条目按全局配置目录解析。
- Console workspace 也可下发 instructions。

## 4. 命令（Commands）

### 4.1 Markdown 命令

```markdown title=".opencode/commands/review.md"
Review $ARGUMENTS for bugs and missing tests.
```

TUI 中：

```text
/review src/auth.ts
```

提交为：

```text
Review src/auth.ts for bugs and missing tests.
```

位置：

```text
~/.config/opencode/commands/review.md      # 全局
.opencode/commands/review.md               # 项目
```

- 只发现 `.md` 文件。
- 嵌套路径变成带 `/` 的命令名：`.opencode/commands/team/review.md` → `/team/review`。
- 旧的单数目录 `command/` 仍会被发现，但新文件应放 `commands/`。

### 4.2 JSON 命令

```jsonc
{
  "commands": {
    "review": {
      "description": "Review code for correctness",
      "template": "Review $ARGUMENTS. Report bugs first."
    }
  }
}
```

JSON 命令必须有 `template`。

### 4.3 字段

| 字段 | 必填 | 行为 |
|---|---|---|
| `template` | 仅 JSON | prompt 模板 |
| `description` | 否 | 命令列表/发现中显示 |
| `agent` | 否 | 运行时选择的 Agent |
| `model` | 否 | `provider/model` 或 `provider/model#variant` |
| `subagent` | 否 | `true` 在后台子会话运行；`false` 强制当前会话 |
| `subtask` | 否 | 已弃用别名；两者都存在时 `subagent` 优先 |

Markdown frontmatter 与 JSON 条目接受相同字段，但 Markdown 的 `template` 来自正文，**不要**在 frontmatter 里写 `template`。

完整示例：

```jsonc
{
  "commands": {
    "audit": {
      "template": "Audit $ARGUMENTS.",
      "description": "Audit a package",
      "agent": "general",
      "model": "anthropic/claude-sonnet-5-5#high",
      "subagent": true
    }
  }
}
```

### 4.4 参数展开

- `$ARGUMENTS`：完整参数字符串，原样。
- `$1`、`$2`…：位置参数；单/双引号分组并去除。
- 最高编号的位置参数会吞掉它及其后的所有参数；缺失位置变成空字符串。
- 没有 `$ARGUMENTS` 也没有位置参数时，非空参数会追加到模板后（空行分隔）。

示例：

```markdown
Check $1. Focus on $2.
```

`/check src/auth.ts "error handling"` → `$1=src/auth.ts`，`$2=error handling`。

```markdown
Compare $1 with $2.
```

`/compare api stable branch` → `Compare api with stable branch.`（`$2` 吞掉 `stable branch`）。

### 4.5 Shell block

用 `!` + 反引号插入命令输出：

```markdown
Review this diff:

!`git diff --stat && git diff`
```

- 在活动项目 Location 中用配置的 shell 执行，插入合并输出。
- 参数占位符先展开：`!`git log --oneline -$1``。
- **不要在 shell block 中放不可信参数**。
- Shell block 在命令求值时执行，**绕过 Agent 工具权限流程**；只使用可信来源。

### 4.6 附件

存储的模板不会展开 `@path`，它只是普通 prompt 文本：

```markdown
Review @README.md.
```

要附加文件，在调用命令时通过 composer 添加；OpenCode 会保留这些附件。

### 4.7 执行与模型选择

命令在提交前展开参数与 shell block，然后作为 durable user prompt 入队；默认在当前会话运行。

模型优先级：

1. 命令的 `model`
2. 否则命令 Agent 配置的模型
3. 否则当前会话模型

Agent：`/plan migration` 会先把当前会话切到 `plan`，再提交 prompt。

### 4.8 后台子会话

```markdown
---
description: Audit changes
agent: general
subagent: true
---

Audit $ARGUMENTS for bugs and missing tests.
```

| `subagent` | 行为 |
|---|---|
| `true` | 总是用子会话，即使 Agent 是 `mode: primary` |
| `false` | 总是用当前会话，即使 Agent 是 `mode: subagent` |
| 省略 | 仅当 Agent 是 `mode: subagent` 时用子会话 |

子会话模型顺序：命令 `model` → 选中 Agent 的模型 → 父会话模型。完成后把结果/失败回传父会话。

### 4.9 加载与覆盖

Markdown 与 JSON 命令共用一个注册表；后加载的同名命令替换先前的：

```text
~/.config/opencode/commands/review.md   # 低优先级
.opencode/commands/review.md            # 替换全局
```

- 项目来源覆盖全局；更近的项目来源覆盖祖先。
- 自定义定义可以替换内置命令。
- 命令文件与配置变更会自动重载；保存后无需重启。

## 5. 与 Agent 的关系

- Agent 可以限制 `skill` 权限（隐藏/拒绝技能）。
- 命令可以指定 `agent`，从而切换执行者。
- `AGENTS.md` 与 `instructions` 注入所有 Agent；Agent 自己的 `system` 在其之前。
- 子 Agent 也会收到全局指令，但项目 `AGENTS.md` 的发现基于其会话目录。

## 6. 控制面关注点

- **技能/命令/指令都属于 Location**：切换目录或移动会话会改变可见集合。控制面缓存时要带 `location.directory` 作为键。
- **技能正文可能很长**：不要把所有技能正文都拉进控制面 UI；只展示 ID/name/description，按需预览。
- **命令的 shell block 绕过权限**：控制面若允许用户创建/编辑命令，应视为“可执行代码”，做来源校验与审计。
- **`AGENTS.md` 内容对客户端不可见**：控制面无法通过 API 读取“当前生效的指令原文”（只能看到来源变化）。需要展示时，应直接读文件系统（受权限约束）。
- **`instructions` 支持 URL**：远程指令有 5 秒超时，失败会跳过/保留旧内容；控制面不要假设它总是最新。
- **命令参数展开在 server 侧完成**：控制面只需提交 `name` + `text`，不要自己展开 `$1`。
- **`subagent: true` 是后台执行**：控制面要能展示子会话（`parentID`）并在完成后回传结果。
