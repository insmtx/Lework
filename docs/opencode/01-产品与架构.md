# 01 产品与架构

> 来源：官方 `docs.md`、`cli.md`、`cli/web`、`cli/commands`、`config`、`troubleshooting`、`build/plugins/server`，以及 `openapi.json`。
> 适用：OpenCode 2.x。

## 1. 产品形态

OpenCode 是一个开源编码 Agent，提供四种前端：

| 形态 | 入口 | 说明 |
|---|---|---|
| 终端全屏 TUI | `opencode` | 主界面，支持 `/命令`、多会话、diff、主题、键位 |
| 极简交互 | `opencode mini` | 非全屏终端界面，适合快速会话 |
| 桌面应用 | OpenCode Desktop | 内嵌/连接 server，提供面板、GUI 插件、浏览器工具 |
| Web | `opencode pair` 打开的网页 | 与 TUI 共用同一个 server，密码保护 |
| 非交互 CLI | `opencode run "..."` | 脚本 / CI，输出到 stdout，可 `--format json` |
| 编辑器 Agent | `opencode acp` | 通过 ACP（Agent Client Protocol）供 Zed 等编辑器使用 |

所有前端都**不是**各自维护一套会话：它们连接同一个后台 server。

## 2. 总体架构

```text
┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│  TUI / mini  │  │ Desktop 应用 │  │ Web 浏览器   │  │ run / api    │
└──────┬───────┘  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘
       │ HTTP + SSE       │ HTTP + SSE       │ HTTP + SSE       │ HTTP
       └──────────────────┴────────┬─────────┴──────────────────┘
                                   │
                    ┌──────────────▼───────────────┐
                    │  OpenCode Server (共享后台)  │
                    │  - sessions / messages       │
                    │  - config / plugins          │
                    │  - permissions / policies    │
                    │  - tools / MCP / skills      │
                    │  - snapshots / VCS / PTY     │
                    └──────┬───────────────┬───────┘
                           │               │
                  ┌────────▼──────┐  ┌─────▼────────────┐
                  │ SQLite 数据库  │  │ Provider APIs     │
                  │ + 本地对象存储 │  │ (HTTPS/WebSocket) │
                  └───────────────┘  └──────────────────┘
```

关键点：

- **server 是唯一状态所有者**。客户端可以随时崩溃/重连，不会丢会话。
- 默认情况下，每个用户账号只有**一个共享后台 server**；`opencode serve` 可以在前台再起一个独立 server（`--standalone` 让单条 CLI 命令使用私有 server）。
- server 通过 **HTTP API** 提供读写，通过 **SSE**（`GET /api/event`）推送实时事件；PTY 另有 WebSocket 连接。
- 桌面端的 GUI 插件、TUI 插件、ACP 都只是不同前端/插件运行时，最终仍调用同一套 server API。

## 3. Location、Project、Worktree、Session

这四个概念决定了“配置从哪里来、文件能改哪里、会话属于谁”。

| 概念 | 含义 | 关键事实 |
|---|---|---|
| **Location** | 一个被 server 打开的目录（通常是一个项目 checkout 的某个子目录） | 读取类 API 返回 `location`；配置、模型、Agent、MCP 都按 location 解析；空闲可被卸载 |
| **Project** | 由 Git 仓库/canonical checkout 标识的项目 | 有稳定的 `projectID`；worktree、session 迁移、项目级 API 使用它 |
| **Worktree** | 项目的 Git 工作树 | 可由 `worktree_create` 创建；session 可移动到 worktree；去除时默认要求无未提交改动 |
| **Session** | 一次对话（可含子会话） | 记录 `projectID`、`location`、agent、model、权限规则、revert 状态、token/cost |

重要约束：

- session 的 `location.directory` 是它创建/移动后的目录；`subpath` 是相对项目根的路径。
- 路径在 location 内是“相对内部路径”，在 location 外是“规范化绝对路径”；跨目录访问要过 `external_directory` 权限。
- 一个 server 可以同时打开多个 location；`experimental.location_idle_timeout` 控制空闲卸载（默认 60 分钟，`false` 表示永不卸载）。

## 4. 进程模型与启动方式

| 方式 | 命令 | 特点 |
|---|---|---|
| 共享后台 server（默认） | 任意客户端自动发现；`opencode service start/stop/restart/status` | 一个用户一个实例，注册文件 `~/.local/state/opencode/service.json` |
| 前台独立 server | `opencode serve --hostname 0.0.0.0 --port 4096` | 自己管理端口/CORS/密码，适合容器、systemd、远程主机 |
| 单命令私有 server | `opencode run --standalone ...` | 命令结束即退出，不污染共享会话 |
| 指定 server | `opencode --server http://127.0.0.1:4096` | 客户端连接已有 server |
| ACP | `opencode acp` | 为 ACP 客户端启动**私有** server，不连共享服务、不开 ACP 网络端口 |
| 嵌入式 SDK | `@opencode/sdk` 的 `OpenCode.create()` | 进程内组装 server，走内存路由，无 HTTP 监听 |

共享后台 server 的默认监听：

| 平台 | 默认端口 |
|---|---|
| macOS / Linux / WSL | 49374 |
| Windows | 28894 |

默认只绑定回环地址；改动 `hostname`/`port`/`password`/`cors` 会停止后台 service，需要 `opencode service start` 重新启动。

## 5. 认证与安全模型

- HTTP Basic Auth：用户名固定 `opencode`，密码由 `OPENCODE_PASSWORD`（或 service 配置的 `password`）提供；未设置时自动生成。
- `opencode pair` 生成一次性登录链接（5 分钟有效、只能用一次），换取 30 天会话 Cookie；修改密码会让所有会话失效。
- server 默认只监听 localhost；`opencode pair --remote` 通过 OpenTunnel 暴露到公网（端到端加密，仍需密码），首次会要求确认。
- 工具执行使用**宿主用户的文件系统、进程与网络权限**；`shell` 不是沙箱。权限规则是“防误操作”，不是安全边界。
- 快照对象可能包含文件完整内容；OpenCode 数据目录应按敏感本地数据处理。

## 6. 状态与数据路径

| 数据 | 默认路径 | 备注 |
|---|---|---|
| SQLite 数据库 | `~/.local/share/opencode/opencode.db` | `OPENCODE_DB` 可覆盖；相对路径相对 data 目录；支持 `:memory:` |
| 日志 | `~/.local/share/opencode/log/opencode.log` | 每行含 `run` 与 `role`（`role=server` 看会话/Provider/工具） |
| service 注册 | `~/.local/state/opencode/service.json` | 发现与健康检查用 |
| service 私有配置 | `~/.config/opencode/service.json` | hostname/port/password/cors/env 等；`service get` 可读，注意含密钥 |
| 全局配置 | `~/.config/opencode/opencode.json(c)` | 用户级 |
| 终端客户端配置 | `~/.config/opencode/cli.json` | **只**影响 TUI/mini，server 不读 |
| 项目配置 | `<project>/opencode.json(c)`、`<project>/.opencode/opencode.json(c)` | 合并规则见 03 |
| 快照对象库 | OpenCode data 目录下的独立 Git 对象库 | 不建提交、不动分支/索引 |
| references 缓存 | `~/.local/share/opencode/repos/<host>/<repo>[@branch]` | 24 小时刷新节流 |
| 默认 worktree 根 | data 目录下 `worktree/<项目ID前6位>` | 可用 `worktree.directory` 覆盖 |
| plan 文件目录 | `~/.opencode/plan` | `plan` Agent 唯一允许写入的位置 |

可通过 `opencode debug paths [db|home|data|config|cache|state|tmp|bin|log|repos]` 精确获取。

## 7. 一对关键区分：Client 状态 vs Server 状态

| 状态 | 例子 | 谁拥有 |
|---|---|---|
| 业务状态 | session、message、inbox、tool call、permission request、snapshot、MCP 连接、skill 注册表 | server |
| 界面偏好 | 主题、键位、tab、滚动、prompt 编辑器、图像预览 | 客户端（`cli.json` 或桌面设置） |
| 本地进程 | 端口、PID、service 注册、持久 PTY | server 所在机器 |
| 项目内容 | 文件、Git 状态、diff | 文件系统 + Git；OpenCode 只读/写并做快照 |

推论：

- 控制面**不应该**保存“消息列表”作为权威数据；应保存索引（sessionID → 节点、标题、最后活动时间）和 UI 偏好。
- 重连后先拉 `GET /api/session/{id}/message` 与 `GET /api/session/{id}/context`，再从 `GET /api/event` 接增量事件。
- 事件流是 **live-only**（客户端库明确不重放、不自动重连），必须自己实现断线重连 + 快照补偿。

## 8. 事件模型（概览）

事件通过 SSE `GET /api/event` 推送，支持 `types` 查询参数过滤（可重复/逗号分隔），并始终先发一个 `server.connected` 标记。

三类事件：

1. **生命周期/索引类**：`session.created/renamed/archived/deleted/forked/moved`、`session.agent.selected`、`session.model.selected`、`session.permissions`、`session.usage.*`。
2. **执行流类**：`session.execution.started/succeeded/failed/interrupted`、`session.step.*`、`session.text.*`、`session.reasoning.*`、`session.tool.*`、`session.retry.scheduled`。
3. **外部资源类**：`permission.asked/replied`、`filesystem.changed`、`mcp.status.changed`、`config.updated`、`worktree.updated`、`pty.*`、`form.*`、`tui.*`。

每个事件大致形如：

```json
{
  "id": "evt_...",
  "created": 1760000000000,
  "type": "session.text.delta",
  "location": { "directory": "/workspace" },
  "durable": { "aggregateID": "ses_...", "seq": 42, "version": "..." },
  "data": {
    "sessionID": "ses_...",
    "assistantMessageID": "msg_...",
    "ordinal": 3,
    "delta": "Hello"
  }
}
```

`durable` 只出现在需要持久化语义的事件上（如 step 边界、工具输入结束/结果、compaction、execution）；`session.text.delta`、`session.reasoning.delta`、`session.tool.input.delta`、`session.tool.progress`、`permission.asked` 等增量/瞬时事件没有。完整清单见附录 B。

## 9. 能力边界（控制面必须知道）

**OpenCode 负责**：会话执行、上下文组装、压缩、工具调用、MCP、权限裁决、快照、文件读写、VCS 查询、PTY、Provider 调用与重试。

**OpenCode 不做**：

- 不做多节点编排（没有“集群”概念）；
- 不做组织/RBAC（Console 只做策略下发与计费）；
- 不提供“服务器推送通知”之外的持久消息队列；
- 不运行 LSP（V2 接受 `lsp` 配置但不启动语言服务器、不产生诊断）；
- 不保证快照是事务或备份。

**lework 负责**：节点注册与心跳、WSS 出站隧道、跨节点 session 索引、浏览器侧聚合 API、UI 偏好、把权限/表单请求路由给人。

## 10. 控制面关注点

1. **一个节点可以跑多个 OpenCode server 吗？** 可以，但通常一个节点一个共享 service 即可；控制面用 `nodeID + baseURL` 标识。
2. **server 地址是节点的本地回环**。agentd 与 OpenCode 同机，控制面不应直接连 OpenCode；所有请求经 agentd 的 WSS 隧道转发。
3. **location 必须显式**。控制面创建 session 时要传 `location.directory`（节点上的绝对路径），否则会落到 server 的工作目录。
4. **事件必须按 session 聚合**。SSE 是全局流，控制面应按 `data.sessionID` 路由到订阅了该 session 的浏览器连接。
5. **断线补偿**。SSE 不重放：重连后拉 session 快照 + 最近消息 + 待处理权限/表单列表。
6. **不要把 OpenCode 的 `policies` 与 lework 自己的权限混淆**。控制面可以做“谁能看哪个节点”，但 Agent 行为限制应下发给 OpenCode 的 `permissions`/`policies`。
