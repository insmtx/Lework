# 05 模型与提供商

> 来源：官方 `models`、`providers`、`config#providers`、`warming`、`migrate-v1`。
> 适用：OpenCode 2.x。Provider 与模型 ID **大小写敏感**。

## 1. 选择与默认

```text
/models           # TUI 中选择当前会话模型
```

```bash
opencode models
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"
```

配置文件默认：

```jsonc title="opencode.jsonc"
{
  "model": "anthropic/claude-sonnet-5-5"
}
```

规则：

- 选择只作用于当前会话，不改配置。
- 可用性是 **项目/location 范围**：模型启用、Provider 在当前项目可用、凭据属于该项目。
- 配置模型可用时成为目录默认；否则回退到“最新可用且受支持”的模型。
- 会话已选模型优先于配置默认；切换会话模型不写回配置。
- **根级 `model` 不保留 `#variant`**；变体在 run/session/agent/command 上选。

## 2. 免费模型

`opencode` / `opencode-go` 中输入价格为 0 的模型是免费模型。隐藏它们：

```bash
OPENCODE_DISABLE_FREE_MODELS=1 opencode serve
# 共享后台：
opencode service set env OPENCODE_DISABLE_FREE_MODELS 1
```

隐藏后：从目录与默认值中消失；显式选择会报 `Model unavailable`。未登录时 `opencode` Provider 不存在，直到连接 Console 账号或设置 `OPENCODE_API_KEY`（后者恢复付费模型）。

## 3. 模型引用语法

```text
provider/model
provider/model#variant
openrouter/anthropic/claude-sonnet-5.5#high
```

| 部分 | 规则 |
|---|---|
| Provider | 到第一个 `/` 结束；不能含 `/` 或 `#` |
| Model | 可含额外 `/`；不能含 `#` |
| Variant | `#` 之后 |
| 大小写 | Provider/Model ID 大小写敏感 |

目录/配置中两种形式：

```jsonc
{
  "model": "openai/gpt-6.1-sol#high",
  "agents": {
    "reviewer": { "model": { "providerID": "openai", "model": "gpt-6.1-sol", "variant": "high" } }
  }
}
```

注意：选择器对象用 `model`；Provider 目录条目用 `modelID` 表示“发给 Provider 的真实 ID”。

## 4. 变体（Variants）

变体是同一模型的命名选项（推理强度、token 预算等）。名称来自 models.dev 的当前元数据；未知变体会导致模型解析错误。

```bash
opencode run --model openai/gpt-6.1-sol#high "..."
```

自定义/覆盖：

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol": {
          "settings": { "reasoningEffort": "medium" },
          "variants": [
            { "id": "fast", "settings": { "reasoningEffort": "low" } },
            {
              "id": "deep",
              "settings": { "reasoningEffort": "high", "reasoningSummary": "auto" }
            }
          ]
        }
      }
    }
  }
}
```

- 每个变体可含 `settings`、`headers`、`body`，在 Provider 与模型值之后应用。
- 覆盖推理变体也可用 `capabilities.reasoning`（models.dev v2 形状）：

```jsonc
{
  "capabilities": {
    "reasoning": {
      "supported": true,
      "effort": ["low", "medium", "high"]
    }
  }
}
```

| 字段 | 作用 |
|---|---|
| `supported` | 是否支持推理；`false` 或 `true` 无控制项时不生成变体 |
| `toggle` | 增加 `none` 变体关闭推理 |
| `effort` | 可选强度；`default` 保留 Provider 默认且不生成变体 |
| `budget` | 可选 `min`/`max` thinking tokens；有 `effort` 时忽略 |

`variants` 显式列出的变体叠加在 `capabilities.reasoning` 生成结果之上。

## 5. 请求选项：settings / headers / body

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "baseURL": "https://api.example.com/v1" },
      "headers": { "X-Team": "platform" },
      "models": {
        "gpt-6.1-sol": {
          "settings": { "reasoningEffort": "high" },
          "body": { "store": false }
        }
      }
    }
  }
}
```

| 字段 | 作用 |
|---|---|
| `settings` | Provider 包选项（`baseURL`、`reasoningEffort`、超时、编码等） |
| `headers` | 额外 HTTP 头（名称大小写不敏感） |
| `body` | 合并进请求体的 JSON 字段 |

应用顺序：**Provider → Model → Variant**。

- 嵌套 `settings`/`body` 递归合并；数组与标量后者覆盖前者。
- 选项是 Provider 包特定的，换包可能被忽略或拒绝。
- `settings` 还可能包含：`apiKey`、`baseURL`、`headerTimeout`、`chunkTimeout`、`timeout`、`encoding`、`transport`、`cache`、`compaction`、`resourceName`、`profile`、`region`、`project`、`location`。

## 6. 模型字段

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "coding-default": {
          "modelID": "gpt-6.1-sol",
          "name": "Coding default",
          "family": "gpt",
          "type": "chat",
          "releaseDate": "2026-06",
          "package": "@opencode/ai/providers/openai",
          "settings": {},
          "headers": {},
          "body": {},
          "capabilities": {
            "tools": true,
            "freeform": ["text", "lark"],
            "input": ["text", "image"],
            "output": ["text"],
            "reasoning": { "supported": true, "effort": ["low", "high"] }
          },
          "compatibility": {},
          "variants": [],
          "cost": { "input": 3, "output": 15, "cache": { "read": 0.3, "write": 3.75 } },
          "limit": { "context": 200000, "output": 32000 },
          "disabled": false
        }
      }
    }
  }
}
```

| 字段 | 说明 |
|---|---|
| `modelID` | 发给 Provider 的模型/部署 ID |
| `name` | 展示名 |
| `family` | 分组用 |
| `type` | `chat`（默认）、`image`、`decision`；只有 chat 可用于会话 |
| `releaseDate` | `YYYY-MM-DD` 或 `YYYY-MM` |
| `package` | 模型级运行时覆盖 |
| `capabilities` | 工具、输入/输出媒体、温度、推理控制 |
| `compatibility` | API 怪癖，覆盖 Provider 级 |
| `cost` | 每百万 token 的 input/output/cache 价格 |
| `limit` | `context` / `input` / `output` |
| `disabled` | 从选择中移除 |

### 6.1 未在目录中的模型的回退假设

- 支持 JSON 工具、文本+图像输入、文本输出。
- 除非 `capabilities.freeform` 列出格式，否则不支持 freeform 工具输入。
- 200,000 context、32,000 output；input 限制未指定。
- 可识别的 freeform 格式：`text`、`regex`、`lark`；其他 models.dev 名称被忽略但不丢模型/工具。
- 代理拒绝 freeform 工具时，把 `capabilities.freeform` 设为 `[]`。

## 7. 推理字段兼容性

OpenAI 兼容模型若在自定义 assistant 字段里流式返回推理：

```jsonc
{
  "compatibility": { "reasoningField": "reasoning_content" }
}
```

OpenCode 识别 `reasoning`、`reasoning_content`、`reasoning_text`，也接受其他 Provider 特定字符串；读取流式推理并在回传历史 assistant 消息时恢复该字段。相关：`requireReasoning`。

## 8. Prompt 缓存

OpenCode 在已知需要缓存断点的路由（如 Anthropic）自动放置断点。

Claude 经 OpenAI 兼容代理（如 LiteLLM）时，需要显式声明：

```jsonc
{
  "providers": {
    "litellm": {
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "https://litellm.example.com/v1" },
      "models": {
        "claude-sonnet-5-5": { "compatibility": { "cacheFormat": "anthropic" } }
      }
    }
  }
}
```

OpenCode 会在最后一个工具定义、系统提示、最新消息上标记 `cache_control: {"type":"ephemeral"}`（默认 5 分钟）。Alibaba Model Studio 用 `"alibaba"`（忽略工具定义上的标记）。

### 8.1 缓存生命周期

```jsonc
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "1h" } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "ttl": "5m" } } }
      }
    }
  }
}
```

- `ttl` 单位：`ms`、`s`、`m`、`h`、`d`；原样发送，必须是 Provider 接受的值。
- Anthropic Messages 写入 `cache_control.ttl`（接受 `5m`/`1h`）；Bedrock Converse 写入每个 `cachePoint.ttl`；OpenAI Chat/Responses 把 `24h` 写入 `prompt_cache_retention`，其他值写入 `prompt_cache_options.ttl`。
- 自动缓存（如 Gemini）忽略该设置。
- 更长缓存的写入通常更贵（Anthropic 1h 写入 2× 输入价，5m 为 1.25×）。
- `warming.interval: "auto"` 用该值计时（见 11）。

## 9. 兼容性（compatibility）

`compatibility` 描述“模型经哪个 API 提供服务”的请求/响应怪癖。每个模型只经一个 API，字段只在该 API 读取时生效。

| 字段 | 作用 | 读取方 | 值/默认 |
|---|---|---|---|
| `reasoningField` | assistant 消息中承载推理的字段 | OpenAI Chat | 任意字段名（除 role/content/refusal/tool_calls）；未设置用流中看到的字段，否则 `reasoning_content` |
| `requireReasoning` | 每条历史 assistant 消息都发送推理字段（无推理时为空串） | OpenAI Chat | 默认：设置 `reasoningField` 或 DeepSeek 时为 true，否则 false |
| `maxTokensField` | 输出 token 限制的 body 字段 | OpenAI Chat | `max_completion_tokens` / `max_tokens`；未设置时对 DeepSeek、Moonshot、Together AI、Z.AI、Cerebras 检测为 `max_tokens` |
| `requireFinishReason` | 流缺少 `finish_reason` 视为不完整 | OpenAI Chat | 默认 true |
| `requireAssistantAfterTool` | 在工具结果与下一条 user 之间插入 assistant | OpenAI Chat | Mistral 家族默认 true，否则 false |
| `supportsPromptCacheKey` | 是否接受 `prompt_cache_key` | OpenAI Chat/Responses、Mistral | boolean |
| `streamUsage` | 用 `stream_options.include_usage` 请求流式 usage | OpenAI Chat | 默认 true |
| `cacheFormat` | 缓存标记语法 | 所有支持缓存标记的 API | `anthropic` / `alibaba` |
| `supportsThinkingBlockBinding` | 丢弃因上下文变化而失效的 thinking block，而非拒绝请求 | Anthropic Messages、Bedrock Converse | 未设置时检测 Claude 5.1+ |
| `supportsEffortUpdates` | 把推理强度变更作为 per-message 更新发送（保留缓存） | Anthropic Messages、OpenAI Responses | 未设置时检测 Claude Opus 5、Claude 5.1+、GPT-6+ |
| `mediaInput` | 决策请求中图像/媒体位置 | System One | `assets` / `state` / `root` |

Provider 级 `compatibility` 应用于其所有模型；模型级逐字段覆盖。`supportsThinkingBlockBinding` 与 `supportsEffortUpdates` **仅模型级**可用。

## 10. Provider 定义

```jsonc
{
  "providers": {
    "acme": {
      "name": "Acme",
      "env": ["ACME_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "canonical": "openai",
      "compatibility": {},
      "settings": { "baseURL": "https://llm.acme.example/v1" },
      "headers": {},
      "body": {},
      "models": { "qwen3-coder": { "name": "Qwen 3 Coder" } }
    }
  }
}
```

| 字段 | 作用 |
|---|---|
| `name` | 展示名 |
| `env` | 有序的环境变量名，用于提供凭据 |
| `package` | 运行时 Provider 包 |
| `canonical` | 继承其目录默认值的内置 Provider ID |
| `compatibility` | 该 Provider 所有模型共享的 API 怪癖 |
| `settings` | 类型化控制 + 传给运行时包的 JSON 选项 |
| `headers` / `body` | 请求头 / 请求体合并 |
| `models` | 新增或覆盖模型（key 为 OpenCode 模型 ID） |

### 10.1 包（package）

原生包（部分）：

```text
@opencode/ai/providers/openai
@opencode/ai/providers/openai/chat
@opencode/ai/providers/openai/responses
@opencode/ai/providers/openai-compatible
@opencode/ai/providers/openai-compatible/responses
@opencode/ai/providers/anthropic
@opencode/ai/providers/anthropic-compatible
@opencode/ai/providers/google
@opencode/ai/providers/google-vertex
@opencode/ai/providers/google-vertex/gemini
@opencode/ai/providers/google-vertex/chat
@opencode/ai/providers/google-vertex/responses
@opencode/ai/providers/google-vertex/messages
@opencode/ai/providers/azure
@opencode/ai/providers/azure/chat
@opencode/ai/providers/azure/responses
@opencode/ai/providers/amazon-bedrock
@opencode/ai/providers/amazon-bedrock/mantle
@opencode/ai/providers/openrouter
@opencode/ai/providers/xai
```

也支持 npm 包（如 `@acme/opencode-provider`）与本地 `file://` 包。V1 的 AI SDK 包在迁移时加 `aisdk:` 前缀。

### 10.2 超时

| 设置 | 默认 | 作用 |
|---|---|---|
| `settings.headerTimeout` | 5 分钟 | 等待响应头 |
| `settings.chunkTimeout` | 15 分钟 | 流式响应 chunk 间隔 |
| `settings.timeout` | 无 | 整个请求（发送→完成） |
| `chunkTimeout`（WebSocket） | 30 分钟 | 帧间隔 |

值为毫秒，或 `false` 禁用。超时按 transport error 处理，OpenCode 最多重试 3 次。

### 10.3 请求编码

```jsonc
{ "providers": { "openai": { "settings": { "encoding": "none" } } } }
```

`zstd` / `gzip` / `none`，可设在 Provider/模型/变体（最具体优先）。只对能解码的端点启用；OpenAI 在 ChatGPT 登录且未自定义 `baseURL` 时默认 `zstd`，API key 发送明文。WebSocket 不受影响。

## 11. 常见 Provider

### 11.1 OpenAI / ChatGPT

- `/connect` 选择 OpenAI；可用 API key、ChatGPT 登录或旧 Codex 登录。
- ChatGPT 登录的上下文默认被限制：GPT-6.1 Sol 及更新 500,000；旧模型 272,000。禁用插件可取消：`"plugins": ["-opencode.provider.openai-context-caps"]`。

### 11.2 Azure

```jsonc
{
  "providers": {
    "azure": {
      "settings": { "resourceName": "my-models" }
    }
  }
}
```

- 资源名也可用 `AZURE_RESOURCE_NAME`（兼容 `AZURE_COGNITIVE_SERVICES_RESOURCE_NAME`）。
- 支持 API key 或 Entra ID（Azure CLI 登录）；资源名可用配置/环境/连接保存，连接保存优先。
- Azure 只通过 deployment 提供模型：OpenCode 列出 deployment 作为模型 ID（小写），继承目录模型的 limit/cost/capabilities。
- 显式映射：`"models": { "gpt-6-luna": { "modelID": "gpt-production" } }`。
- 所需角色：Azure OpenAI 用 **Cognitive Services OpenAI User**；其他 Foundry 模型用 **Cognitive Services User**。
- 旧的 `azure-cognitive-services` ID 在 V2 改为 `azure`。

### 11.3 Amazon Bedrock

```jsonc
{
  "providers": {
    "amazon-bedrock": {
      "settings": {
        "profile": "work",
        "region": "us-west-2",
        "baseURL": "https://bedrock-runtime.vpce.example.com"
      }
    }
  }
}
```

- 使用 AWS 默认凭据链（SSO profile、access key、web identity、容器凭据）。
- 区域：`settings.region` → `AWS_REGION` → `AWS_DEFAULT_REGION` → `us-east-1`。
- 只有区域不会激活 Provider，必须有 profile 或其他凭据链输入。
- Bedrock API key 用 `AWS_BEARER_TOKEN_BEDROCK`；其他 AWS 变量用于 SigV4，不作为 OpenCode API-key 账户存储。

### 11.4 Google Vertex

```bash
gcloud auth application-default login
```

```jsonc
{
  "providers": {
    "google-vertex": {
      "settings": { "project": "my-project", "location": "us-central1" }
    }
  }
}
```

- 使用 ADC；必须能解析 project。
- Project 解析顺序：`GOOGLE_VERTEX_PROJECT` → `GOOGLE_CLOUD_PROJECT` → `GCP_PROJECT` → `GCLOUD_PROJECT`。
- Location：`GOOGLE_VERTEX_LOCATION` → `GOOGLE_CLOUD_LOCATION` → `VERTEX_LOCATION`，默认 `us-central1`。
- 服务账号：`GOOGLE_APPLICATION_CREDENTIALS` 指向 JSON，同时仍需 project。
- 统一使用 `google-vertex`；V2 不再有 `google-vertex-anthropic`。

### 11.5 GitHub Copilot

`/connect` → GitHub Copilot → 选择 GitHub.com 或 Enterprise → 设备授权流程 → `/models`。

- 账号必须有 Copilot Chat 权限；否则先订阅 Copilot Free 或让组织分配席位。
- 登录后以及切换账号时拉取账号的模型列表。
- Enterprise 输入部署 URL/域名；OpenCode 优先用 GitHub 返回的 Copilot API 端点，否则从域名推导。

### 11.6 OpenCode Go / Console

`/connect` 选择 OpenCode Go，粘贴 Console 生成的 API key。详见 18。

### 11.7 OpenRouter 与网关

- OpenRouter 用原生运行时与目录，模型 ID 保留完整路径：`openrouter/anthropic/claude-sonnet-5.5`。
- 覆盖端点时保留原生包，以维持请求/推理行为。
- 自建 OpenAI 兼容网关建议定义自定义 Provider，配置 key 即 Provider 前缀、`models` key 即可选模型 ID。

## 12. 本地模型

### 12.1 Ollama

- 默认探测 `http://127.0.0.1:11434`；模型 ID 形如 `ollama/gemma3:4b`。
- 后台刷新清单；读取上下文、视觉、工具能力；排除 embedding-only 模型。
- 远程/代理：设置 `settings.baseURL`（含 `/v1`），OpenCode 从它推导 `/api/tags` 与 `/api/show`；`apiKey` 可选（作为 bearer 发送）。
- 禁用发现：`"plugins": ["-opencode.provider.ollama"]`。

### 12.2 LM Studio

- 默认 `http://127.0.0.1:1234`；ID 形如 `lmstudio/google/gemma-4-26b-a4b`。
- 从 `/api/v1/models` 发现；排除 embedding 模型。
- 禁用发现：`"plugins": ["-opencode.provider.lmstudio"]`。

### 12.3 vLLM

- 默认 `http://127.0.0.1:8000`；先查 `/health`，再刷新 `/v1/models`。
- 用 `max_model_len` 作上下文限制；只纳入 owner 为 `vllm` 的模型卡。
- 发现的模型只声明文本输入/输出，**不支持视觉/工具**；工具调用需服务端 `--enable-auto-tool-choice` 等参数，发现不会报告。
- 禁用发现：`"plugins": ["-opencode.provider.vllm"]`。

### 12.4 其他 OpenAI 兼容服务

```jsonc
{
  "model": "local/coder",
  "providers": {
    "local": {
      "name": "Local server",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": { "baseURL": "http://127.0.0.1:1234/v1" },
      "models": {
        "coder": {
          "modelID": "model-name-on-server",
          "capabilities": { "tools": true, "input": ["text"], "output": ["text"] },
          "limit": { "context": 32768, "output": 8192 }
        }
      }
    }
  }
}
```

必须使用服务器真实模型名、限制、输入输出类型与工具支持；OpenCode 无法检测这些回退值是否准确。

## 13. WebSocket 传输

OpenAI、xAI 与部分 Azure Responses 模型可为每个会话保持一条 WebSocket，连续步骤复用未变前缀，只发送新增内容。

```jsonc
{
  "providers": {
    "openai": { "settings": { "transport": "http" } }
  }
}
```

规则：

- 内置 Provider 按自身策略为受支持路由开启。
- `"websocket"` 启用，`"http"` 关闭；路由不支持时记录警告并回退 HTTP。
- OpenAI 的 Provider 原生压缩复用同一连接。
- xAI 只从已存响应继续；其默认 `store:false` 时每步完整发送。
- 连接关闭后下一步重连；打不开则回退 HTTP。
- 带 `http.request`/`http.response` 钩子的 Provider 插件会被保持在 HTTP，以保证可观察。

## 14. 错误速查

| 错误/现象 | 检查 |
|---|---|
| `No model is available for session ...` | 没有启用的可选模型；完成 Provider 设置后在 `/models` 选 |
| `Model unavailable: provider/model` | Provider 未激活、模型 ID 不存在/被禁用、动态发现不再返回；自定义别名检查 `models` 的 key 而非 `modelID` |
| `Cannot initialize provider/model: NAME is required ...` | `baseURL` 里仍有 `${NAME}` 占位符 |
| `Azure resource name is missing` | 设置 `settings.resourceName`、`AZURE_RESOURCE_NAME` 或完整 `baseURL` |
| Vertex 不出现 | 没有可解析的 project（只有 ADC 不够） |
| Bedrock 不出现 | 缺少 profile 或其他凭据链输入；只有区域不够 |
| Ollama 无模型 | `/api/tags`、`/api/show` 不可达，或 `/api/show` 未报告 `completion` |
| Copilot 无模型 | 账号无 Copilot Chat 权限；看 `failed to sync GitHub Copilot models` |
| 旧 Provider ID | `azure-cognitive-services` → `azure`；`google-vertex-anthropic` → `google-vertex` |

## 15. 控制面关注点

1. **Provider/模型列表按 location 解析**：`GET /api/provider`、`GET /api/model` 返回 `{ location, data }`。控制面缓存要带 location 维度。
2. **凭据管理不要复制**：`/api/credential` 只返回元数据；密钥由 OpenCode 存在自己的目录。控制面不要保存 Provider key。
3. **展示“为什么不可用”**：模型不可用可能是 `policies`、`disabled`、凭据、location 四类原因；分别查 `/api/model`、`/api/provider`、`/api/config`、`/api/integration`。
4. **变体是字符串后缀**：前端选择器要把 `#variant` 作为模型引用的一部分传给 session/agent/command。
5. **成本数据来自 `Model.Info.cost` 与 `Session.Info.cost/tokens`**；不要按 token 自行估算。
6. **WebSocket 传输不可观察 HTTP 钩子**：如果控制面依赖 `http.request` 事件做审计，需把 `transport` 固定为 `http`。
7. **`settings.timeout` 无默认值**：长任务建议在节点基线配置里显式设置，避免请求无限挂起。
