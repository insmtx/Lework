# 19 控制面能力对齐清单

> 基准：OpenCode V2 官方 `openapi.json`（139 条 path）+ 本仓库当前代码（2026-11，分支 `docs/opencode-v2-docs`）。
> 用途：回答“控制面到底接管了 OpenCode 的哪些能力、哪些只做了一半、哪些不做”。
> 关联文档：[15-控制面Agent层集成指南.md](15-控制面Agent层集成指南.md)（方案与协议）、[12-HTTP-API参考.md](12-HTTP-API参考.md)（OpenCode 端点）、[附录B-事件与权限动作速查.md](附录B-事件与权限动作速查.md)（事件与 action）。

## 1. 统计口径

### 1.1 链路三层

控制面能力必须三层齐全才算“已接管”，缺一层就是“部分”：

```text
浏览器 UI  →  控制面浏览器 API  →  节点 RPC（agentd/handler）  →  OpenCode HTTP/SSE
frontend/     controlplane/api      agentd 方法名                  opencode/client
```

**只有节点 RPC 而没有浏览器 API 不算接管。** 本清单会把这种情况明确标成“节点侧已具备、控制面未暴露”。

### 1.2 状态定义

| 标记 | 含义 |
|---|---|
| ✅ 已接管 | 三层打通，前端有可用入口，字段语义对齐 OpenCode |
| 🟡 部分接管 | 链路通但有明确缺口：字段被丢弃、无分页、无快照、无前端入口、或只支持部分取值 |
| ⬜ 未接管 | OpenCode 有契约，lework 任一层缺失 |
| ⛔ 明确不接管 | 按控制面边界不应由 lework 承担（OpenCode 自身、TUI/Desktop/Console 或后续阶段） |

### 1.3 一句话结论

当前控制面接管的是**一条窄而完整的执行链**：节点 → Session 列表/创建 → 文本 prompt → 消息快照 → 工具卡片 → 权限回复 → turn diff → 文件浏览 → 会话 PTY → SSE 事件透传。

未接管的是**产品化外围**：Agent/模型/Provider 选择、会话生命周期管理（重命名/归档/fork/revert）、表单问答、命令/技能/MCP、VCS/worktree、用量成本、配置与策略下发、OpenCode 启停运维入口。

## 3. 逐域明细

### 3.1 节点与隧道（lework 自有，不对应 OpenCode 端点）

| 能力 | lework 链路 | 状态 | 说明 |
|---|---|---|---|
| 节点注册 / 心跳 / 在线状态 | `agentd/transport` → `agentgw.Gateway` → `node.Registry` + SQLite | ✅ | 出站 WSS，无入站端口；35s 心跳窗口 |
| 节点列表 / 详情 | `GET /api/nodes`、`GET /api/nodes/{id}` | ✅ | 身份取自 SQLite，`connected` 取自实时注册表 |
| 节点健康（OpenCode 状态） | `GET /api/nodes/{id}/health` → RPC `opencode.status` | 🟡 | 后端已通，前端 `lib/api.ts` 未接 |
| 能力声明 `capabilities` | hello 帧上报 → 节点视图 / 前端类型 | 🟡 | 浏览器 API 会返回，但前端类型声明后未渲染，也未用于功能开关 |
| 浏览器侧鉴权 | 无登录态，仅回环绑定 | 🟡 | 安全边界是“只绑定 127.0.0.1”，多用户/远程访问未设计 |
| 多节点调度 / 故障转移 | 前端手动选节点 | ⬜ | 无自动选点、无跨节点任务上下文 |

### 3.2 OpenCode 进程生命周期

| 能力 | OpenCode 契约 | lework 链路 | 状态 | 缺口 |
|---|---|---|---|---|
| 健康检查 | `GET /api/info` | `opencode.Client.Health` → supervisor 就绪探测 | 🟡 | 仅作为启动探针，未单独暴露 |

| 重启 | — | RPC `opencode.restart` | ⬜ | 无浏览器 API、无 UI |
| 停止 | — | RPC `opencode.stop` | ⬜ | 无浏览器 API、无 UI |

### 3.6 权限与策略

| 能力 | OpenCode 契约 | lework 链路 | 状态 | 缺口 |
|---|---|---|---|---|
| 待审批事件 | `permission.asked` | runner → Hub → 前端 `PermissionCard` | ✅ | 从事件 payload 直接还原卡片 |
| 已决事件 | `permission.replied`（`data.requestID` + `data.reply`） | 前端按 `data.id` 移除卡片 | 🟡 | **字段名不匹配**：`replied` 没有 `id`，只有 `requestID`；本端回复后靠本地删除掩盖了问题，跨客户端/多标签回复时卡片会残留。`permission.resolved` 不是 V2 事件，属死分支 |
| 回复 `once` / `reject` | `POST /api/session/{id}/permission/{requestID}/reply` | RPC `permission.reply` | ✅ | — |
| 回复 `always` | 同上，`decision=always` | 后端**原样透传**，未做枚举校验 | 🟡 | 前端类型与 UI 只给 `once` / `reject`；用 curl 可调通 |

| 已保存规则 CRUD | `GET/PATCH/DELETE /api/permission/saved` | — | ⬜ | 无法查看/撤销 `always` 留下的规则 |
| 会话级权限列表 | `GET /api/session/{id}/permission` | — | ⬜ | — |
| `policies` 下发 | 配置 / 托管 | — | ⬜ | 控制面没有任何强制约束通道 |

> 权限是当前唯一的“交互式中断点”，也是最容易因断流产生状态漂移的地方。P0 建议：新增 `GET /api/sessions/{node}/{session}/permissions`，在选中会话和 `resync` 时拉一次快照。

### 3.14 明确不接管

| 范围 | 原因 |
|---|---|
| TUI / Desktop / Web 客户端界面、键位、主题 | 属于 OpenCode 客户端，控制面只提供浏览器视图 |
| Console、组织/成员/计费/SCIM/SSO | 企业 SaaS 能力，与“个人单用户多节点”定位冲突 |
| 插件 GUI、`/api/plugin/gui` | 插件运行时归 OpenCode |
| `POST /api/rpc/{rpcID}/{method}` | 插件私有 RPC，控制面不代理解析 |
| `POST /api/debug/heap-dump`、`/api/debug/location` | 调试端点，不对外暴露 |
| `POST /api/experimental/generate/*`、voice | 生成/语音为独立产品面，暂不进入控制面 |
| 会话状态持久化副本 | 违反“不建第二状态机”的硬边界 |
| 模型推理代理、API key 分发 | key 只属于 OpenCode 进程，控制面不得持有或落盘 |
| ACP / `opencode acp` | 遗留执行内核才用 ACP；控制面走 HTTP/SSE |

## 4. 缺口优先级

### P0 — 影响“能不能正常用”

1. **权限 `always`**：`permission-card.tsx` 增加第三按钮，`lib/types.ts` 与 `page.tsx` 放宽联合类型（后端已支持）。
2. **`permission.replied` 字段修正**：前端改为读 `data.requestID`，并删除不存在的 `permission.resolved` 分支；否则跨客户端回复后卡片不消失。
3. **权限快照对账**：新增浏览器 API + RPC，选中会话与 `resync` 时拉 `GET /api/permission/request`。
4. **会话重命名 / 删除**：`PATCH` / `DELETE /api/session/{id}`，否则列表会无限增长且不可读。
5. **OpenCode 启停入口**：状态已有 `GET /api/nodes/{id}/health`，只需前端接入；再补 `POST /api/nodes/{id}/opencode/{start|restart|stop}` 复用三个已有 RPC。
6. **消息分页**：`limit` 可配 + `before` 游标，避免 200 条截断静默丢历史。

### P1 — 影响“好不好用”

6. Agent / 模型 / variant 选择（会话级 + prompt 级）。

## 5. 契约对齐风险

| 风险 | 现状 | 后果 | 建议 |
|---|---|---|---|
| 事件无重放，`Seq` 恒 0 | runner 硬编码 `Seq: 0`，断流发 `agent.resync_required` | 断线期间的状态变化永久丢失 | 所有页面级状态都必须有“快照接口”兜底，不能依赖事件补全 |
| 权限事件无 durable | 只靠 `permission.asked` 事件 | 断线后权限卡消失，OpenCode 侧仍在等 | P0 权限快照 |
| `session.list` 忽略 `directory` | handler 解码后未使用 | 多 location 下会话混在一起 | 要么按 location 过滤，要么在 UI 标明目录 |
| 消息固定 200 条 | `messagesLimit = 200` | 长会话截断且无提示 | 分页 + 显式 `truncated` 标记 |
| 前端按事件全量重取 | `page.tsx` 250ms 防抖 | 长回答抖动、事件风暴放大请求 | 增量渲染或按 turn 合并 |
| `always` 只能靠 curl | 后端不校验 decision 枚举 | UI 与 API 能力不一致 | 统一枚举并补 UI |
| `workspace_roots` 边界 | session/file/diff/PTY 全部走 `confineDirectory` / `confinePath`，但**未配置 roots 时是直通** | 默认部署下任何绝对路径都可操作 | 部署时应强制配置；不要为“方便”留空 |
| 单帧 1 MiB、文件 512 KiB | gateway `maxFrameBytes`、`maxFileReadBytes` | 大文件/大事件被截断或拒绝 | 需要时走分片或路径读取，不要抬上限 |
| 控制面无登录态 | 仅回环绑定 | 本机任意进程可操作 | 远程访问前必须先加认证（属产品决策） |

## 6. 如何复核本清单

清单会随代码漂移，复核时按下面顺序对一遍即可：

```bash
# 1. 浏览器 API 全集
sed -n '/func (a \*API) Register/,/^}/p' backend/internal/controlplane/api/api.go

# 2. 节点 RPC 全集（真正的能力边界）
sed -n '/func (h \*Handler) Handle/,/^}/p' backend/internal/agentd/handler/handler.go

# 3. agent 上报的能力声明
sed -n '/Capabilities: \[\]string{/,/},/p' backend/internal/agentd/runner/runner.go

# 4. 实际调用的 OpenCode 端点
grep -rn '"/api/' backend/internal/agentd/opencode/

# 5. 前端已接的浏览器 API
grep -n 'request<' frontend/apps/control-plane/lib/api.ts

# 6. OpenCode 侧的完整契约
python3 -c "import json;d=json.load(open('openapi.json'));print('\n'.join(sorted(d['paths'])))"
```

判定规则：

- 只有第 4 步命中、第 2 步没有 → **未接管**。
- 第 2 步有、第 1 步没有 → **部分（节点侧已具备，控制面未暴露）**。
- 第 1 步有、第 5 步没有 → **部分（后端已具备，前端无入口）**。
- 三步都有但字段/取值被裁剪 → **部分**，并在“缺口”列写清裁剪点。
