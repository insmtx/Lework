# 11 上下文管理

> 来源：官方 `compaction`、`snapshots`、`references`、`attachments`、`warming`、`formatters`、`config`（`tool_output`、`media`、`experimental.location_idle_timeout`）。
> 本文覆盖“让长会话持续运行”和“让文件/外部资料进入上下文”的机制。

OpenCode 的上下文不是一个静态 prompt，而是由系统提示、指令、工具 schema、MCP 指导、历史消息、附件、引用、快照共同组成。控制面能做的是**观察与提示**，而不是自己重写上下文。

## 1. 压缩（Compaction）

### 1.1 原理

接近模型上下文上限时，OpenCode 总结整个当前对话，并保留最近一段原文：

```text
before   [ system prompt ][ older conversation ............ ][ recent 15k ][ pending work ]
request  [ system prompt ][ older conversation ............ ][ recent 15k ][ summary instructions ]
after    [ system prompt ][ summary of older + recent ][ recent 15k ][ pending work ]
```

- 发送完整对话让摘要请求复用 prompt cache（provider 支持时）。
- 后续压缩在上一次 checkpoint 之后更新摘要。
- 压缩是**有损**的：需要精确细节时调大 `keep.tokens`，或提前手动压缩。

### 1.2 配置

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
    "buffer": "15%"
  }
}
```

| 字段 | 默认 | 行为 |
|---|---|---|
| `auto` | `true` | 接近上限自动压缩；provider 报“太长”时恢复一次；手动压缩始终可用 |
| `keep.tokens` | `15000` | 摘要旁保留的最近对话估算 token；越大保留越多，留给新工作的越少 |
| `buffer` | `"15%"`，至少 16k | 为模型窗口保留的空闲比例；达到其余部分时开始自动压缩 |

`buffer`：

- 是“保留空闲”，不是“开始压缩的点”：`"20%"` 在 80% 满时压缩。
- 接受 `"1%"`–`"99%"`，可带小数（`"12.5%"`）。
- 也接受 token 数（如 `20000`）：对小窗口是大比例，对大窗口是小比例。
- token 数 ≥ 模型窗口时被忽略，使用默认值。

### 1.3 手动压缩

```sh
opencode api post /api/session/ses_example/compact --data '{}'
```

- 响应只表示“请求已接受”，不等待摘要完成。
- 跟随 `session.compaction.*` 事件了解完成时机。
- 在下一次安全点、等待中的 prompt 之前运行。
- 多个 pending 请求会合并。
- `compaction.auto: false` 时手动仍可用。
- 传 `id` 可让精确重试幂等；同一 ID 用于不同请求会冲突。

### 1.4 压缩模型

默认使用会话模型；可指定：

```jsonc
{
  "agents": {
    "compaction": { "model": "anthropic/claude-sonnet-5-5" }
  }
}
```

无法解析时回退到会话模型。

### 1.5 后台压缩（实验）

```jsonc
{ "experimental": { "background_compaction": true } }
```

- 提前写摘要，到阈值时换入；会话不暂停。
- 未使用的摘要仍消耗 token。
- 到点时摘要未完成会等待。
- 摘要后对话增长超过阈值约 40%，或模型/指令/对话开头变化，会回退到普通压缩。
- 原生压缩、刚切模型、provider 报太长时不使用。
- 摘要保存在内存，重启丢失。

### 1.6 Provider 原生压缩

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } }
      }
    }
  }
}
```

- 模型设置覆盖 provider 设置；`native` 用 provider 压缩，`summary` 用 OpenCode 摘要。
- 原生压缩返回不透明、加密的 checkpoint，替代旧对话；最近消息与附件（到 `keep.tokens`）保留。
- 支持 OpenAI Responses 模型，具体取决于部署与模型。
- checkpoint 只能在同一 provider/模型使用；切模型会从原始对话继续。
- provider 报压缩太长时会用更小请求重试，**不**切换到摘要。

### 1.7 摘要结构

摘要按“另一个 Agent 能接手”的结构生成：

```markdown
## Objective
Finish the authentication migration.

## Next Move
- Update the callback handler.
- Verify the login flow.
```

覆盖目标与要求、决策、已完成/进行中工作、阻塞与下一步、相关文件。保留的最近对话中，长工具输出会缩短，附件数据替换为简短描述。

压缩后，当前版本的指令文件成为会话基线。

### 1.8 限制

| 限制 | 结果 |
|---|---|
| 模型 | 摘要遵循 `agents.compaction.model`；原生压缩总用会话模型 |
| 历史 | 需要可替换的旧对话；固定指令/工具 schema 占满时无法腾出空间 |
| 大小 | 待压缩对话本身太长时，发送缩短文本版，可能省略最旧交换 |
| 恢复 | 报“太长”压缩并重试一次；第二次报错 |
| 存储 | 早期消息仍存储，只是不再发送给模型 |

## 2. 快照与撤销（Snapshots）

### 2.1 工作流

```text
/undo      # 暂存回滚，恢复文件，把被移除的 prompt 放回 composer
/redo      # 取消暂存，恢复 /undo 前的对话与文件
```

- 编辑恢复出的 prompt 再提交 → 提交暂存回滚。
- 也可以选一条早期消息并选择 **Revert**。
- TUI 默认快捷键：`<leader>u`（undo）、`<leader>r`（redo）。

HTTP 对应接口见 06 号文档：`POST .../revert/stage`、`POST .../revert/commit`、`DELETE .../revert`。

### 2.2 捕获

每个模型 step：

```text
before model step ── snapshot A
model edits src/api.ts
step finishes ────── snapshot B ── changed: src/api.ts
```

- 捕获是 best-effort；任一快照不可用，对话继续，但该 step 可能没有可恢复的文件变更。
- assistant message 的 `snapshot` 记录 `start`/`end` 与变更文件。

### 2.3 范围

| 内容 | 是否捕获 | 示例 |
|---|---|---|
| 活动目录内已跟踪文件 | 是 | `packages/app/src/app.tsx` |
| 未忽略的未跟踪文件，单文件 ≤ 2 MiB | 是 | `packages/app/notes.txt` |
| Git ignored 文件 | 否 | `dist/app.js` |
| 单文件 > 2 MiB 的未跟踪文件 | 否 | `debug.log` |
| 活动目录之外的文件 | 否 | `packages/server/src/index.ts` |
| Git 元数据/其他副作用 | 否 | commit、分支、数据库、进程 |

- 需要 Git 仓库；不在仓库内时 `/undo` 只能回滚对话，不能恢复文件。
- 只覆盖会话活动目录，不覆盖整个仓库。

### 2.4 恢复

- 只恢复“被选中边界之后的 assistant step”归因的路径。
- 每个路径回到第一个被回滚 step 之前的状态；这些 step 创建的文件若之前不存在则删除。
- 不属于这些 step 的路径不动。
- 当前对受影响路径的编辑可能被覆盖；继续前先看恢复摘要与 `git diff`。

### 2.5 存储与安全

- 快照存在数据目录下独立的内部 Git 对象库，不创建 commit、不移动分支、不有意改索引。
- 快照对象可能包含完整文件内容；把数据目录视为敏感本地数据。
- 默认启用；`snapshots: false` 停止未来捕获，但**不删除**已存快照。
- 快照不是事务/备份：shell 可改变服务、进程、网络、数据库、Git 状态、ignored 输出或活动目录外的文件；恢复不会反转这些。
- 中断/失败可能留下变更；回滚会覆盖当前内容；提交回滚只从活动视图移除消息，**不是安全擦除**。

## 3. 引用（References）

### 3.1 配置

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Use for product behavior and terminology"
    }
  }
}
```

- 本地路径相对配置文件所在目录解析；支持绝对路径与 `~/`。
- 字符串简写只在该值以 `.`、`/`、`~` 开头时视为本地路径；裸 `docs` 会被当作 Git 仓库。

### 3.2 Git 引用

```jsonc
{
  "references": {
    "effect": { "repository": "Effect-TS/effect", "branch": "main" },
    "internal-sdk": { "repository": "git@gitlab.example.com:platform/sdk.git", "branch": "release/v2" }
  }
}
```

支持：GitHub `owner/repo`、Git URL、host/path、SCP 风格；**不支持本地 `file:` 仓库**。省略 `branch` 时跟随远程默认分支。

### 3.3 存储

按 remote + branch 每个 checkout 一份，位于全局数据目录：

```text
~/.local/share/opencode/repos/github.com/Effect-TS/effect
~/.local/share/opencode/repos/github.com/Effect-TS/effect@main
```

### 3.4 刷新

- 缺失仓库异步克隆。
- 已存在 checkout 在引用加载/重载后、以及在其 Location 接纳新用户 prompt 后，后台检查。
- 上次尝试 ≥ 24 小时或从未尝试才 eligible。
- 刷新会 fetch 并 reset 到配置分支/远程默认分支。
- 时间戳跨重启持久；共享同一 checkout 的 Location 共享时间戳；失败仍遵守 24 小时限制；未使用的 Location 不轮询。
- 克隆/刷新失败不影响其他引用。
- prompt **不等待**克隆/刷新；附件可能是旧内容，而后续工具读取看到新内容。
- 缓存 checkout 共享且可能在 Agent 使用时更新；**不要编辑缓存 checkout**，刷新会 reset。

### 3.5 可见性

- `description` 让引用出现在 Agent 指令中（alias + 解析后的路径）。
- 无 `description` 的引用仍对客户端可用，但不自动广告。
- `hidden: true` 只从交互式客户端选择器隐藏；仍在 reference API 与（有 description 时）指令中。

### 3.6 使用与权限

- 客户端按根 alias 附加；附件包含根目录的**非递归**直接子项列表。
- 引用**不授予**额外工具权限；外部访问仍受 `external_directory` 与 `read`/`edit` 规则约束。

### 3.7 字段

| 字段 | Local | Git | 说明 |
|---|---|---|---|
| `path` | 必填 | 否 | 本地目录 |
| `repository` | 否 | 必填 | 远程 Git |
| `branch` | 否 | 可选 | fetch/checkout 的分支 |
| `description` | 可选 | 可选 | 何时使用 |
| `hidden` | 可选 | 可选 | 交互式选择器隐藏 |

alias 不能为空，不能含 `/`、`\`、空白、反引号、逗号。

## 4. 附件（Attachments）

### 4.1 提交格式

V2 prompt/command 输入用 `uri` + 可选 `name`/`description`：

```json
{
  "uri": "file:///home/me/project/src/server.ts",
  "name": "server.ts",
  "description": "HTTP server entrypoint"
}
```

- 文本文件可用 `?start=20&end=60` 选 1-based 行。
- `data:` URL 内联内容。
- **不支持** HTTP(S) 附件 URL。

### 4.2 支持格式

| 输入 | 模型收到 | 示例 |
|---|---|---|
| UTF-8 文本 | 文件名 + 解码文本 | `README.md` |
| 目录 | 直接子项的非递归列表 | `file:///home/me/` |
| PNG/JPEG/GIF/WebP | 图片媒体 | `diagram.png` |
| PDF | 文档媒体 | `report.pdf` |

- PDF 需要模型支持 PDF 输入；模型不支持时 OpenCode 发送简短说明。
- SVG 按文本处理。
- AVIF、BMP、音频、视频、其他二进制不会进入请求；先转文本或支持图片。
- 提交前读取附件；拒绝非法 URL、不可读路径、非文件/目录、解码后 > 20 MiB。
- 媒体类型按字节检测；改文件名/`data:` 的 mime 不能让不支持的二进制可见。

### 4.3 图片处理

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880
    }
  }
}
```

| 字段 | 默认 | 行为 |
|---|---|---|
| `auto_resize` | `true` | 超限缩放；`false` 时拒绝 |
| `max_width` | 2000 | 最大宽度（像素，正整数） |
| `max_height` | 2000 | 最大高度 |
| `max_base64_bytes` | 5242880 | Base64 编码后的最大字节 |

- 同时应用于 prompt 附件与 `read` 工具返回的图片。
- `auto_resize: true`：保持比例缩放到限制内，再逐步尝试更小的 PNG/JPEG 编码直到满足 Base64 限制，因此输出媒体类型可能改变。
- 无编码可用则失败；`auto_resize: false` 时超限直接失败；无法解码也失败。
- 图片缩放器不可用时原图透传；这些设置是处理限制，**不是上传/安全边界**。

### 4.4 限制

| 限制 | 值/行为 |
|---|---|
| 直接附件 | 每项解码后 20 MiB；客户端可能更低 |
| Desktop 选择器 | 总计 20 MiB |
| `max_base64_bytes` | 只算 Base64，不含完整 `data:` URL |
| Provider 图片限制 | OpenCode 处理后仍可能被拒 |
| 文本附件 | 不需要多模态模型 |
| `read` 文本 | 使用独立分页/截断限制 |

## 5. 缓存保温（Warming）

默认关闭。开启后，在 prompt cache 过期前发送周期请求，保持 provider 侧缓存。

```jsonc
{ "warming": true }
```

默认在模型 `cache.ttl` 的 **90%** 处（无 TTL 时每 4 分钟）保温，直到最近一次非保温请求后 **30 分钟**。

### 5.1 选项

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "5 minutes",
    "duration": "1 hour"
  }
}
```

| 字段 | 默认 | 作用 |
|---|---|---|
| `prompt` | keep-alive 指令 | 每次保温请求追加的临时用户消息；默认要求不工作、不用工具、只回 `OK` |
| `interval` | `"auto"` | 下次保温前的空闲时间；auto 用 90% `cache.ttl`，无 TTL 用 4 分钟 |
| `duration` | `"30 minutes"` | 从最近非保温请求起算的保温窗口 |

### 5.2 按 provider/model

`settings.cache.warming` 取与顶层相同的值（除 `prompt`），覆盖顶层；模型覆盖 provider。

```jsonc
{
  "providers": {
    "anthropic": {
      "settings": { "cache": { "ttl": "5m", "warming": true } },
      "models": {
        "claude-haiku-5-5": { "settings": { "cache": { "warming": false } } }
      }
    }
  }
}
```

### 5.3 时长与时机

- `interval`/`duration` 必须是有限正数，且 `interval < duration`，否则跳过并警告。
- 从最近一次请求/保温请求**发送**时计时（不是响应完成）。
- 只保温顶层会话；子会话不保温。
- 保温请求不延长 active window。
- 新的非保温活动（含压缩）重置两个计时器。
- 模型请求/压缩运行时不发保温；到点仍在运行则等结束后立即发（若缓存未过期），否则停止到下次正常请求。

### 5.4 请求、失败与成本

- 保温使用会话当前模型/Agent/指令/对话上下文，临时追加 prompt，调用一次并丢弃响应。
- 不接纳输入、不写历史、不改 durable 状态；不分发本地工具、不继续工具循环。
- 失败只记日志，不改会话；下个间隔再试。
- 缓存未命中（读少于写）会停止该会话保温，直到下次正常请求；不报告缓存用量的 provider 不算 miss。
- **保温是真实请求**：消耗 token、产生成本、计入速率限制。默认在 30 分钟窗口内最多 7 次（第 4/8/12/16/20/24/28 分钟）。
- `warming: false` 显式关闭；省略也关闭。

## 6. 格式化（Formatters）

默认关闭。开启后，在 `write`/`edit`/`patch` 改文件后运行格式化器。

```jsonc
{ "formatter": true }
```

- `true` 启用所有内置；仅当可执行文件与项目要求满足时运行。
- `{}` 保留继承设置并启用内置；`true` 重置为内置。
- 内置包括：`gofmt`、`mix`、`oxfmt`、`prettier`、`biome`、`zig`、`clang-format`、`ktlint`、`ruff`、`air`、`uv`、`rubocop`、`standardrb`、`htmlbeautifier`、`dart`、`ocamlformat`、`terraform`、`latexindent`、`gleam`、`shfmt`、`nixfmt`、`rustfmt`、`pint`、`ormolu`、`cljfmt`、`dfmt`。

自定义：

```jsonc
{
  "formatter": {
    "prettier": {
      "environment": { "NODE_ENV": "development" },
      "extensions": [".js", ".ts"]
    },
    "deno-markdown": {
      "command": ["deno", "fmt", "$FILE"],
      "extensions": [".md"]
    }
  }
}
```

| 字段 | 类型 | 行为 |
|---|---|---|
| `disabled` | boolean | `true` 移除该格式化器 |
| `command` | string[] | 替换内置命令或定义自定义 |
| `environment` | map | 追加环境变量，保留父环境 |
| `extensions` | string[] | 替换扩展名列表；含前导点 |

- `command` 是参数数组，不是 shell 字符串；`$FILE` 替换为绝对路径，工作目录是活动项目目录。
- 匹配**最终扩展名**，大小写敏感；`.part.md` 不匹配 `notes.part.md`（最终是 `.md`）。
- 多个匹配按注册顺序尝试，第一个成功即停止；失败记日志并尝试下一个。
- 要禁用下层启用的格式化：`formatter: false`；禁用单个内置：`{ "prettier": { "disabled": true } }`。

## 7. 工具输出上限

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200
  }
}
```

- 默认 2000 行 / 50 KiB；超出截断，完整内容通常保留在 managed 文件/存储。
- 与 `read`（50 KiB/页）、附件（20 MiB）、浏览器传输（5 MiB）等独立。

## 8. Location 空闲卸载

```jsonc
{ "experimental": { "location_idle_timeout": "4 hours" } }
```

- Location 无会话活动多久后卸载其服务；默认 `"60 minutes"`。
- 运行中的会话与后台任务保持 Location 加载。
- `false` 表示永不卸载。项目配置可覆盖全局。

## 9. 控制面关注点

- **上下文占用条**用 `GET /api/session/{id}/context`，不要按消息长度估算；压缩阈值用 `compaction.buffer` 解释。
- **压缩事件要展示原因与阶段**：`session.compaction.started` 的 `reason` 是 `auto|manual`；`ended`/`failed` 决定 UI 状态。压缩期间避免重复 `steer`。
- **`keep.tokens` 是产品决策**：远程长任务建议调大；控制面可在节点配置层暴露预设（精确/均衡/省 context）。
- **快照不是备份**：控制面不要把 `/undo` 当作“回滚所有副作用”；shell 改动的服务/数据库/网络不会恢复。
- **附件路径是 server 本机路径**：控制面/节点 agent 必须确保 `file:` URL 指向节点可读的路径；跨节点不能直接传本地路径。
- **附件 20 MiB 上限**：控制面应在选择文件时提前校验，避免提交后失败。
- **References 是缓存 checkout**：可能被后台刷新重置；不要把它当作用户工作区。
- **Warming 有成本**：默认关闭；控制面若暴露开关，应显示“会产生额外请求与费用”。
- **Formatter 默认关闭**：开启会改变文件内容，属于“写操作”的一部分；审计时应记录。
- **`location_idle_timeout` 会影响“会话还在不在”**：超时后 Location 卸载，但 durable 会话仍在；控制面不要据此删除索引。
