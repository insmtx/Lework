# 06 会话与消息模型

> 来源：官方 `api`（OpenAPI）、`agents`、`compaction`、`attachments`、`snapshots`、`cli/acp`。
> 契约以 `openapi.json` 为准：`Session.Info`、`Session.Message.Info`、`Session.Inbox.Item`、`Session.ForkBoundary` 等 schema 定义了全部字段。

本文描述 OpenCode V2 的会话（Session）、收件箱（Inbox）、消息（Message）与执行（Execution）模型。理解这一层是控制面做流式 UI、审批、历史回放与“继续对话”的基础。

## 1. 三层身份：Project / Location / Session

| 概念 | 含义 | 关键字段 |
|---|---|---|
| Project | 一个 Git/工作区项目，可含多个 worktree | `projectID`、`project.directory`、`project.canonical` |
| Location | 一次打开的工作目录（可以是 worktree 或子目录） | `location.directory`（绝对路径）、可选 `workspaceID` |
| Session | 一段对话，归属于某个 Project 与 Location | `id`、`projectID`、`location`、`subpath`、`parentID` |

- 一个 server 可以同时加载多个 Location；每个 Location 有独立的配置、插件、MCP 连接与 Agent 列表。
- 会话记录自己的 `location`，因此“会话在哪个目录”是会话属性，不是客户端属性。
- `subpath` 表示会话在 Location 内的相对子路径，用于把同一 worktree 下的多个会话区分到子目录。
- 子会话通过 `parentID` 关联；`fork` 字段记录它从哪个会话的哪个边界复制而来。

```jsonc
// Session.Info（节选）
{
  "id": "ses_...",
  "parentID": "ses_...",          // 子会话才有
  "projectID": "prj_...",
  "location": { "directory": "/work/app" },
  "subpath": "packages/web",
  "agent": "build",
  "model": { "providerID": "anthropic", "id": "claude-sonnet-5-5", "variant": "high" },
  "title": "Timeout cleanup",
  "cost": { "amount": 0.012, "currency": "USD" },
  "tokens": { "input": 1200, "output": 340, "reasoning": 0, "cache": { "read": 0, "write": 0 } },
  "time": { "created": 1760000000000, "updated": 1760000100000, "busy": 1760000010000, "idle": 1760000100000 },
  "metadata": {},
  "permissions": [ /* Permission.Rule[]，会话级覆盖 */ ],
  "revert": { "messageID": "msg_...", "files": [ /* FileDiff.Info[] */ ] },
  "outcome": "succeeded"
}
```

`Session.Info` 必填字段只有 `id`、`projectID`、`cost`、`tokens`、`time`、`location`；其余字段可能缺省。`time.busy` 是最近一次执行的开始时间，`time.idle` 是最近一次进入空闲的时间，`time.viewed`/`time.archived` 用于 UI 排序。

## 2. 会话生命周期 API

### 2.1 创建

```http
POST /api/session
Content-Type: application/json

{
  "id": "ses_custom",           // 可选，客户端指定 ID（幂等重试）
  "parentID": null,             // 创建子会话时指定
  "title": "Review auth flow",
  "agent": "build",
  "model": { "providerID": "anthropic", "id": "claude-sonnet-5-5", "variant": "high" },
  "location": { "directory": "/work/app" },
  "metadata": { "ticket": "ABC-1" },
  "permissions": [ { "action": "edit", "resource": "*", "effect": "deny" } ]
}
```

- 所有字段可选；缺省时使用 Location 的默认 Agent/模型。
- `location` 缺省时使用请求的目录上下文（目录头或 server 默认目录）。
- `permissions` 是**会话级**规则集，追加在全局与 Agent 规则之后；不是替代。
- 返回完整的 `Session.Info`。

### 2.2 列表与分页

```http
GET /api/session?limit=50&order=desc&search=auth&parentID=null&archived=false&directory=/work/app&project=prj_...&subpath=packages/web&cursor=...
```

| 参数 | 说明 |
|---|---|
| `limit` | 默认最新 50 条 |
| `order` | `asc` / `desc`，只影响第一页 |
| `search` | 标题/内容搜索（由 server 实现） |
| `parentID` | 过滤子会话；`null` 表示只看顶层会话 |
| `archived` | `true` / `false` |
| `directory`、`project`、`subpath` | 按 Location/项目过滤 |
| `cursor` | 上一页返回的 `cursor.next` |

响应：

```jsonc
{
  "data": [ /* Session.Info[] */ ],
  "cursor": { "previous": null, "next": "..." }
}
```

`GET /api/session/active` 返回当前有执行在跑的会话列表（`SessionActive[]`，`type: "running"`）。`GET /api/experimental/session/stats` 返回聚合统计（会话数、子会话数、prompt 数、step 数、token、成本、工具使用、活跃天数、streak、模型分布）。

### 2.3 读取、更新、删除

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/session/{sessionID}` | 单个会话 |
| `PATCH` | `/api/session/{sessionID}` | 改标题/元数据/归档等（字段由 schema 约束） |
| `DELETE` | `/api/session/{sessionID}` | 删除会话（204） |
| `POST` | `/api/session/{sessionID}/view` | 记录“已查看”，更新 `time.viewed` |
| `POST` | `/api/experimental/session/{sessionID}/wait` | 等待会话空闲（204），超时由客户端控制 |

### 2.4 导入与导出

```http
GET  /api/experimental/session/{sessionID}/export
POST /api/experimental/session/import
```

导出返回一个可迁移的数据包（消息、元数据、可能的附件引用）；导入在另一个 server/Location 重建会话。格式属于 experimental，控制面不要把导出包当作稳定长期存档格式，重要历史应另存。

## 3. Prompt 提交：入队而非同步

### 3.1 请求

```http
POST /api/session/{sessionID}/prompt
Content-Type: application/json

{
  "id": "msg_custom",             // 可选，客户端消息 ID；同 ID 重试幂等
  "text": "Review src/auth.ts",   // 必填
  "files": [
    {
      "uri": "file:///work/app/src/auth.ts?start=1&end=120",
      "name": "auth.ts",
      "description": "auth entrypoint",
      "mention": { "start": 7, "end": 20 }
    }
  ],
  "agents": [ { "name": "explore", "mention": { "start": 0, "end": 8 } } ],
  "skills": [ { "id": "effect", "mention": { "start": 30, "end": 37 } } ],
  "metadata": { "source": "control-plane" },
  "delivery": "steer",            // steer | queue
  "resume": true                  // 可选：在中断/失败后恢复
}
```

响应是一个 **Inbox item**（`Session.Inbox.Item`），不是助手回复。真正的输出通过事件流获得。

字段细节：

- `text` 必填，即使只发附件也要给空字符串或说明。
- `files[].uri` 必须是 server 可读的绝对 `file:` URL 或 `data:` URL；HTTP(S) 附件不支持。可用 `?start=&end=` 选文本行（1-based）。
- `mention` 用于把 prompt 中的 `@path` 文本位置映射到附件；插件改写文本后必须同步调整 offset。
- `agents` 是“提及”而不是切换当前 Agent；真正的 Agent 切换用 `/agent` 接口。
- `skills` 让 OpenCode 在提交时直接加载指定技能（仍走 `skill` 权限）。
- `delivery` 只有两个值：
  - `steer`（默认）：插到当前执行的下一个安全边界，优先于队列中的后续输入。
  - `queue`：排到队列尾部，等当前执行结束。
- `resume` 用于恢复被中断的会话执行。

### 3.2 入队语义

```text
用户提交 prompt
  → 解析附件/技能/提及
  → 写入 durable inbox
  → 返回 inbox item
  → 当前执行到达安全边界时取队首（steer 优先）
  → 生成 user message + assistant message
  → 通过事件流输出
```

- 相同 `id` 的重复提交返回原 admission，不重复执行（插件 hook 也可能不重复运行）。
- 并发提交可能都通过 hook，但只有第一个成功 admission 生效。
- `delivery: "queue"` 的消息不会打断当前工具循环；`steer` 会在下一个 step 边界插入。

### 3.3 其他输入类型

| 接口 | 作用 | 关键 body |
|---|---|---|
| `POST /api/session/{id}/command` | 执行斜杠命令 | `name`、`text`（必填），可选 `files`/`agents`/`skills`/`delivery` |
| `POST /api/experimental/session/{id}/skill` | 激活技能 | 技能 ID |
| `POST /api/session/{id}/synthetic` | 注入合成消息（系统提示、上下文） | 文本/元数据 |
| `POST /api/session/{id}/shell` | 在会话中执行 shell 命令 | `command`（必填），可选 `id` |
| `POST /api/session/{id}/compact` | 手动压缩 | 可选 `id`、`delivery` |

命令的 `text` 会先按模板展开（`$ARGUMENTS`、`$1`、shell block），再作为用户 prompt 入队。命令可以指定 `agent`/`model`/`subagent`，见 10 号文档。

## 4. Inbox 模型

`Session.Inbox.Item` 是判别联合（discriminated union），按 `type` 区分：

| `type` | payload | 来源 |
|---|---|---|
| `user` | `Session.Inbox.UserPayload`：`text`、`files`、`agents`、`skills`、`metadata` | prompt / command |
| `synthetic` | `Session.Inbox.SyntheticPayload` | 合成消息 |
| `compaction` | `Session.Inbox.CompactionPayload` | 手动压缩 |
| `move` | `Session.Inbox.MovePayload` | 会话迁移 |

每个 item 都带 `delivery: "steer" | "queue"`。

### 4.1 管理接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/session/{sessionID}/inbox` | 列出队列（按投递顺序） |
| `PATCH` | `/api/session/{sessionID}/inbox/{inboxID}` | 修改待投递项（例如改写文本、切换 delivery） |
| `DELETE` | `/api/session/{sessionID}/inbox/{inboxID}` | 取消待投递项（204） |

### 4.2 Inbox 事件

| 事件 | 时机 |
|---|---|
| `session.inbox.enqueued` | item 入队；`data.item` 是完整 item |
| `session.inbox.delivered` | item 被投递给模型 |
| `session.inbox.cancelled` | item 被取消 |
| `session.inbox.delivery.changed` | `steer`/`queue` 改变 |

控制面可以用 `enqueued` + `delivered` 精确显示“排队中/已发送”，而不必轮询。

## 5. Message 模型

`GET /api/session/{sessionID}/message` 返回：

```jsonc
{
  "data": [ /* Session.Message.Info[] */ ],
  "cursor": { "previous": "...", "next": "..." }
}
```

`GET /api/session/{sessionID}/message/{messageID}` 取单条。

`Session.Message.Info` 是一个大联合，按 `type` 区分：

| `type` | schema | 说明 |
|---|---|---|
| `user` | `Session.Message.User` | 用户输入：`text`、`files`、`agents`、`skills`、`metadata`、`time.created` |
| `assistant` | `Session.Message.Assistant` | 助手输出：`content[]`、`agent`、`model`、`cost`、`tokens`、`finish`、`error`、`retry`、`snapshot` |
| `synthetic` | `Session.Message.Synthetic` | 合成/系统注入内容 |
| `system` | `Session.Message.System` | 系统消息 |
| `skill` | `Session.Message.Skill` | 技能加载记录 |
| `shell` | `Session.Message.Shell` | 会话内 shell 命令 |
| `compaction` | `Session.Message.Compaction` | 压缩开始/完成/失败 |
| `idle` | `Session.Message.Idle` | 空闲标记 |
| `agent.selected` | `Session.Message.AgentSelected` | Agent 切换记录 |
| `model.selected` | `Session.Message.ModelSelected` | 模型切换记录 |
| `location.switched` | `Session.Message.LocationSwitched` | Location 迁移记录 |

### 5.1 Assistant 内容块

`content` 是以下三者的数组：

```jsonc
[
  { "type": "text", "text": "..." },
  { "type": "reasoning", "text": "...", "time": { "created": 1760000000000, "completed": 1760000001000 } },
  {
    "type": "tool",
    "id": "call_1",
    "name": "read",
    "executed": true,
    "state": { "status": "completed", "input": { "path": "src/auth.ts" }, "content": [ /* Tool.Content[] */ ], "metadata": {} },
    "time": { "created": 1760000000000, "ran": 1760000000100, "completed": 1760000000200 }
  }
]
```

工具状态机（`Session.Message.ToolState.*`）：

| `status` | 字段 | 含义 |
|---|---|---|
| `streaming` | `input: string` | 模型正在流式生成工具参数（JSON 尚未闭合） |
| `running` | `input: object`、`metadata` | 参数解析完成，工具执行中 |
| `completed` | `input`、`content[]`、`metadata` | 成功；`content` 至少一项 |
| `error` | `input`、`error: Session.StructuredError`、可选 `content` | 失败 |

`Session.StructuredError` 统一了错误形状：`type`、`message`、可选 `status`、`response.body`、`retryAfterMs`。

### 5.2 Assistant 的完成信息

- `finish`：`stop` / `length` / `tool-calls` / `content-filter` / `error` / `unknown`。
- `rawFinish`：provider 原始结束原因。
- `snapshot`：`start`/`end` 快照 ID 与受影响文件列表（见 11 号文档）。
- `native`：provider 原生数据，控制面不应依赖其结构。
- `retry`：重试状态（attempt、下次时间）。

## 6. 执行控制

### 6.1 中断

```http
POST /api/session/{sessionID}/interrupt
```

返回 `{ "interrupted": true|false }`：`true` 表示当前进程确实中断了一个属于它的执行。**它不会中断另一个 OpenCode 进程里的执行**。

### 6.2 后台化阻塞工具

```http
POST /api/session/{sessionID}/background
```

把当前阻塞会话的工具调用（例如长 shell）转入后台任务，让会话继续。后台任务通过 `/api/experimental/job` 与 shell 接口查询。

### 6.3 等待空闲

```http
POST /api/experimental/session/{sessionID}/wait
```

等到会话没有执行时返回 204。控制面在“发送后需要同步结果”的场景可用它，但通常应优先消费事件。

### 6.4 生成辅助文本

```http
POST /api/session/{sessionID}/generate
{ "prompt": "Summarize the current changes" }
```

返回 `SessionGenerateResponse`。它使用会话上下文但不写入会话历史，适用于标题、摘要、分类等辅助请求。与 `POST /api/experimental/generate/text`（完全独立的生成）不同。

### 6.5 读取上下文与 diff

| 接口 | 返回 |
|---|---|
| `GET /api/session/{id}/context` | 当前会话的上下文构成（系统提示、指令、工具、消息 token 估算等） |
| `GET /api/session/{id}/diff` | 按轮次的文件 diff |
| `GET /api/session/{id}/log` | 会话事件日志（`SessionLogItem[]`，可用于调试/重放） |
| `GET /api/session/{id}/environment` | 会话环境变量（若启用） |
| `PUT /api/session/{id}/environment` | 设置会话环境变量 |

`/context` 是控制面显示“上下文占用条”的权威来源；不要自己按消息长度估算。

## 7. Fork / Move / Revert

### 7.1 Fork

```http
POST /api/session/{sessionID}/fork
{ "before": "msg_..." }
```

- `before` 指定分叉边界：复制该消息**之前**的历史；省略时复制全部历史。
- 返回新会话 `Session.Info`，其 `fork` 字段记录 `{ sessionID, boundary }`。
- `Session.ForkBoundary` 有两种：`{ "type": "before", "messageID" }` 与 `{ "type": "through", "messageID" }`。
- 子会话（subagent）也通过 `parentID` 表达，但 fork 是“复制历史”，二者语义不同。

### 7.2 Move

```http
POST /api/session/{sessionID}/move
{ "directory": "/work/app-worktrees/login", "delivery": "queue" }
```

- 把会话迁移到另一个目录（AbsolutePath）。迁移在安全边界生效。
- 目标目录的配置、Agent、MCP、指令会重新加载；会话的历史保留。
- `delivery` 控制迁移请求本身的投递方式。
- 迁移后 `location.switched` 消息与 `session.moved` 事件会出现。

### 7.3 Revert（undo/redo）

OpenCode 的 undo 是“暂存回滚 + 提交/清除”两步：

```text
POST   /api/session/{id}/revert/stage   { "messageID": "msg_...", "files": true }
POST   /api/session/{id}/revert/commit  → 真正提交回滚
DELETE /api/session/{id}/revert         → 取消暂存（redo）
```

- `stage` 会把目标消息之后的消息标记为待回滚，并恢复受影响文件（`files: false` 可只回滚对话）。
- `Session.Info.revert` 保存暂存状态：`messageID`、`partID`、`snapshot`、`files: FileDiff.Info[]`。
- 提交后消息从活动视图移除，但**不删除** durable 历史或快照对象。
- 会话正在执行时，server 会拒绝回滚。
- 快照依赖 Git 且只覆盖会话活动目录，见 11 号文档。

## 8. Agent / Model / 权限切换

| 接口 | body | 说明 |
|---|---|---|
| `POST /api/session/{id}/agent` | `{ "agent": "plan" }` | 切换 Agent，产生 `agent.selected` 消息 |
| `POST /api/session/{id}/model` | `{ "model": { "providerID": "...", "id": "...", "variant": "..." } }` | 切换模型，产生 `model.selected` 消息 |
| `POST /api/session/{id}/permission` | `{ "action", "resources", "save", "metadata", "source", "agent" }` | 由客户端/插件主动创建权限请求 |
| `GET` | `/api/session/{id}/permission` | 列出该会话待处理请求 |
| `GET` | `/api/session/{id}/permission/{requestID}` | 单条请求 |
| `POST` | `/api/session/{id}/permission/{requestID}/reply` | `{ "decision": "once"|"always"|"reject", "message": "..." }` |

全局待处理请求：`GET /api/permission/request`（可用 `location` 过滤）。已保存的审批：`GET /api/permission/saved`、`PATCH /api/permission/saved/{id}`、`DELETE /api/permission/saved/{id}`。详见 09 号文档。

## 9. 典型调用序列（控制面）

```text
1. GET /api/info                       → server 版本/认证/能力
2. GET /api/location                   → 当前目录与项目
3. POST /api/session                   → 创建会话
4. GET /api/event?types=session.*,permission.*   → 先订阅
5. POST /api/session/{id}/prompt       → 入队
6. 消费事件：
   session.execution.started
   session.step.started
   session.text.delta / reasoning.delta
   session.tool.input.* → called → progress → success|failed
   session.step.ended
   session.execution.succeeded|failed|interrupted
   session.usage.updated
   session.idle
7. GET /api/session/{id}/message       → 需要补全历史时拉取
8. permission.asked → POST .../reply   → permission.replied
```

**先订阅再提交**：事件流是 live-only，没有重放；晚订阅会丢掉提交瞬间的事件。若确实错过了，用 `GET /api/event` 重连后拉取 `GET /api/session/{id}/message` 与 `/api/session/{id}/log` 对齐。

## 10. 控制面关注点

- **不要把 Session/Message 复制进控制面数据库作为主状态。** 控制面只存索引（节点、会话 ID、标题、活跃时间、未读数）与 UI 偏好；详情按需向节点 agent 查询。
- **会话 ID 是跨节点路由键。** 控制面需要维护 `sessionID → nodeID/location` 映射，并在节点断线时标记为“不可达”，而不是伪造会话。
- **`delivery` 的语义要在 UI 明确展示**：`steer` 会打断当前步骤，`queue` 不会。默认使用 `queue` 更符合“远程排队”的预期。
- **审批要展示 `action` 与完整 `resources`**，并区分 `once`/`always`/`reject`。`always` 会写入项目级持久规则，控制面应提示其影响范围。
- **`/context` 用于上下文占用展示**；`compaction.*` 事件用于提示“正在压缩/已压缩”，不要在压缩期间重复提交 `steer`。
- **`interrupt` 只作用于当前进程**；控制面调用前应确认该会话由目标节点托管。
- **`revert/stage` 不是删除**：UI 应显示“待回滚”，并提供 `commit` 与 `clear` 两个动作。
- **子会话展示**：`parentID` + `session.created` 的 `parentID` 能构建树；ACP 里子会话事件带 `_meta["opencode/child-session"]`，HTTP 事件流则通过 `parentID` 关联。
