# 14 插件开发

> 来源页面：`/docs/build/plugins`、`/docs/build/plugins/server`、`/docs/build/plugins/cli`、`/docs/build/plugins/gui`、`/docs/build/plugins/rpc`、`/docs/build/plugins/effect`、`/docs/build/plugins/migrate-v1`、`/docs/plugins`
> 适用版本：OpenCode V2（`@opencode/plugin`）。GUI 插件仍标记为 experimental。

插件是 OpenCode 官方的进程内扩展机制。和“从外部调 HTTP API”不同，插件直接运行在 OpenCode server（或 TUI / Desktop）里，可以**注册工具、命令、Agent、技能、MCP 服务器、Provider 模型**，也可以**拦截 prompt、模型请求、权限判定、shell、工具执行**。

对 lework 控制面而言，插件是“节点侧深度定制”的正规入口；控制面自身仍应通过 HTTP API / SSE 观察 OpenCode，**不要用插件复制会话状态**。

---

## 1. 插件模型

### 1.1 一个包，四个可选部分

| 部分 | `exports` 键 | 运行位置 | SDK | 用途 |
|---|---|---|---|---|
| Server | `.` 或 `./server` | OpenCode server | `@opencode/plugin` | 工具、hooks、transform、命令、Agent、MCP、RPC 实现 |
| TUI | `./tui` | 终端 UI | `@opencode/plugin/tui` | 命令、路由、slot、Markdown 渲染、对话框 |
| GUI | `./gui-experimental` | OpenCode Desktop 窗口 / Electron 主进程 | `@opencode/plugin/gui` | 面板、设置页、命令、原生集成 |
| RPC | `./rpc` | 类型契约（无运行时代码） | `@opencode/plugin/rpc` | server 实现、其他部分和外部客户端调用 |

一个条目加载插件的所有部分。TUI 会加载其 server 所加载插件的 TUI 部分；Desktop 只从**全局** `opencode.json(c)` 读取 GUI 部分。

### 1.2 包结构

```json title="package.json"
{
  "name": "opencode-acme-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./tui": "./src/tui.tsx",
    "./gui-experimental": "./dist/gui-experimental.cjs",
    "./rpc": "./src/rpc.ts",
    "./contract": "./src/contract.ts"
  },
  "files": ["src", "dist"],
  "dependencies": {
    "@opencode/plugin": "latest"
  }
}
```

本地目录没有 `package.json` 的 `name`/`exports` 时，按根目录文件名解析：

- `server`（否则 `index`）
- `tui`
- `rpc`
- `gui-experimental.cjs`（或 `.js`）

扩展名可为 `.ts` / `.tsx` / `.js`（GUI 例外，只接受 `.cjs` / `.js`）。

### 1.3 插件 ID

- server 部分的 `id` 来自 `Plugin.define`。
- 只有 GUI 的包用包名（本地目录用目录名）。
- TUI 部分自己声明 `id`。
- GUI 部分不声明 `id`，继承插件 ID。
- GUI 会用它给所有对象加前缀：命令 `<id>.<command>`、面板键 `<id>:<tab>`、存储键 `plugin.<id>.<key>`。

## 2. 加载与配置

### 2.1 配置条目

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    "opencode-acme-plugin",
    "opencode-acme-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": { "agent": "reviewer", "strict": true }
    }
  ]
}
```

- 相对路径相对于**包含该条目的配置文件**解析。
- 配置的本地路径必须是目录；单文件路径会被跳过。
- 多个配置文件的 `plugins` 数组按优先级**累加**，不是后者覆盖前者（低 → 高：全局 → 项目 → `.opencode/`）。

### 2.2 自动发现

OpenCode 会从每个被发现目录的 `.opencode/plugins/` 加载：

- 直接的 `.ts` / `.js` 文件
- 直接子目录中的插件包

```text
.opencode/
└── plugins/
    ├── concise.ts
    ├── reviewer.js
    └── acme-package/
```

全局插件使用同样布局：`~/.config/opencode/plugins/`。

项目根 `opencode.json(c)` 旁边的 `plugins/` 目录**不会**自动发现，必须显式配置。

### 2.3 启用/禁用

```jsonc
{
  "plugins": ["*", "-opencode.provider.*", "opencode.provider.openai", "-acme.reviewer"]
}
```

- `-` 前缀禁用；`*` 匹配全部；`.*` 匹配 ID 前缀。
- 后面的同 ID 条目可重新启用。
- 两个内置插件忽略移除，防止仓库关闭策略执行：
  - `opencode.config.policy`
  - `opencode.provider.opencode`（Console 组织策略连接）

### 2.4 CLI 管理

```sh
opencode plugin add opencode-acme-plugin@1.2.0
opencode plugin list
opencode plugin list --builtin
opencode plugin check
opencode plugin update
opencode plugin update opencode-acme-plugin
opencode plugin remove opencode-acme-plugin@1.2.0
```

`plugin add` 支持 npm 版本/标签/范围、Git 托管简写、HTTPS、SSH、`::path:` 子目录；不接受 tarball 和 npm alias。本地插件与精确版本/完整 commit 不参与自动更新。

### 2.5 重载

- 被监视的配置目录变更会自动重载。
- server 启动时立即加载缓存的包插件，后台安装缺失包，并检查未固定版本更新（不改变已安装版本）。
- 未监视的本地依赖变更可能需要 `opencode service restart`。

## 3. Server 插件基础

### 3.1 最小形态

```ts title=".opencode/plugins/example/index.ts"
import { Plugin } from "@opencode/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

`setup` 在插件加载时运行，可返回 cleanup：

```ts
export default Plugin.define({
  id: "example",
  setup(ctx) {
    console.log(`loaded in OpenCode ${ctx.app.version}`)
    return () => console.log("unloaded")
  },
})
```

### 3.2 Context

插件 context 基本就是“OpenCode server client + 插件专属能力”：

- `ctx.app`：`name` / `version` / `channel`
- `ctx.location`：当前插件实例加载位置
  - `directory`
  - 可选 `workspaceID`
  - `project.id` / `project.directory` / `project.canonical`
- `ctx.options`：`plugins` 对象条目里的 `options`
- 领域 API：`ctx.session`、`ctx.tool`、`ctx.permission`、`ctx.event` 等
- 插件专属：`transform`、`hook`、`reload`、`storage`、`rpc`

`ctx.location` 是**插件实例**的位置，不是它能访问的每个会话/事件的位置；处理多 location 事件时必须读事件自身的 location。

### 3.3 生命周期与注册

- `setup` / `effect` 运行一次。
- 返回的 cleanup / Effect scope 关闭时释放资源。
- 所有 transform、hook、RPC、事件订阅都随插件卸载自动释放。
- 需要提前撤销时保留返回的 `Registration` 并调用 `dispose()`（幂等）。

## 4. Transforms：可重放的领域状态编辑

### 4.1 语义

Transform 是**同步**编辑 OpenCode 领域状态的注册：

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
})
```

关键规则：

1. 回调必须同步、轻量、可重复执行。
2. 任何注册、移除或 `reload()` 都会把该领域标记为变更；下一次读取会在**新值上按注册顺序重放全部 transform**。
3. 读取 API（如 `ctx.model.list()`）反映到目前为止的所有注册，包括 setup 期间。
4. 资源状态 API 仍反映真实连接状态：注册了定义不等于连接/刷新已完成。
5. 不要依赖一次性副作用；外部数据要在注册前加载并捕获，变化后调用领域 `reload()`。
6. 后注册的 transform 能看到并覆盖先注册的结果。
7. 已经读取到的值是快照，不会被后续重建修改。

### 4.2 领域与编辑器能力

#### Agent

```ts
const agents = await ctx.agent.list()
const build = await ctx.agent.get({ agentID: "build" })

await ctx.agent.transform((editor) => {
  editor.default("build")
  editor.update("build", (agent) => {
    agent.description = "Builds features and fixes bugs"
  })
  editor.remove("legacy")
})
await ctx.agent.reload()
```

编辑器：`list()`、`get(id)`、`default(id|undefined)`、`update(id, fn)`、`remove(id)`。

#### Provider

```ts
await ctx.provider.transform((editor) => {
  editor.update("anthropic", (provider) => {
    provider.headers = { ...provider.headers, "x-company": "engineering" }
  })
  editor.models.update("anthropic", "claude-sonnet-5-5", (model) => {
    model.name = "Team Sonnet"
  })
  editor.models.remove("anthropic", "legacy-model")
  editor.remove("legacy-provider")
})
```

- 编辑器读取包含非活动 provider，返回不可变定义。
- `models.set` 整体替换来源模型清单。
- `sourceConnection` 用于账号相关发现：当用户切换到另一个连接时，OpenCode 会排除该 provider，直到插件发布刷新后的清单。
- provider 变更会使整个活动模型结果失效。

#### Model

```ts
await ctx.model.transform((editor) => {
  editor.list("anthropic").forEach((model) => {
    editor.update(model.providerID, model.id, (draft) => {
      draft.enabled = draft.capabilities.tools
    })
  })
  editor.default.set("anthropic", "claude-sonnet-5-5")
  editor.remove("anthropic", "legacy-model")
})
```

- 编辑的是整个活动 provider 的候选集合。
- 被禁用的候选在所有 transform 结束前仍可编辑；`update` 只能给可用 provider 增模型。
- 回调编辑原始 override；provider 默认值在提交结果时合并一次。
- `editor.provider` 暴露不可变来源定义（含非活动模板），不是 model transform 的输出。

#### Command

```ts
await ctx.command.transform((editor) => {
  editor.add({
    name: "security-review",
    description: "Review changes for security issues",
    execute: async ({ sessionID, prompt, delivery }) => {
      await ctx.session.prompt({
        ...prompt,
        sessionID,
        text: `Review these changes for security issues.\n\n${prompt.text}`,
        delivery,
      })
    },
  })
})
```

- 编辑器只有 `add`。
- `execute` 收到 `sessionID`、`prompt`、`delivery`。

#### Integration / Credential

```ts
const integrations = await ctx.integration.list()
const connection = await ctx.integration.connection.active("github")
const credential = connection
  ? await ctx.integration.connection.resolve(connection)
  : undefined

await ctx.integration.connect.key({ integrationID: "github", key: process.env.GITHUB_TOKEN! })

const attempt = await ctx.integration.oauth.connect({ integrationID: "github", methodID: "oauth" })
await ctx.integration.oauth.status({ integrationID: "github", attemptID: attempt.data.attemptID })
await ctx.integration.oauth.complete({ integrationID: "github", attemptID: attempt.data.attemptID, code })
await ctx.integration.oauth.cancel({ integrationID: "github", attemptID: attempt.data.attemptID })

await ctx.credential.activate({ credentialID })
```

命令式连接也有 `command.connect` / `status` / `cancel`。transform 可管理 integration 与认证方法。

#### MCP

```ts
await ctx.mcp.transform((editor) => {
  editor.set("docs", { type: "remote", url: "https://mcp.example.com" })
  editor.update("docs", (server) => {
    server.disabled = false
  })
  editor.remove("legacy")
})
```

- `disabled: true` 会断开并禁用；`false` 允许 OpenCode 重连。
- OpenCode 根据 transform 后的配置协调服务器生命周期。

#### Reference / Skill

```ts
await ctx.reference.transform((editor) => {
  editor.add("handbook", { type: "local", path: "/workspace/docs/handbook" })
  editor.add("standards", { type: "git", repository: "https://github.com/acme/standards", branch: "main" })
  editor.remove("legacy")
})

await ctx.skill.transform((editor) => {
  editor.add({
    id: Skill.ID.make("review"),
    name: Skill.Name.make("Review"),
    description: "Review the current changes",
    path: Skill.Info.fields.path.make("/workspace/.opencode/skills/review/SKILL.md"),
    content: "Review the current changes for correctness and missing tests.",
  })
  editor.update("review", (skill) => {
    skill.autoinvoke = true
  })
  editor.remove("legacy")
})
```

#### Tool

```ts
const registration = await ctx.tool.transform((editor) => {
  editor.namespace({ name: "acme", description: "Customer account tools" })
  editor.add({
    name: "greeting",
    description: "Create a greeting",
    input: {
      type: "object",
      properties: { name: { type: "string" } },
      required: ["name"],
      additionalProperties: false,
    },
    options: { namespace: "acme", codemode: true },
    execute: async (input, context) => {
      await context.progress({ status: "greeting" })
      return { content: `Hello ${(input as { name: string }).name}!` }
    },
  })
})
```

- `execute` 第二参数提供 `signal`（传给 `fetch` 等可取消操作）和 `progress`。
- 同一有效工具名的后注册覆盖先注册。
- `update` / `remove` 使用有效名（含 namespace，如 `acme_greeting`）。
- namespace 中的点与工具名不支持字符会变 `_`。
- 每次模型请求捕获稳定的工具快照；后续 transform/reload/dispose 只影响未来请求。
- 释放 registration 会移除该 transform 并从剩余 transform 重建，可能露出被覆盖的早期定义。

**Freeform 输入**：直接工具若只有一个必填字符串字段，可声明：

```ts
freeform: { type: "text" }
freeform: { type: "regex", pattern: "OPS-[0-9]+" }
freeform: { type: "lark", grammar: "..." }
```

如果模型 API 在 models.dev 中列出 `regex`，模型可直接写 `OPS-42`；否则 OpenCode 只省略 `freeform`，模型仍以 `{"id":"OPS-42"}` 调用。Code Mode 中可 `await tools.ticket("OPS-42")`。

#### VCS / Worktree / Websearch

```ts
const info = await ctx.vcs.get()
const changes = await ctx.vcs.status()
const diff = await ctx.vcs.diff({ mode: "working", context: 3 })

await ctx.vcs.transform((editor) => {
  editor.add({
    id: "custom",
    name: "Custom VCS",
    info: async () => ({ branch: { current: "feature", default: "main" } }),
    branches: async (input, { signal }) => readBranches(input, signal),
    status: async (scope, { signal }) => readStatus(scope.worktree, signal),
    diff: async (input, { signal }) => readDiff(input, signal),
  })
  editor.default.set("custom")
})

await ctx.websearch.transform((editor) => {
  editor.add({
    id: "internal",
    name: "Internal search",
    execute: async ({ query }, { signal }) => {
      const response = await fetch(`https://search.example.com?q=${encodeURIComponent(query)}`, { signal })
      const result = (await response.json()) as { url: string; title: string; content: string }
      return [{ url: result.url, title: result.title, content: result.content, time: {} }]
    },
  })
  editor.default.set("internal")
})
```

Worktree 策略通过 `ctx.worktree.transform` 注册，随后 `create` / `list` / `refresh` / `remove` 都要求 `projectID`。策略可抛 `new Worktree.OperationError({ message, forceRequired })` 请求强制确认。

#### Session / Permission / Generate

```ts
const created = await ctx.session.create({ title: "Review" })
const messages = await ctx.session.context({ sessionID })
const prompt = await ctx.session.prompt({ sessionID, text: "Review the current changes" })
const generated = await ctx.session.generate({ sessionID, prompt: "Summarize this project" })
await ctx.session.command({ sessionID, name: "review", text: "--staged" })
await ctx.session.synthetic({ sessionID, text: "Deployment completed" })
await ctx.session.update({ sessionID, title: "Review" })
await ctx.session.interrupt({ sessionID, resume: false })
await ctx.session.wait({ sessionID })
await ctx.session.remove({ sessionID })
```

- `session.list` 使用 `cursor` 分页；`cursor.next` 记住过滤条件。
- `remove` 会停止执行并递归删除子会话。
- `compact` 返回被接纳的 inbox item，不是完成的摘要；默认在下一个 step 边界执行。
- `instructions.entry.put/list/remove` 维护 `<context key="...">` 块，更新在下一个 step 边界公告，不排消息轮次。
- `permission.assert` 按会话权限规则（含已保存审批）判断；`deny` 直接拒绝，`ask` 弹审批。
- `permission.list/get/reply` 查看/回复待审批。
- `session.update({ permissions })` 替换会话级规则，在 Agent 规则之后求值，最后匹配生效；子会话继承创建时生效的规则。
- `ctx.experimental.generate.text/image/decisions` 不创建会话、不调工具、不写历史；`ctx.generate.text` 已弃用。

## 5. Hooks：拦截实时操作

Hook 注册在拥有该操作的领域上，返回 registration。多个插件可注册同一 hook，按插件顺序执行，后者能看到前者的修改。

```ts
const registration = await ctx.session.hook("context", () => {})
await registration.dispose()
```

### 5.1 Session hooks

| Hook | 触发点 | 可改 |
|---|---|---|
| `fork` | 复制历史后、fork 返回前 | 只读观察（`sessionID`） |
| `prompt` | 用户 prompt 进入持久 inbox 前 | `text`、`files`、`agents`、`skills`、`metadata`、`delivery` |
| `context` | agent 循环每次模型请求前 | `system`、`messages`、`tools`、`options` |
| `compaction` | 检查点摘要请求前 | 同上；可设 `result` 跳过模型 |
| `generate` | `session.generate` 请求前 | 同上 |
| `title` | 标题生成请求前 | `system`、`messages`、`options`；可设 `result` |
| `experimental.model.resolve` | 会话解析模型时、构建请求前 | `model`（同 provider，可隐藏模型） |
| `model.request` | 模型请求设置 | `headers` 等 |
| `http.request` / `http.response` | 原生 provider HTTP | 请求/响应（body 是单次流） |
| `experimental.ws.handshake/send/receive` | WebSocket provider | URL、headers、frame |
| `retry` | 失败分类后、安排重试前 | `decision = {retry, delay}` |

#### prompt hook 细节

```ts
await ctx.session.hook("prompt", (event) => {
  event.prompt.text = event.prompt.text.replaceAll("company-secret", "[redacted]")
  event.prompt.files ??= []
  event.prompt.files.push({ uri: "file:///project/policy.md" })
  event.metadata = { ...event.metadata, source: "company-policy" }
  event.delivery = "queue"
})
```

- 收到的是可变的**所有权草稿**。
- 会话 ID、消息 ID 只读，不能改投递目标。
- 新增文件和技能走正常解析/校验。
- 改写文本时要同步修正/删除附件 `mention` 偏移。
- Agent mention 不会切换会话当前 Agent。
- 只在通过 `session.prompt` 的提交上运行；synthetic、shell、compaction 控制、move 控制不运行。
- 只在准入时运行一次，不是每次模型调用。
- 因为模型解析发生在准入之后，prompt hook 不能按 provider 作用域。
- 编辑结果成为持久化的规范用户输入。
- 不是 exactly-once 副作用边界：重试已 pending/delivered 的 ID 返回原准入且不重跑；并发提交可能多次运行，但只有第一个成功准入生效。

#### context / 请求覆盖

```ts
await ctx.session.hook("context", (event) => {
  event.system.push({ type: "text", text: "Keep the review focused on correctness." })
  delete event.tools.write
  event.options.temperature = 0.2
  event.options.maxTokens = 8_000
})
```

- 修改只影响本次外发请求，不影响持久历史或配置。
- 要向所有请求种类生效，必须分别注册 `context`、`compaction`、`generate`、`title`。
- `options` 每次调用从空开始，不含已解析模型设置。
- 类型化键是生成参数；其他键作为 provider option 传给协议。
- 请求覆盖优先于模型默认值，模型默认值优先于路由默认值。
- provider option 对象递归合并；数组与标量替换。
- 删除或设为 `undefined` 会回退到配置默认值，而不是移除。
- 原始 HTTP body overlay 在协议 lowering 之后应用，可覆盖最终字段。
- 可用第三个参数 `{ providerID }` 限定 provider。

#### 权限 hook

```ts
await ctx.permission.hook("evaluate", async (event) => {
  if (event.action === "read") return
  const messages = await ctx.session.context({ sessionID: event.sessionID })
  const review = await ctx.generate.text({ /* ... */ })
  event.effect = parseDecision(review.text).effect
  event.message = parseDecision(review.text).reason
})
```

- 只对 `allow` 与 `ask` 结果运行。
- 配置中的显式 `deny` 是最终结果，不调用 hook。
- hook 可改成 `allow` / `ask` / `deny`。
- `message` 会出现在升级后的审批请求或拒绝原因里。

#### shell / tool hooks

```ts
await ctx.shell.hook("create.before", (event) => {
  event.timeout = Math.min(event.timeout, 60_000)
  event.env.COMPANY_ENV = "development"
})

await ctx.tool.hook("execute.before", (event) => {
  if (event.tool === "read") console.log(event.input)
})

await ctx.tool.hook("execute.after", (event) => {
  if (event.status === "completed") event.result = { ...event.result, metadata: { observed: true } }
  if (event.status === "error") console.error(event.error.message)
})
```

`execute.before` 可替换输入或抛错阻止执行；`execute.after` 可观察/替换成功结果或失败。

## 6. RPC：插件自定义方法

### 6.1 定义契约

```ts title="src/rpc.ts"
import { Rpc } from "@opencode/plugin/rpc"

export const Acme = Rpc.define({
  id: "acme",
  methods: {
    search: {
      input: {
        type: "object",
        properties: { query: { type: "string" } },
        required: ["query"],
        additionalProperties: false,
      },
      output: {
        type: "object",
        properties: { text: { type: "string" } },
        required: ["text"],
        additionalProperties: false,
      },
      errors: {
        not_found: {
          type: "object",
          properties: { query: { type: "string" } },
          required: ["query"],
          additionalProperties: false,
        },
      },
    },
  },
  events: {
    updated: {
      schema: {
        type: "object",
        properties: { itemID: { type: "string" }, text: { type: "string" } },
        required: ["itemID", "text"],
        additionalProperties: false,
      },
    },
  },
})
```

- 支持 JSON Schema 或任意 Standard Schema 校验器（Zod / Valibot / ArkType）。
- 方法可省略 `input` / `output`。
- `errors` 的 key 成为错误 `type`，schema 定义 `data`。
- 以 `rpc.` 开头的错误名保留给 OpenCode。
- 事件数据必须是对象；无数据用空对象 schema。
- 标量、数组、`null`、`undefined` 不是合法事件数据。

### 6.2 实现与调用

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"
import { Acme } from "./rpc.js"

export default Plugin.define({
  id: "acme-plugin",
  async setup(ctx) {
    const registration = await ctx.rpc.register(Acme, {
      search: async (input, context) => {
        const { query } = input as { query: string }
        const text = await findText(query, { signal: context.signal })
        if (!text) return context.error("not_found", "Result not found", { query })
        return { text }
      },
    })

    const acme = ctx.rpc(Acme)
    const result = await acme.search({ query: "hello" })

    await registration.events.emit("updated", { itemID: "item-1", text: "ready" })
  },
})
```

外部客户端：

```ts
import { OpenCode } from "@opencode/client"
import { Acme } from "opencode-acme-plugin/rpc"

const client = OpenCode.make({ baseUrl: "http://localhost:4096" })
const acme = client.rpc(Acme)
const result = await acme.search({ query: "hello" })
```

HTTP 形态为 `POST /api/rpc/{rpcID}/{method}`。

### 6.3 订阅

```ts
const unsubscribe = acme.events.on("updated", (event) => {
  console.log(event.type, event.location.directory, event.data.text)
})
unsubscribe()

for await (const event of acme.events.subscribe("updated")) {
  console.log(event.data.text)
}
```

- 订阅是 live-only，断线会丢事件。
- 订阅用本地名（`updated`），收到类型带前缀（`rpc.acme.updated`）。
- 每个事件含 `data` 与 `location`；外部客户端会收到所有 location 的事件。
- 插件卸载会关闭其订阅。

## 7. TUI 插件

TUI 插件是包的 `./tui` 部分，扩展终端 UI。

```tsx title="src/tui.tsx"
import { Plugin } from "@opencode/plugin/tui"

export default Plugin.define({
  id: "acme.cli",

    context.ui.toast.show({ message: "TUI plugin loaded", variant: "success" })

```

`setup` 拿到：options、app 元数据、当前 location、OpenCode client、缓存数据、theme token、OpenTUI renderer、UI API。可返回 cleanup。

### 7.1 数据与事件

```ts
const stopPermission = context.data.on("permission.asked", (event) => {
  context.ui.toast.show({ message: `Permission ${event.data.id}` })

const stopAll = context.data.listen(({ details }) => console.log(details.type))

const sessions = context.data.session.list()
const session = context.data.session.get(sessionID)
const pending = await context.data.session.pending.sync(sessionID)
const messages = await context.data.session.message.list(sessionID)
```

还提供 projects、shell、location、vcs、agent、command、integration、model、provider、reference、skill、mcp 的 `list/sync/invalidate`。

### 7.2 命令与快捷键

```ts
context.keymap.layer(() => ({
  mode: "global",
  priority: 10,
  commands: [
    {
      id: "acme.status",

      group: "Acme",

```

layer 在以下最早发生时移除：插件禁用/重载/setup 失败；创建它的组件或响应式计算销毁。工厂必须纯。

### 7.3 Slot / 对话框 / 路由

```tsx
return context.ui.slot({
  append: "sidebar.content",
  render: ({ sessionID }) => <text>{context.data.session.get(sessionID)?.title}</text>,

```

Slot 位置：`app`、`home.footer`、`home.footer.status`、`prompt.footer`、`prompt.footer.status`、`prompt.footer.file`、`session.composer.top`、`sidebar.content`、`sidebar.footer`，以及 `session.panel`。放置方式：`prepend` / `append` / `before` / `after` / `replace`。

Markdown：`context.markdown.registerCodeBlockRenderer(lang, fn)`。

注意力：`context.attention.notify({ title, message, notification: { when }, sound: { name, volume, when } })`。

## 8. GUI 插件（experimental）

GUI 插件给 OpenCode Desktop 增加面板、命令、设置页和原生集成，是包的 `./gui-experimental` 部分。

### 8.1 两个进程

- `setup`：每个 Desktop 窗口运行；注册面板、命令、设置页、slot、server 来源、链接处理器、样式。
- `main`：Electron 主进程运行一次；提供 `Ipc` 契约、原生菜单、`WebContentsView`、Node/Electron 集成。

同一文件在两个进程都被求值，另一边模块用惰性占位符代替。每个进程的代码放在自己的 setup 内。

### 8.2 构建

`./gui-experimental` 必须是预构建的单个 CommonJS 文件：

```ts title="vite.config.ts"
import { defineConfig } from "vite"
import { gui } from "@opencode/plugin/gui/vite"

export default defineConfig({ plugins: [gui()] })
```

```bash
vite build
```

预设会编译 Solid JSX、内联动态 `import()`、保留共享模块 external、打包其余依赖，并在遇到非共享的 `effect/*`、`solid-js/*`、`@opencode/*` 时构建失败。

### 8.3 声明与注册

```ts
export const definition = Plugin.define({
  os: ["macos", "linux"],
  stores: {
    prefs: Store.global(Schema.Struct({ enabled: Schema.Boolean }), { enabled: true }),
  },
  i18n: {
    en: { title: "Acme", "command.open": "Open Acme" },
    de: { title: "Acme", "command.open": "Acme öffnen" },
  },
})
```

可用 registry：

| Registry | 用途 |
|---|---|
| `Command` | 命令面板、快捷键、`/` 菜单 |
| `Panel` | 会话侧栏 tab（可拖到底部） |
| `SettingsPage` | 设置页 / 宿主页面 section / General 行 |
| `Slot` | `window.bottom`、`session.header`、`session.location.menu`、`session.panel.end` |
| `MenuItem` | 侧栏 `+`、Add server、server 行菜单 |
| `TitlebarItem` | 标题栏胶囊按钮 |
| `ComposerPill` | composer 上方的状态胶囊 |
| `CodeBlock` / `CodeBlockAction` | 自定义 fenced code 渲染与按钮 |
| `LinkHandler` | 打开本地文件/自定义链接 |
| `Server` | 贡献服务器连接列表 |
| `Style` / `Theme` | CSS 与主题 |

`ctx.add(registry, item | () => item | undefined)` 返回撤销函数；项跟随响应式状态时传函数，返回 `undefined` 表示暂时撤回。

### 8.4 契约与 IPC

- `Contract.define<Api, "acme.badge">("acme.badge")`：窗口 setup 向其他插件暴露 API/组件；`ctx.provide` 提供，`ctx.use` 消费。
- `Ipc.define({ id, methods: { ... Effect Schema } })`：主进程与窗口之间的类型化桥；`main` 用 `ctx.provide` 实现，窗口用 `ctx.main(token)` 调用。
- `Registry.define<T>("acme.exporter")`：插件拥有的列表，其他插件 `ctx.add`，拥有者 `ctx.list`。
- token ID 必须是插件自己的 ID 或以 `<id>.` 开头。

### 8.5 宿主 API

常用：`ctx.layout`（面板打开/关闭/状态/宽度/设置/草稿）、`ctx.sessions.current()`、`ctx.screen.current()?.composer`（读写 prompt、附件、模型）、`ctx.servers.get("sidecar")`、`ctx.dialogs`、`ctx.toast`、`ctx.attention`、`ctx.tabs`、`ctx.keybinds`、`ctx.commands.run`、`ctx.system`、`ctx.desktop`、`ctx.storage`、`ctx.ui`。

存储：`Store.global` / `Store.session` 在 `Plugin.define` 声明；运行时用 `ctx.storage.store(key, { schema, initial, scope })`，scope 可为 `"global"`、`{ server, directory? }`、`{ session }`。

响应式辅助：`createKeyed`、`createLatest`、`createVisitState`、`usePanel`、`useDrawer`。

## 9. Effect 插件（可选）

`@opencode/plugin/effect` 是 Effect 原生版本：

```ts
import { Plugin } from "@opencode/plugin/effect"
import { Effect } from "effect"

export default Plugin.define({
  id: "example",
  effect: (ctx) =>
    Effect.gen(function* () {
      yield* ctx.storage.set("loaded", true)
    }),
})
```

- 生命周期由 `Scope` 表示；scope 关闭时释放注册、scoped fiber 与 finalizer。
- 后台任务用 `Effect.forkScoped`。
- 操作返回 `Effect`，事件是 `Stream`。
- 宿主会重定向 `effect`、`effect/*`、`@opencode/plugin` 导入到自己的运行时实例；**不要把 effect 打进产物**，构建时标记 external。
- 能力面与 Promise 版基本对应，但部分 API 形状不同（如 `command.transform` 仅 add、集成 OAuth 用 Effect）。

## 10. 同一包兼容 V1 与 V2

```ts title="src/index.ts"
import { Plugin } from "@opencode/plugin"

export default {
  ...Plugin.define({
    id: "example",
    async setup(ctx) {
      await ctx.tool.hook("execute.before", () => {
        console.log("A tool is about to run")
      })
    },
  }),
  async server() {
    return {
      "tool.execute.before": async () => {
        console.log("A tool is about to run")
      },
    }
  },
}
```

- V1 调 `server()` 并使用返回的 hooks。
- V2 读默认导出的 `id` 与 `setup()`（或 `effect()`），忽略 `server()`。
- 两套实现彼此独立，不会自动翻译。
- V1 对象形态从 OpenCode `1.18.29` 起支持。

## 11. 控制面关注点

1. **插件是节点侧能力，不是控制面状态源。** 插件注册的 Agent / Skill / Command 会通过 `/api/agent`、`/api/skill`、`/api/command` 暴露；控制面读取即可，不要另建注册表。
2. **工具没有独立列表 API。** 插件新增工具只能通过会话消息里的 tool part 观察；控制面不要把“工具清单”做成强一致前提。
3. **权限 hook 不适合做远程同步审批。** `permission.hook("evaluate")` 在 server 内同步等待；远程控制面审批应走 `permission.asked` 事件 + reply 接口，避免把网络延迟塞进 hook。
4. **prompt hook 可以脱敏，但不能保证 exactly-once。** 若用于审计/脱敏，必须容忍并发重复执行；不要把关键副作用放在这里。
5. **组织级强制限制用 `policies`，不要用插件。** 插件可被项目配置禁用；`opencode.config.policy` 与 Console 策略连接是受保护的。
6. **RPC 是额外 API 面。** 控制面若调用插件 RPC，需要自行定义版本兼容与错误处理；优先使用标准 API。
7. **插件日志与密钥。** 插件运行在 server 内，能读到 provider 凭据解析结果；节点侧插件不得把密钥写入日志、事件或控制面。
8. **TUI/GUI 插件与 lework Web 控制面无关。** 除非未来做桌面壳，否则只需关注 server 部分。
9. **Effect 插件增加运行时约束。** 如果节点插件生态要统一，优先 Promise API，避免 effect 版本冲突。
