# 02 安装与命令行

> 来源：`index.md`、`cli.md`、`cli/commands`、`cli/web`、`cli/acp`、`troubleshooting`、`network`、`migrate-v1`。
> 适用：OpenCode 2.x。所有命令都支持 `--help`。

## 1. 安装

V1 与 V2 默认不再并存，二者都使用 `opencode` 命令。安装 V2 前先移除包管理器安装的 V1；V2 的 curl 安装脚本会替换 V1 二进制。

| 方式 | 命令 |
|---|---|
| curl | `curl -fsSL https://opencode.ai/v2/install \| bash` |
| Homebrew | `brew install anomalyco/tap/opencode-v2` |
| npm | `npm install -g @opencode/cli` |
| Bun | `bun install -g --trust @opencode/cli` |
| pnpm | `pnpm add -g --allow-build=@opencode/cli @opencode/cli` |
| Yarn | `yarn global add @opencode/cli` |
| Vite+ | `vp install -g @opencode/cli` |
| AUR | `paru -S opencode-beta` |
| mise | `mise use -g opencode`（需 mise ≥ 2026.10.9） |

说明：

- npm 包通过 postinstall 选择平台原生二进制；Bun/pnpm 需要显式允许构建脚本。
- **不支持 Windows 包管理器**；Windows 用下载的独立二进制。
- 官方提供 macOS/Windows/Linux（glibc/musl，x64/arm64/baseline）独立包。
- Docker 镜像使用版本 tag，如 `ghcr.io/anomalyco/opencode:2.0.0`。

升级与卸载：

```bash
opencode upgrade                     # 升级到最新
opencode upgrade 2.0.21 --method bun # 指定版本与包管理器（别名 update）
opencode uninstall --dry-run         # 预览
opencode uninstall                   # 停止后台 service、清缓存、卸载
```

`uninstall` **不会**删除会话数据、配置与 state。

## 2. 启动与全局行为

```bash
opencode                    # 在当前目录打开全屏 TUI
opencode ~/code/my-project  # 指定项目目录
opencode --standalone       # 使用私有 server（不连共享后台服务）
opencode --server http://127.0.0.1:4096
opencode --print-logs ...   # 日志写 stderr（排查 ACP/协议问题时常用）
```

- 默认自动发现或启动**一个共享后台 server**（每用户一个），所有本地客户端连它。
- `service set disabled true` 可让 CLI 命令默认改用私有 server（仍可用 `--server` 指定；`pair` 会不可用）。
- `--standalone` 与 `serve` 使用**自己进程的环境变量**，`service set env` 不作用于它们。

## 3. 命令总览

### 3.1 `run` — 非交互执行

```bash
opencode run "Explain this repository"
opencode run --model anthropic/claude-sonnet-5-5 "Refactor parseToken"
opencode run --continue "Now handle the expired case"
opencode run --session ses_4f2a1c "Check edge cases"
opencode run --agent build "Fix the failing test"
opencode run --file src/server.ts --file src/client.ts "Review these"
opencode run --format json "List the TODO comments"   # NDJSON
opencode run --auto "Fix the failing test"            # 自动允许未被显式 deny 的权限
opencode run --archived "Review this diff"            # 会话归档创建，不出现在列表/inbox
opencode run --standalone --model ... "..."           # CI：私有 server + 环境里的 key
```

CI 示例（官方）：

```yaml
- run: npm install --global @opencode/cli
- run: opencode run --standalone --model anthropic/claude-sonnet-5-5 "Review this repository..."
  env:
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
```

要点：

- `--archived` 的会话仍存在，`opencode session list` 能看到、可按 ID 打开。
- `--auto` 只是把“未显式 deny 的 ask”自动放行；显式 `deny` 仍然生效。
- 结果直接写 stdout；`--format json` 为逐行 JSON，适合脚本消费。

### 3.2 `mini` — 极简交互

```bash
opencode mini
opencode mini --continue
opencode mini --model anthropic/claude-sonnet-5-5 --prompt "Summarize this repository"
opencode mini --session ses_4f2a1c
```

### 3.3 `session` — 会话管理

```bash
opencode session list
opencode session list --max-count 20 --format json
opencode session delete ses_9c1b08          # 连同子会话递归删除
opencode session export ses_4f2a1c
opencode session export ses_4f2a1c --sanitize
opencode session import session.json
opencode session import session.json --directory ~/code/project
```

### 3.4 `auth` — Provider 凭据

```bash
opencode auth list
opencode auth list --format json
opencode auth login anthropic
opencode auth login anthropic --method key
opencode auth logout anthropic work
opencode auth switch anthropic work
opencode auth export anthropic > credentials.json   # 含密钥
opencode auth import credentials.json
```

### 3.5 `models`

```bash
opencode models
```

列出当前可用模型（受 Provider 可用性、`disabled`、`policies` 影响）。

### 3.6 `mcp` — MCP 服务器

```bash
opencode mcp list
opencode mcp add context7 --url https://mcp.context7.com/mcp
opencode mcp add everything --global -- npx -y @modelcontextprotocol/server-everything
opencode mcp add everything --env LOG_LEVEL=debug -- npx -y @modelcontextprotocol/server-everything
opencode mcp add context7 --url https://mcp.context7.com/mcp --header CONTEXT7_API_KEY=secret
opencode mcp auth sentry
opencode mcp logout sentry
```

`add` 默认写入项目配置，`--global` 写入全局配置；详见 08。

### 3.7 `plugin`

```bash
opencode plugin list
opencode plugin list --builtin
opencode plugin add @example/opencode-tui
opencode plugin check
opencode plugin update [package]
opencode plugin remove @example/opencode-tui
```

`add` 会把插件写入全局配置。支持 npm 版本/标签/范围与 Git 包（`github:`、`git+ssh://`、`::path:` 子目录）；不接受 tarball 与 npm alias。

### 3.8 `stats`

```bash
opencode stats
opencode stats --days 7
opencode stats --models
opencode stats --cost
opencode stats --json
opencode stats --project .
```

### 3.9 `serve` — 前台 API/Web server

```bash
opencode serve
opencode serve --hostname 0.0.0.0 --port 4096
opencode serve --cors https://app.example.com
```

- 与 TUI 使用同一个 server 实现，但由当前进程持有。
- 适合容器、systemd、远程主机、固定端口/CORS。
- 客户端连接：`opencode --server http://host:4096`。
- `--cors` 可重复；CORS 不改变监听地址、不绕过认证。

### 3.10 `pair` — 一次性登录链接

```bash
opencode pair
opencode pair --url https://dev.example.com
opencode pair --remote          # 通过 OpenTunnel 暴露到公网（首次需确认）
opencode pair --remote --yes    # 无交互确认（脚本）
```

- 链接 5 分钟过期、只能使用一次；换取 30 天会话 Cookie。
- `--remote` 会把 server 暴露到互联网（端到端加密 + 密码），首次会提示风险。
- 关闭远程访问：`opencode service set remote false`。

### 3.11 `service` — 后台 server 生命周期与配置

```bash
opencode service start
opencode service restart
opencode service status
opencode service stop
opencode service get hostname
opencode service set hostname 0.0.0.0
opencode service set port 49374
opencode service set password "a-long-secret"
opencode service set cors https://app.example.com,https://other.example.com
opencode service set env OPENCODE_LOG_LEVEL DEBUG
opencode service set disabled true     # 默认不再使用共享服务
opencode service unset hostname
opencode service unset env HTTPS_PROXY
```

可配置键（官方文档明确出现）：`hostname`、`port`、`password`、`cors`、`env`、`remote`、`disabled`。

规则：

- **修改任意 service 配置会停止后台 server**；需要 `opencode service start` 重新启动。
- `service get env` 会显示环境变量原值（可能含代理密码），不要外泄。
- service 配置存于 `~/.config/opencode/service.json`，注册信息在 `~/.local/state/opencode/service.json`。

### 3.12 `reload` — 热重载配置

```bash
opencode reload
```

不重启 server，重新加载配置；运行中的会话在下一个 step 边界使用新服务。

### 3.13 `api` — 直接调用 server

```bash
opencode api GET /api/session
opencode api session.list --param limit=10
opencode api session.create --data '{"title": "New session"}'
opencode api GET /api/session -H "accept: application/json"
```

- 自动发现并认证共享 service（必要时会启动它）。
- 位置参数可以是 `METHOD PATH`，也可以是 OpenAPI `operationId`。
- `--param k=v` 追加查询参数，`--data/-d` 传 JSON body，`--header/-H` 加请求头。

### 3.14 `acp` — Agent Client Protocol

```bash
opencode acp
opencode --print-logs acp
opencode acp --login   # 由 ACP 客户端在终端中启动登录流程
```

- 通过 stdin/stdout 交换 newline-delimited JSON-RPC（ACP v1）。
- 启动**私有** server；不连共享服务、不开网络端口；客户端关闭 stdin 即退出。
- 直接运行看起来“卡住”是正常的（在等 stdin 输入）。
- 协议细节见 13。

### 3.15 `debug`

```bash
opencode debug agents
opencode debug config       # 列出配置来源
opencode debug heap-dump    # 对运行中的后台 server 抓堆快照并打印路径
opencode debug heap-dump --directory ./snapshots
opencode debug paths
opencode debug paths db
```

`debug paths` 的选择器：`db`、`home`、`data`、`config`、`cache`、`state`、`tmp`、`bin`、`log`、`repos`。它不会启动 server，也不会打开数据库。

### 3.16 `upgrade` / `uninstall`

见第 1 节。`upgrade` 别名 `update`。

## 4. 环境变量

| 变量 | 作用 |
|---|---|
| `OPENCODE_PASSWORD` | server 密码（Basic Auth 密码）；也给 `opencode --server` 使用 |
| `OPENCODE_SERVER_PASSWORD` | V1 兼容密码变量 |
| `OPENCODE_LOG_LEVEL` | 日志级别（V2 不再用配置里的 `logLevel`） |
| `OPENCODE_DB` | 覆盖数据库路径；相对路径相对 data 目录 |
| `OPENCODE_DISABLE_PROJECT_CONFIG` | `1` 时跳过项目配置与项目 `AGENTS.md` 发现（全局配置仍加载） |
| `OPENCODE_DISABLE_FREE_MODELS` | `1`/`true` 隐藏免费 `opencode`/`opencode-go` 模型 |
| `OPENCODE_CLI_CONFIG_CONTENT` | 内联 CLI 设置 JSON，覆盖 `cli.json` |
| `OPENCODE_API_KEY` | 登录前恢复 `opencode` Provider 的付费模型 |
| `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` | 出站代理；**必须**把回环地址放进 `NO_PROXY` |
| `NODE_EXTRA_CA_CERTS` | 额外信任的私有 CA（PEM） |
| `AWS_*`、`GOOGLE_*`、`AZURE_*` | 各云 Provider 的凭据/区域/项目 |

注意：V2 **不再支持** `OPENCODE_SERVER_USERNAME`，Basic Auth 用户名永远是 `opencode`。

## 5. 后台服务与代理

CLI 与后台 server 之间是本地 HTTP 连接。如果 shell 配了代理，必须排除回环：

```bash
export HTTP_PROXY=http://proxy.example.com:8080
export HTTPS_PROXY=http://proxy.example.com:8080
export NO_PROXY=localhost,127.0.0.1,::1
opencode
```

后台 server 的代理要持久化：

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

代理认证把凭据写进 URL（对 `@`、`:`、`/` 做百分号编码）：

```bash
opencode service set env HTTPS_PROXY 'http://user:p%40ssword@proxy.example.com:8080'
```

验证：

```bash
opencode api get /api/info
```

## 6. 控制面关注点

- **不要依赖 `opencode` CLI 的交互输出做集成**；用 `--server` + HTTP API，或 `opencode api` 仅做手工排障。
- 节点 agent 启动 server 时建议固定 `--hostname 127.0.0.1 --port <分配端口>` 并设置 `OPENCODE_PASSWORD`，避免与用户自己的共享 service 冲突。
- 若复用共享 service，注意 `service set` 会**停掉服务**；控制面不应在用户使用期间改 service 配置。
- CI/无人值守场景用 `--standalone` + 环境变量密钥；不要依赖 `--auto` 绕过用户的显式 `deny`。
- `opencode acp` 的私有 server 不暴露端口，适合编辑器集成；控制面若要走 ACP，应作为 ACP 客户端启动子进程。
