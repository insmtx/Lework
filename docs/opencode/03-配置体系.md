# 03 配置体系

> 来源：官方 `config`、`migrate-v1`、`policies#precedence`、`cli/config`。
> 配置 schema 的权威地址：`https://opencode.ai/config.json`。本文只列官方文档明确出现的字段；完整嵌套以 schema 为准。

## 1. 文件格式与位置

支持 **JSON** 与 **JSONC**（注释、尾逗号）。推荐加 `$schema` 获得编辑期校验：

```jsonc title="opencode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-5-5",
}
```

### 1.1 系统级（机器范围）

| 平台 | 目录 |
|---|---|
| macOS | `/Library/Application Support/opencode` |
| Linux | `/etc/opencode` |
| Windows | `%ProgramData%\opencode` |

系统目录除 `opencode.json(c)` 外，还加载 `agents/`、`commands/`、`skills/`、`plugins/`，对机器上所有用户生效：

```text
/etc/opencode/
├── opencode.json
├── agents/review.md
├── commands/release.md
└── skills/deploy/SKILL.md
```

macOS 还读取 MDM 下发的 managed preferences（域 `ai.opencode.managed`）：

```text
/Library/Managed Preferences/<user>/ai.opencode.managed.plist
/Library/Managed Preferences/ai.opencode.managed.plist
```

**托管配置优先级最高**，用户与项目无法覆盖。但“配置”本身不能阻止用户新增 Provider/MCP/Agent/插件，必须用 `policies` 做强制限制。

### 1.2 用户级与项目级

```text
~/.config/opencode/opencode.json(c)      # 全局
<project>/opencode.json(c)               # 项目（直接形式）
<project>/.opencode/opencode.json(c)     # 项目（.opencode 形式）
```

## 2. 合并顺序（最易踩坑）

OpenCode 从当前目录向上搜索到文件系统根，先合并**直接** `opencode.json(c)`（从最远到最近），再合并 `.opencode/` 内的配置（同样从最远到最近）。

**后果：任何 `.opencode/opencode.json(c)` 都覆盖任何直接配置**，即使直接配置在更近的目录。官方建议一个目录树内只使用一种形式。

示例：从 `/home/user/projects/acme/packages/web` 启动，按优先级从低到高：

```text
1. ~/.config/opencode/opencode.json
2. /home/user/projects/acme/opencode.json
3. /home/user/projects/acme/packages/web/opencode.json
4. /etc/opencode/opencode.json
```

- 不冲突的设置全部保留；冲突时后者覆盖前者。
- **`policies` 的顺序相反**：越宽泛（global/system）越晚求值，因而覆盖更窄的（项目）策略。详见 09。
- `agents`、`skills`、`plugins` 等集合类字段通常**合并**而非整体替换（各文档分别说明）。
- V1 与 V2 字段可共存；同一 canonical 值冲突时，合法的 V2 值优先。

## 3. 顶层字段总览

| 字段 | 类型 | 作用 | 默认 |
|---|---|---|---|
| `shell` | string | 终端与 `shell` 工具使用的 shell | 平台默认 |
| `model` | string \| object | 默认模型 `provider/model`（根级不保留 `#variant`） | 目录默认模型 |
| `default_agent` | string | 会话未指定时的主 Agent | `build` |
| `update` | `disable`\|`notify`\|`auto` | 更新检查/安装（仅全局生效） | `notify` |
| `username` | string | 用户名（接受但不展示） | — |
| `permissions` | 规则数组 | 每 Agent 的 `allow/ask/deny` 有序规则 | 见 09 |
| `policies` | 语句数组 | 二元强制约束，从不提示 | 全允许 |
| `agents` | map | 覆盖/新增 Agent | 内置 |
| `snapshots` | boolean | 是否抓取文件快照（undo 用） | `true` |
| `watcher` | object | 忽略不触发文件事件的路径 | — |
| `formatter` | bool \| object | 写文件后格式化 | 关闭 |
| `media` | object | 图片缩放/拒绝策略 | 见 11 |
| `tool_output` | object | 工具结果保留上限 | 2000 行 / 50 KiB |
| `websearch` | object \| false | 搜索 Provider 选择；`false` 关闭工具 | 首次询问 |
| `mcp` | object | MCP 服务器与全局超时 | — |
| `compaction` | object | 自动压缩与保留量 | `auto:true`、15k、15% |
| `warming` | bool \| object | 缓存保温请求 | 关闭 |
| `skills` | string[] | 额外技能目录/HTTP catalog | 自动发现 |
| `commands` | map | 斜杠命令 | 文件发现 |
| `instructions` | string[] | 额外指令文件/glob/URL | `AGENTS.md` |
| `references` | map | 命名外部目录/Git 引用 | — |
| `worktree` | object | 新 worktree 的父目录 | data 目录 |
| `plugins` | array | 插件包/目录 | `.opencode/plugins` 自动发现 |
| `providers` | map | Provider/模型/请求选项 | models.dev 目录 |
| `experimental` | object | 实验项 | 见下 |

## 4. 字段详解

### 4.1 `shell`

```jsonc
{ "shell": "/bin/zsh" }
```

影响终端与 `shell` 工具。Windows 上另有 PowerShell 支持。

### 4.2 `model` 与 `default_agent`

```jsonc
{
  "model": "anthropic/claude-sonnet-5-5",
  "default_agent": "build"
}
```

- `model` 是 `provider/model`；**根级默认值不保留 `#variant`**，变体在 agent/command/session/run 上选。
- 配置的模型不可用时会回退到“最新可用且受支持”的模型。
- 会话已选模型优先于配置默认值；切换会话模型不会改配置文件。
- `default_agent` 必须存在、可见且支持 primary；否则用 `build`，再退到第一个可见的主 Agent。修改不会替换已存在会话的 Agent。

### 4.3 `update` 与 `username`

```jsonc
{
  "update": "notify",
  "username": "alice"
}
```

- `update`：`disable` 跳过检查，`notify` 提示后安装，`auto` 自动安装；默认 `notify`。**项目级值被忽略**。自动安装不会重启正在运行的 server。
- `username`：接受但不显示在会话中。

### 4.4 `permissions`

```jsonc
{
  "permissions": [
    { "action": "shell", "resource": "git push *", "effect": "ask" }
  ]
}
```

有序规则，最后匹配生效。完整 action/默认值/审批与目录规则见 09。

### 4.5 `policies`

```jsonc
{
  "policies": [
    { "action": "provider.use", "resource": "*", "effect": "deny" },
    { "action": "provider.use", "resource": "anthropic", "effect": "allow" },
    { "action": "tool.use", "resource": "shell:git push *", "effect": "deny" }
  ]
}
```

二元 allow/deny、不提示、只收紧。优先级高于 `permissions` 与已保存审批。见 09。

### 4.6 `agents`

```jsonc
{
  "agents": {
    "reviewer": {
      "description": "Review changes without editing files",
      "mode": "subagent",
      "system": "Focus on correctness, security, and missing tests.",
      "permissions": [{ "action": "edit", "resource": "*", "effect": "deny" }]
    }
  }
}
```

详见 04。内置 Agent 用同 ID 覆盖；`disabled: true` 可移除。

### 4.7 `snapshots`

```jsonc
{ "snapshots": false }
```

关闭后不再抓取新快照；已存快照不删除；会话回滚仍可用但无法恢复文件。快照依赖 Git，只覆盖会话活动目录。见 11。

### 4.8 `watcher`

```jsonc
{
  "watcher": {
    "ignore": ["dist/**", "coverage/**"]
  }
}
```

忽略的路径不触发文件系统更新事件（`filesystem.changed`）。

### 4.9 `formatter`

```jsonc
{ "formatter": true }
```

在 `write`/`edit`/`patch` 改动文件后运行格式化器。`true` 启用全部内建（仅在可执行文件/项目依赖可用时运行）；对象形式可覆盖或新增；`false` 关闭。详见 11。

### 4.10 `media`

```jsonc
{
  "media": {
    "image": {
      "auto_resize": true,
      "max_width": 2000,
      "max_height": 2000,
      "max_base64_bytes": 5242880
    }
  }
}
```

作用于 prompt 附件与 `read` 工具读到的图片。`auto_resize:false` 时超限直接失败。这些是**处理限制**，不是上传/安全边界。

### 4.11 `tool_output`

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200
  }
}
```

工具结果保留的最大行数与字节数；超出部分被截断，完整内容可能保存在 managed storage（由具体工具实现）。

### 4.12 `websearch`

```jsonc
{
  "websearch": {
    "provider": "random"
  }
}
```

可选 `exa`、`firecrawl`、`parallel`、`tavily`、`tinyfish`、`opencode`（Console）或 `random`。`false` 完全移除工具。见 07/09。

### 4.13 `mcp`

```jsonc
{
  "mcp": {
    "timeout": { "startup": 45000, "catalog": 30000, "execution": 600000 },
    "servers": {
      "playwright": {
        "type": "local",
        "command": ["bunx", "@playwright/mcp"]
      }
    }
  }
}
```

- V2 服务器必须放在 `mcp.servers` 下（V1 是直接放在 `mcp` 下）。
- 全局 `mcp.timeout` 只作用于配置文件定义的服务器；服务器自身的 `timeout` 覆盖对应项。
- 详见 08。

### 4.14 `compaction`

```jsonc
{
  "compaction": {
    "auto": true,
    "keep": { "tokens": 15000 },
    "buffer": "15%"
  }
}
```

| 字段 | 默认 | 说明 |
|---|---:|---|
| `auto` | `true` | 接近上下文上限时自动压缩；Provider 报“太长”时恢复一次 |
| `keep.tokens` | `15000` | 摘要旁保留的近期上下文（非负整数） |
| `buffer` | `"15%"`（至少 16k） | 上下文窗口保留空闲比例，达到“总量-buffer”即触发；也接受 token 数 |

`buffer` 取值 `"1%"`–`"99%"`（可小数）；token 数 ≥ 窗口时被忽略并回退默认。

Provider 原生压缩：

```jsonc
{
  "providers": {
    "openai": {
      "settings": { "compaction": { "type": "native" } },
      "models": {
        "gpt-6.1-sol": { "settings": { "compaction": { "type": "summary" } } }
      }
    }
  }
}
```

模型设置覆盖 Provider 设置；`native` 用 Provider 检查点，`summary` 用本地摘要。详见 11。

### 4.15 `warming`

```jsonc
{
  "warming": {
    "prompt": "Do not perform any work. Reply with exactly: OK",
    "interval": "auto",
    "duration": "30 minutes"
  }
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `prompt` | 保活指令 | 每次保温请求临时追加的用户消息 |
| `interval` | `"auto"` | 空闲多久发一次；auto = `cache.ttl` 的 90%，无 ttl 则 4 分钟 |
| `duration` | `"30 minutes"` | 从最近一次非保温请求起的保温窗口 |

`warming: true` 等价于全部默认。Provider/model 的 `settings.cache.warming` 可覆盖（不含 `prompt`）；模型覆盖 Provider。要求 `interval < duration` 且均为正有限值。详见 11。

### 4.16 `skills`

```jsonc
{
  "skills": ["./team-skills", "https://example.com/.well-known/skills/"]
}
```

支持相对/`~/`/绝对路径与 HTTP catalog。相对路径**相对当前工作目录**，不是配置文件目录。所有配置文件的数组**合并**。详见 10。

### 4.17 `commands`

```jsonc
{
  "commands": {
    "review": {
      "description": "Review the current changes",
      "template": "Review the current diff for correctness and missing tests."
    }
  }
}
```

JSON 形式必须有 `template`；Markdown 形式用正文作模板。详见 10。

### 4.18 `instructions`

```jsonc
{
  "instructions": ["CONTRIBUTING.md", "docs/guidelines/*.md"]
}
```

支持相对/`~/`/绝对路径、glob 与 HTTP(S) URL（5 秒超时）。配置项在 `AGENTS.md` 之后按列出顺序加载。详见 10。

### 4.19 `references`

```jsonc
{
  "references": {
    "docs": {
      "path": "../product-docs",
      "description": "Product behavior and terminology"
    },
    "effect": {
      "repository": "Effect-TS/effect",
      "branch": "main"
    }
  }
}
```

本地路径或远程 Git；`hidden` 只影响交互选择器。详见 11。

### 4.20 `worktree`

```jsonc
{
  "worktree": {
    "directory": "../worktrees"
  }
}
```

- 相对路径相对项目的 **canonical checkout**（不是当前子目录）；绝对路径原样使用；`~/` 相对 home。
- 未设置时使用 server data 目录下 `worktree/<项目 ID 前 6 位>`。
- 改变不会移动已有 worktree；Git 是内建默认策略，注册策略的插件可在其运行时成为默认。

### 4.21 `plugins`

```jsonc
{
  "plugins": [
    "opencode-example-plugin",
    "opencode-example-plugin@1.2.0",
    "@acme/opencode-plugin",
    "./plugins/local",
    {
      "package": "@acme/opencode-plugin",
      "options": { "agent": "reviewer", "strict": true }
    }
  ]
}
```

- 相对路径相对**包含该条目的配置文件**。
- 本地配置路径必须是目录（单文件会被跳过）。
- 各配置文件数组合并（低优先级在前），不是替换。
- 支持 `-` 前缀禁用、`*` 全匹配、`.*` 前缀匹配；内置 `opencode.config.policy` 与 `opencode.provider.opencode` 不允许被禁用。详见 14。

### 4.22 `providers`

```jsonc
{
  "providers": {
    "openai": {
      "models": {
        "gpt-6.1-sol-custom": {
          "modelID": "gpt-6.1-sol",
          "name": "GPT-6.1 Sol Custom",
          "limit": { "context": 200000, "output": 32000 }
        }
      }
    }
  }
}
```

Provider 级字段：`name`、`env`、`package`、`canonical`、`compatibility`、`settings`、`headers`、`body`、`models`。
`settings.transport: "websocket"` 启用该 Provider 的会话 WebSocket。详见 05。

### 4.23 `experimental`

所有实验项位于 `experimental` 下，**可能随时变更/移除**：

```jsonc
{
  "experimental": {
    "todo": true,
    "subagent_depth": 2,
    "background_compaction": true,
    "image_generate": { "model": "openai/gpt-image-2" },
    "location_idle_timeout": "4 hours"
  }
}
```

| 键 | 作用 | 默认 |
|---|---|---|
| `todo` | 给 Agent `todowrite` 工具 | `false` |
| `subagent_depth` | 子 Agent 可再开子 Agent 的深度 | `1` |
| `background_compaction` | 后台预写压缩摘要，避免卡顿 | `false` |
| `image_generate.model` | `experimental_image_generate` 默认模型 | — |
| `location_idle_timeout` | location 空闲卸载时间；`false` 永不卸载 | `"60 minutes"` |
| `policies` | **已弃用**，合并进顶层 `policies` | — |

## 5. 变量替换

在 JSON 字符串中使用：

| 语法 | 含义 | 缺失时 |
|---|---|---|
| `{env:NAME}` | 环境变量 | 替换为空字符串 |
| `{file:path}` | 文件内容 | 替换为空字符串 |

路径可以是相对配置文件目录、绝对路径或 `~/`。

```jsonc
{
  "providers": {
    "anthropic": {
      "settings": { "apiKey": "{env:ANTHROPIC_API_KEY}" }
    }
  }
}
```

用途：密钥不入库、跨文件复用片段。注意：变量替换发生在配置加载时，修改环境变量需要 reload/重启。

## 6. 配置生效与热重载

- 普通配置修改通常自动重载；`opencode reload` 可显式重载而不重启 server。
- 运行中的会话在下一个 **step 边界**使用新配置；进行中的模型请求保留启动时的设置。
- 修改 service 配置（`service set`）会停止后台 server，需要重新启动。
- `OPENCODE_DISABLE_PROJECT_CONFIG=1` 时跳过项目配置与项目 `AGENTS.md`，全局配置仍生效。

## 7. 控制面关注点

1. **节点级基线配置**建议放系统目录或由 agentd 生成临时全局配置，避免污染用户 `~/.config/opencode`。
2. 控制面下发策略用 `policies`（强制），不要用 `permissions` 假装强制——用户可以覆盖自己的 `permissions`。
3. 每个 session 可以带**会话级权限规则**（`permissions` 字段），创建/更新 session 时传入，优先级在 Agent 规则之后、`policies` 之前。
4. 多项目节点要保证 `location.directory` 明确，否则配置合并结果不可预期。
5. 修改 `plugins`/`providers` 后要 `reload` 或重启；不要假设下一次请求自动生效（尤其进行中的请求）。
6. `$schema` 只用于编辑期校验，运行时不要依赖它。
