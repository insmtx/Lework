# 16 故障排查与运维

> 来源：官方 `troubleshooting`、`cli`、`cli/commands`、`service`、`cli/web`，以及 lework `agent.yaml`、`serve`/`agent` 启动参数。
> 排障顺序遵循“先分层，再看日志，最后动数据”。**不要**在未备份时删除数据库、service 文件或 agent 配置。

## 1. 先判断故障在哪一层

OpenCode 是 client-server 架构；lework 又在此之上加了一层节点代理。出现问题时先定位层级，避免在错误的位置改配置。

```text
浏览器
  │ ① 同源 HTTP / SSE / WebSocket
  ▼
lework serve ── ② WSS ── lework agent ── ③ 回环 HTTP/SSE ── opencode serve
```

| 症状 | 优先检查 | 常见原因 |
|---|---|---|
| 页面打不开 | ① 控制面进程/端口 | `lework serve` 未启动、端口被占、绑定了错误地址 |
| 页面能开但节点离线 | ② WSS | 控制面地址错、注册令牌错、TLS/代理、心跳超时 |
| 节点在线但请求 502/504 | ③ OpenCode | OpenCode 未启动、密码错、端口冲突、请求超时 |
| 会话能建但无输出 | ③ 事件 | OpenCode SSE 断开、权限等待、模型/Provider 错误 |
| 终端打不开 | ②/③ PTY | 目录越界、OpenCode 实验性终端不可用、WebSocket 被代理拦截 |
| 升级后行为变化 | 版本/配置 | V2 破坏性变更、插件 API、字段迁移 |

## 2. 控制面（lework serve）

### 2.1 健康检查

```bash
curl -fsS http://127.0.0.1:8787/healthz
# {"status":"ok"}
```

检查：

- 进程是否在监听：`ss -lntp | grep 8787`
- 启动参数：`--listen`、`--db`、`--enrollment-token`
- 数据库文件是否可写：默认 `~/.config/Lework/controlplane.db`
- 是否误绑到 `0.0.0.0`：控制面浏览器 API 没有独立登录态，默认只应绑回环。

### 2.2 节点列表与在线状态

```bash
curl -fsS http://127.0.0.1:8787/api/nodes
```

字段含义：

| 字段 | 说明 |
|---|---|
| `connected` | 取实时注册表；`false` 表示当前没有可用 WSS |
| `last_seen` | 来自 SQLite，心跳会更新 |
| `capabilities` | 节点 hello 声明的方法；缺某个能力时前端应隐藏对应操作 |
| `agent_version` | 节点版本，用于判断是否需要升级 |

`connected=false` 但 `last_seen` 很近，通常是刚断开或心跳窗口内；`last_seen` 很旧则是长时间离线。

### 2.3 常见错误码

| HTTP | `code` | 处理 |
|---|---|---|
| 404 | `not_found` | 节点从未注册；检查 `node_name` 与数据库 |
| 409 | `node_offline` | 节点未连接；恢复 agent 或等待重连 |
| 504 | `agent_timeout` | 节点/OpenCode 卡住；查 agent 与 OpenCode 日志 |
| 502 | `agent_error` | OpenCode 返回业务错误；看 message 与 OpenCode 日志 |
| 400 | `invalid_request` | 目录非绝对、缺幂等键、缺参数 |

## 3. 节点（lework agent）

### 3.1 启动与配置

```bash
lework agent --config /etc/lework/agent.yaml
lework agent version
```

`agent.yaml` 必填项：

| 字段 | 要求 |
|---|---|
| `control_plane_url` | `ws://` 或 `wss://`，必须含 host |
| `enrollment_token` | 与控制面一致；只出现在握手头 |
| `node_name` | 非空；控制面按名称复用节点 ID |
| `workspace_roots` | 至少一个绝对路径 |
| `opencode.port` | 1–65535；默认 4096 |
| `opencode.binary` | 默认 `opencode` |

启动时 agent 会先确保 OpenCode 可用，再连接控制面。日志中应出现：

```text
lework-agent: opencode service ready
lework-agent: starting node "..."
lework-agent: connected to control plane
```

如果只看到 `start opencode service` 警告，说明 OpenCode 没起来；此时即使 WSS 连上，会话请求也会失败。

### 3.2 WSS 连不上

按顺序检查：

1. **地址与协议**：`ws://` 对应 `http://`，`wss://` 对应 `https://`；路径必须是 `/api/agent/connect`。
2. **注册令牌**：与控制面 `--enrollment-token` 完全一致；不要带多余空格。
3. **反向代理**：必须支持 WebSocket Upgrade，并放大读超时；心跳默认 10 秒，代理空闲超时应大于 35 秒。
4. **TLS**：自签证书时配置 `tls_fingerprint`；不要用 `curl -k` 式的“先跑起来再说”。
5. **Origin**：agent 不应发送 `Origin`；控制面会拒绝带 `Origin` 的握手，防止网页借回环注册节点。
6. **心跳窗口**：控制面默认 35 秒内必须收到帧；节点侧若被暂停（休眠、长 GC、调试器）会被判离线。

### 3.3 节点在线但 OpenCode 不可用

```bash
# 在节点机器上，用 agent 配置的端口与密码
curl -u opencode:"$OPENCODE_PASSWORD" http://127.0.0.1:4096/api/info
```

| 结果 | 含义 | 处理 |
|---|---|---|
| 200 | 健康 | 问题在 agent ↔ 控制面或前端 |
| 401 | 密码不匹配 | 检查 `opencode.env.OPENCODE_PASSWORD` 与进程环境 |
| 503 | 启动中/停止中 | 等待；持续 503 看 OpenCode 日志 |
| 500 | 启动失败 | 看 OpenCode 日志与端口占用 |
| 连接拒绝 | 未启动/端口错 | 检查 binary、port、进程 |

端口冲突：

```bash
ss -lntp | grep 4096
```

如果端口已被用户自己的 OpenCode 占用，supervisor 会尝试附着；若协议/密码不兼容，会表现为 401 或健康检查失败。解决方式是给 agent 分配独立端口，而不是杀掉用户的进程。

### 3.4 路径与权限

- `workspace_roots` 非空时，`session.create`、`file.*`、`session.diff`、`pty.create` 都要求目录在根内。
- 符号链接会先 `EvalSymlinks` 再比较；链接指向根外会被拒绝。
- 文件读取单次 512 KiB；大文件返回 `truncated=true`。
- OpenCode 侧还有 `external_directory` 权限；如果 lework 放行但 OpenCode 拒绝，检查项目的 `permissions`。

### 3.5 终端问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `terminal is unavailable` | OpenCode 实验性终端不可用 / PTY 已退出 | 检查 OpenCode 版本与 `/api/info.capabilities.persistentPty` |
| 打开后立即 `exit` | shell 命令退出 / 目录不可用 | 检查 `command`、`args`、目录 |
| 输入无反应 | WebSocket 被代理缓冲 / 帧过大 | 关闭代理缓冲；输入单帧 ≤64 KiB |
| 断线后终端消失 | 浏览器断开触发关闭 | 重新创建；不要在多个标签共享同一 PTY |
| 节点重连后旧终端不可用 | agent 连接结束会关闭所有 PTY | 重新创建终端 |

## 4. OpenCode 服务生命周期

以下命令用于手工排障，不应成为控制面的常规调用路径。

```bash
opencode service status
opencode api get /api/info
opencode service restart
opencode service stop
opencode service start
```

注意：

- OpenCode 通常会自动发现或启动共享后台服务；`service` 命令只在诊断时使用。
- `opencode api` 在找不到兼容的健康服务时**可能启动**后台服务。
- `service set/unset` 会**停止**后台服务，下次启动才生效。用户正在使用时不要改。
- 控制面节点 agent 自己管理 `opencode serve`；不要同时用 `opencode service` 抢同一端口/数据库。

## 5. 认证、CORS 与代理

### 5.1 认证

- 用户名固定 `opencode`。
- 密码来自 `OPENCODE_PASSWORD`（兼容 `OPENCODE_SERVER_PASSWORD`）。
- 未设置时 server 生成密码并在 `opencode serve` 启动时打印。
- 修改密码会让所有已登录会话失效。
- `OPENCODE_SERVER_USERNAME` 在 V2 不再支持。

### 5.2 CORS

浏览器客户端跨源访问时需要显式允许：

```bash
opencode service set cors http://192.168.1.10:3001
opencode service get cors
opencode service unset cors
```

- 必须是精确的 HTTP/HTTPS origin，可带端口，不带 path 或末尾斜杠。
- 多个 origin 用逗号分隔，作为**一个参数**传入。
- 前台 server 用重复的 `--cors`：

```bash
opencode serve --cors http://192.168.1.10:3001 --cors https://app.example.com
```

- `serve --service` 时，命令行 `--cors` 覆盖持久列表；不传则用持久列表。
- CORS 不改变监听地址，也不能绕过认证。

lework 的浏览器界面与 API 同源，**不需要**给 OpenCode 配 CORS；只有直接访问 OpenCode Web UI 或第三方浏览器客户端时才需要。

### 5.3 代理

本地回环必须绕过代理：

```bash
export NO_PROXY=localhost,127.0.0.1,::1
```

后台服务需要持久化时：

```bash
opencode service set env HTTP_PROXY http://proxy.example.com:8080
opencode service set env HTTPS_PROXY http://proxy.example.com:8080
opencode service set env NO_PROXY localhost,127.0.0.1,::1
opencode service start
```

代理认证把凭据写进 URL，并对 `@`、`:`、`/` 做百分号编码。验证：

```bash
opencode api get /api/info
```

## 6. 日志

### 6.1 OpenCode 日志

安装版默认：

```text
~/.local/share/opencode/log/opencode.log
```

```bash
tail -f ~/.local/share/opencode/log/opencode.log
grep 'role=server' ~/.local/share/opencode/log/opencode.log
grep 'run=8fc3b1d5' ~/.local/share/opencode/log/opencode.log
```

- 每行带 `run` 与 `role`；`role=server` 覆盖 Session、Provider、插件、权限、工具活动。
- 日志级别用 `OPENCODE_LOG_LEVEL` 控制；V1 的 `logLevel` 配置在 V2 被忽略。
- 分享日志前删除 API key、Authorization、prompt、文件内容。

### 6.2 lework 日志

- 控制面与 agent 使用进程日志（stdout/stderr）；由 systemd、Docker 或终端收集。
- 日志中不应出现注册令牌、OpenCode 密码、prompt 文本、文件内容。
- 建议在反向代理层记录请求方法、路径、状态码、耗时，但不要记录请求体。

## 7. 内存与 CPU 诊断

### 7.1 Heap dump

```bash
opencode debug heap-dump
opencode debug heap-dump --directory ./snapshots
```

- 只使用**已经运行**的服务，不会启动/替换/重启。
- `--server <url>` 可抓前台 `opencode serve`；有密码时设置 `OPENCODE_PASSWORD`。
- `--directory` 是 server 机器上的路径。
- 写入期间 server 会暂停，内存可能短时上升。
- 快照可能包含 prompt、文件内容、凭据，**不要公开分享**。

桌面端：命令面板 → **Capture heap snapshots**，输出 `memory.json`、`memory-infra.json`、各进程 `.heapsnapshot`、`manifest.json`。远程 server 不包含在内，需在对应机器上抓。

### 7.2 信号抓取（macOS/Linux）

先从健康接口取 `pid`：

```bash
opencode api get /api/info
kill -SIGPROF <pid>   # 10 秒 CPU profile → log 目录 cpu-<pid>-<ts>.cpuprofile
kill -SIGUSR1 <pid>   # heap snapshot → log 目录 heap-<pid>-<ts>.heapsnapshot
```

等待日志出现 `CPU profile written` / `heap snapshot written`，再用 Chrome DevTools 打开。Windows 不支持信号抓取，改用 `debug heap-dump`。

## 8. 文件、数据库与 state

| 用途 | 路径 |
|---|---|
| 后台服务注册 | `~/.local/state/opencode/service.json` |
| 服务配置 | `~/.config/opencode/service.json` |
| 数据库 | `~/.local/share/opencode/opencode.db`（可用 `OPENCODE_DB` 覆盖） |
| 日志 | `~/.local/share/opencode/log/` |
| 控制面数据库 | `~/.config/Lework/controlplane.db`（由 `--db` 指定） |
| agent 配置 | Linux `/etc/lework/agent.yaml`；macOS `~/Library/Application Support/Lework/agent.yaml`；Windows `%ProgramData%\Lework\agent.yaml` |

查看 OpenCode 路径：

```bash
opencode debug paths
opencode debug paths db
```

**不要**在排障时删除或编辑 service 文件、数据库。需要检查持久数据时先备份，并用只读方式打开。删除数据库会丢失 Session 历史与配置索引。

## 9. 升级、回滚与卸载

### 9.1 升级 OpenCode

```bash
opencode upgrade                  # 最新
opencode upgrade 2.0.21 --method bun
```

- 自动安装不会重启正在运行的 server；需手动重启才能生效。
- 升级前确认插件、API 客户端与 V1 配置的兼容性（见 17 号文档）。
- 升级后先验证 `/api/info` 的 `version` 与 `capabilities`，再恢复控制面流量。

### 9.2 回滚

官方没有“一键降级”命令；可靠做法是：

1. 保留升级前的二进制/包版本与配置副本。
2. 停止服务。
3. 用原包管理器安装指定版本。
4. 启动并验证数据库兼容性。

数据库可能已被新版本迁移；回滚前先备份 `opencode.db`。如果新版本做过不可逆迁移，回滚后可能需要从备份恢复。

### 9.3 卸载

```bash
opencode uninstall --dry-run
opencode uninstall
opencode uninstall --force
```

- 会停止已注册后台服务与持久终端，删除全局 cache。
- **不会**删除 Session 数据、配置与 state。
- 包管理器安装会调用检测到的包管理器；curl 安装会打印手动删除可执行文件的命令。
- 卸载 lework 时，控制面 SQLite 与节点 `agent.yaml` 默认保留；确认不再需要后再手动清理。

## 10. 问题报告清单

提交 issue 前收集：

```bash
opencode --version
opencode service status
opencode debug paths
lework agent version
curl -fsS http://127.0.0.1:8787/healthz
curl -fsS http://127.0.0.1:8787/api/nodes
```

并说明：

- 问题发生在浏览器、控制面、agent 还是 OpenCode；
- 最小复现步骤；
- 是否只在某个 Location/项目出现；
- 相关日志的 `run` 与 `role`；
- 是否使用代理、反向代理、自签证书、共享 service。

**提交前删除**：API key、Authorization、prompt、文件内容、终端输出、heap/CPU profile（除非明确需要且已脱敏）。
