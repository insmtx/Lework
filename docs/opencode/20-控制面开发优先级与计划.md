# 20 控制面开发优先级与计划

> 基准：[19-控制面能力对齐清单.md](19-控制面能力对齐清单.md)（2026-11）+ 代码 `github/main@4ee76395`。
> 本文回答两个问题：**先做什么、为什么先做**；以及**每个模块怎么落地、怎么验收**。
> 约束不变：控制面不复制 Session / Message / Tool 状态机，能力与字段以 OpenCode 为准。

## 1. 排序方法

单个能力按三个维度打分（1–5），再结合“是否阻塞主链路”得到最终优先级：

| 维度 | 含义 | 5 分 | 1 分 |
|---|---|---|---|
| 易用性（Ease） | 缺失时用户能不能正常完成任务 | 主链路直接卡死/无入口 | 只是少一个增强视图 |
| 便捷性（Convenience） | 使用频率与操作步数 | 每次对话都要用 | 少数场景才用 |
| 成熟度（Maturity） | 现有代码完成度，决定了交付成本 | 节点 RPC/后端已具备，只差一层 | 三层全缺 |

**综合优先级**：先看阻塞（易用性），再看频率，最后看交付成本。成熟度高不是“更重要”的理由，只是“更快能拿到”的理由。

### P2 — 增强

fork / revert / 快照 undo、worktree 管理、MCP 连接与资源、PTY handoff、durable 日志对账、一次性 shell、持久化 UI 偏好。

### 不建议做（边界）

会话状态持久化副本、模型推理代理、API key 分发、组织/RBAC、OpenCode TUI/Desktop 界面、插件私有 RPC。理由见 19 号文档 3.14 节。

## 3. 执行计划

### 3.0 公共约定

- 每个模块一个分支，分支均从 `github/main` 切出，完成即推送 `cj` 仓库，不合并 `main`。
- 分支命名：`feat/controlplane-<module>`，文档分支 `docs/controlplane-priority-plan`。
- 每个模块按 TDD：先写失败测试 → 最小实现 → `go test -p 1 ./...` → `gofmt -s -w .` → `go vet ./...`。
- 前端改动补 `cd frontend && pnpm typecheck`。
- 提交信息中文、约定式；一个模块一个提交（必要时两个：后端 + 前端）。

### 模块 A：权限闭环（P0-1/2/3）

**目标**：权限卡在会话切换、断流重连、跨客户端回复后都能收敛到 OpenCode 的真实状态；一键 `always`。

后端：

1. `backend/internal/agentd/opencode/client.go`
   - 新增 `ListPermissions(ctx) ([]PermissionRequest, error)`，调用 `GET /api/permission/request`。
   - 新增 `PermissionRequest` 类型（`id`、`sessionID`、`action`、`resources`、`message`）。
2. `backend/internal/agentd/handler/handler.go`
   - `OpenCodeAPI` 接口加 `ListPermissions`。
   - 新增 `permission.list` 方法：参数 `session_id` 可选；返回前按会话过滤。
   - `permission.reply` 校验 `decision ∈ {once, always, reject}`。
3. `backend/internal/controlplane/api/api.go` + `sessions.go`
   - `GET /api/sessions/{nodeID}/{sessionID}/permissions` → `permission.list`。
   - `POST .../permissions/{permissionID}/reply` 增加 decision 枚举校验（400 `invalid_request`）。
4. `backend/internal/agentd/runner/runner.go`：capabilities 增加 `permission.list`。

前端：

1. `components/permission-card.tsx`：增加 `Always allow`；`busy` 联合类型放宽。
2. `app/page.tsx`：
   - `permission.replied` 读 `data.requestID`；删除 `permission.resolved` 死分支。
   - 选中会话时拉取权限快照并与事件合并（按 `id` 去重）。
   - `resync` 时重新拉快照。
3. `lib/api.ts`：新增 `listPermissions`。

测试：

- `opencode/client_test.go`：`ListPermissions` 解码 + 空结果。
- `handler/handler_test.go`：`permission.list` 会话过滤；非法 decision 拒绝。
- `controlplane/api/api_test.go`：`GET .../permissions` 转发与参数；reply 枚举校验。
- 前端 `pnpm typecheck`。

### 模块 B：OpenCode 生命周期（P0-4/8）

**目标**：浏览器能看到 OpenCode 进程状态，并能 start / restart / stop。

后端：

1. `controlplane/api/api.go` + `nodes.go`
   - `POST /api/nodes/{id}/opencode/start|restart|stop`。
   - 复用能力检查：节点未声明对应 capability 时返回 409 `capability_unavailable`（新增错误码，前端可提示）。
2. 沿用现有 `opencode.status` / start / restart / stop RPC，不改协议。

前端：

1. `lib/api.ts`：`nodeHealth`、`startOpenCode`、`restartOpenCode`、`stopOpenCode`。
2. `components/node-sidebar.tsx`：选中节点显示 OpenCode 状态徽标与操作按钮；操作后轮询一次状态。
3. 错误显示在节点卡片下方，不覆盖节点与会话列表。

测试：

- API 层：三个 POST 的方法名与结果透传；未声明 capability 的 409。
- 前端 `pnpm typecheck`。

### 模块 C：会话管理（P0-5/7）

**目标**：会话可重命名、删除；列表按目录过滤，避免多 location 混淆。

后端：

1. `opencode/client.go`
   - `ListSessions(ctx, directory string)`：有目录时加 `?directory=`。
   - `RenameSession(ctx, sessionID, title string)`：`PATCH /api/session/{id}`，body `{title}`。
   - `DeleteSession(ctx, sessionID)`：`DELETE /api/session/{id}`。
2. `agentd/handler`：`session.rename`、`session.delete`；`session.list` 使用 `Directory`。
3. `controlplane/api`：
   - `PATCH /api/sessions/{nodeID}/{sessionID}` body `{title}`。
   - `DELETE /api/sessions/{nodeID}/{sessionID}`。
4. `runner` capabilities 增加 `session.rename`、`session.delete`。

前端：

1. `lib/api.ts`：`renameSession`、`deleteSession`；`listSessions` 已支持 directory，前端增加目录输入或按当前会话目录过滤。
2. `node-sidebar.tsx`：会话行内重命名（输入框 + Enter/Escape）与删除（二次确认）；删除当前会话后清空选择。
3. `page.tsx`：把重命名/删除接到列表刷新与选择回退。

测试：

- `client_test.go`：directory 查询参数、PATCH/DELETE 方法。
- `handler_test.go`：参数校验（空 title 拒绝）与转发。
- `api_test.go`：PATCH/DELETE 路径与 body。
- 前端 `pnpm typecheck`。

### 模块 D：消息分页（P0-6）

**目标**：首屏只取最近 N 条，支持“加载更早”，并显式告知是否还有历史。

后端：

1. `opencode/client.go`
   - `Messages(ctx, sessionID string, limit int, cursor string) (MessagePage, error)`。
   - 首次请求 `order=desc&limit=N`（服务端默认最新优先），返回后由前端反转成时间顺序；`cursor.next` 指向更早的一页。
   - `MessagePage{ Messages []Message; Next string; Previous string }`。
2. `agentd/handler`：`session.messages` 参数加 `limit`、`cursor`；`limit` 限制 1–200。
3. `controlplane/api`：`GET .../messages?limit=&cursor=`，响应保持 `{data, cursor}` 结构（不再只返回数组），并保留旧字段兼容？
   - 决策：浏览器 API 返回 `{"messages": [...], "next": "..."}`；前端同步改，旧客户端不存在。

前端：

1. `lib/types.ts`：`MessagePage`。
2. `lib/api.ts`：`listMessages(node, session, cursor?, limit?)`。
3. `page.tsx`：保存 `nextCursor`、`loadingOlder`；“加载更早”按钮；首屏与事件刷新都只取最近一页，避免覆盖已加载历史。
4. `session-panel.tsx`：透传加载更早的回调与状态。

测试：

- `client_test.go`：query 编码、cursor 解码、空页。
- `handler_test.go`：limit 边界与默认值。
- `api_test.go`：limit/cursor 透传与响应结构。
- 前端 `pnpm typecheck`。

### 后续阶段（本轮不做）

## 4. 验收清单（每个模块）

```bash
gofmt -l .            # 必须为空
go vet ./...
go test -p 1 ./...    # CI 同款
cd frontend && pnpm typecheck
```

模块完成后检查：

- [ ] 浏览器 API 已在 `api.go` 的 `Register` 中登记。
- [ ] 新 RPC 已加入 handler 分派与 runner capabilities。
- [ ] 前端 `lib/api.ts` 有对应函数，UI 有入口。
- [ ] 事件与快照两条路径都能收敛（权限、会话、消息）。
- [ ] 未把 OpenCode 状态复制到控制面。
- [ ] `git status` 无被忽略文件误入提交。

## 5. 风险与回退

| 风险 | 处理 |
|---|---|
| OpenCode 版本差异导致 cursor 行为不一致 | 分页失败时退回 `limit=200` 单页，并在 UI 显示“历史可能不完整”；不猜测游标语义 |
| 权限快照接口在旧版本缺失（404） | 记录一次警告后降级为事件模式，不阻塞会话主链路 |
| capability 未上报导致按钮误隐藏 | 未上报时按“支持”处理（兼容旧 agent），调用失败再提示升级 agent |
| 前端改动影响移动端单栏布局 | 每次改 `page.tsx` / `node-sidebar.tsx` 后同时检查桌面与窄屏结构 |
