# 07 工具系统

> 来源：官方 `tools`、`permissions`、`mcp-servers`、`config`（`tool_output`、`experimental`）、`build/plugins/server`（工具注册）。
> 工具名、权限 action、事件字段以官方文档与 `openapi.json` 中的 `Session.Message.ToolState.*` / `Tool.Content` 为准。

OpenCode 的工具不是固定列表：内置工具、MCP 工具、插件工具、Code Mode、浏览器控制共同组成“当前模型可用的工具目录”。控制面要做的是**正确呈现工具调用与结果**，并在必要时限制/审批，而不是自己实现工具执行。

## 1. 内置工具总览

| 工具 | 类别 | 作用 | 权限 action | resource |
|---|---|---|---|---|
| `read` | 文件 | 读文件或非递归列目录；支持文本分页与图片/PDF | `read` | 规范化路径 |
| `glob` | 文件 | 按 glob 找文件 | `glob` | 请求的 pattern |
| `grep` | 文件 | 按正则/literal 搜索内容 | `grep` | 正则本身（不是搜索路径） |
| `edit` | 文件 | 精确替换文本 | `edit` | 目标路径 |
| `write` | 文件 | 创建/整体覆盖文本文件 | `edit` | 目标路径 |
| `patch` | 文件 | 多文件 add/update/move/delete | `edit` | 每个受影响路径 |
| `shell` | 命令 | 在宿主 shell 执行命令 | `shell` | scanner 产出的每条命令 |
| `webfetch` | Web | 抓取一个 HTTP(S) URL | `webfetch` | URL |
| `websearch` | Web | 搜索当前集成 | `websearch` | 查询字符串 |
| `experimental_image_generate` | 图片 | 生成/编辑图片 | `experimental_image_generate` | 选中的模型 `provider/model[#variant]` |
| `question` | 交互 | 暂停并询问用户 | `question` | `*` |
| `skill` | 扩展 | 加载技能正文 | `skill` | 技能 ID |
| `subagent` | 自动化 | 启动子会话 | `subagent` | 目标 Agent ID |
| `execute` | Code Mode | 运行 JS 并组合调用工具 | `execute` | `*` |
| `todowrite` | 实验 | 多步任务清单（`experimental.todo: true`） | 由实现决定 | — |

MCP 工具不在固定列表里，见第 6 节。

## 2. 文件工具

### 2.1 `read`

```json
{ "path": "src/server.ts", "offset": 120, "limit": 80 }
```

- 文本输出带行号，单页最多 **2000 行 / 50 KiB**；单行超过 2000 字符会被截断。
- `offset`/`limit` 用于分页；大日志应分页读，而不是一次拉全量。
- PNG/JPEG/GIF/WebP/PDF 会作为媒体传给模型，源数据上限 **20 MiB**；其他二进制失败。
- 图片会按 `media.image` 配置缩放/拒绝（见 11 号文档）。
- 目录读取是**非递归**的，只列直接子项。

### 2.2 `glob` / `grep`

```json
{ "pattern": "**/*.test.ts", "path": "packages/core", "hidden": false, "limit": 50 }
```

```json
{ "pattern": "request timed out", "literal": true, "path": "src", "include": "*.ts", "caseSensitive": true, "limit": 100 }
```

- `glob` 默认最多 100 个文件，超时 30 秒。
- `grep` 默认最多 100 行匹配，超时 30 秒；`pattern` 默认按正则解释，`literal: true` 时按字面量。
- `include` 是文件 glob；`caseSensitive` 控制大小写。
- `grep` 的权限资源是 **pattern**，不是 `path`；因此限制搜索目录不能只靠 `grep` 规则。

### 2.3 `edit` / `write` / `patch`

```json
{ "path": "src/config.ts", "oldString": "timeout: 60", "newString": "timeout: 30", "replaceAll": false }
```

```json
{ "path": "docs/example.md", "content": "# Example\n" }
```

```text
*** Add File: src/new.ts
*** Update File: src/old.ts
*** Delete File: src/legacy.ts
```

- `edit` 要求 `oldString` 精确匹配一次；`replaceAll: true` 才替换全部。
- `write` 会创建缺失父目录，并可能运行 formatter。
- `patch` 只在支持的 GPT 模型上暴露；其他模型使用 `edit`/`write`。权限资源是**每个受影响路径**。
- 三者都使用 `edit` action；不存在单独的 `write`/`patch` 权限。
- 写文件后若启用 `formatter`，OpenCode 会调用对应格式化器（见 11 号文档）。

### 2.4 路径与外部目录

- Location 内的相对路径按会话活动目录解析。
- 位于 Location 与其非根 worktree 之外的路径，会在 `read`/`edit` 规则之前先检查 `external_directory`。
- `external_directory` 默认 **allow**；要恢复“外部访问需审批”，必须显式配置 `ask`/`deny`。
- 路径会规范化：反斜杠转 `/`，Windows 上大小写不敏感。

## 3. Shell 工具

```json
{
  "command": "bun test",
  "workdir": "packages/core",
  "timeout": 300000,
  "background": false
}
```

- 用 `workdir` 而不是在命令里写 `cd`。
- 前台默认超时 **2 分钟**；`timeout` 单位毫秒。
- `background: true` 立即返回，任务完成时通知会话；后台任务默认无超时（除非显式设置）。
- 输出过大时会被截断，完整输出保存在 managed 文件里。
- 权限检查由内置 shell scanner 完成，覆盖 Bash/Zsh/POSIX `sh`/PowerShell：
  - 语法错误或无法安全分析的动态求值会返回 scanner error，而不是执行。
  - 复合命令会拆成多条子命令逐条检查；`cd` 目标与推断出的外部工作目录也会检查。
  - `git status *` 这类以 ` *` 结尾的规则也匹配不带参数的 `git status`。
- `shell` 拥有宿主用户的文件系统、进程与网络权限；**目录推断是 best-effort**，不要用“识别所有危险命令”的思路配置规则。

## 4. Web 工具

### 4.1 `webfetch`

```json
{ "url": "https://example.com/docs", "format": "markdown", "timeout": 60 }
```

- `format`：`markdown`（默认）、`text`、`html`。
- 只接受文本类响应（HTML/纯文本/JSON/XML），不下载图片或二进制。
- `timeout` 最多 120 秒。
- 大输出会截断，完整文本保留在 managed storage。

### 4.2 `websearch`

```json
{ "query": "latest Bun release notes" }
```

- 使用 Console 或已连接的搜索 Provider（`exa`、`firecrawl`、`parallel`、`tavily`、`tinyfish`、`opencode` 等）。
- `websearch` 配置为 `false` 时工具不出现；`policies.websearch.use` 可以按 Provider 收紧。
- 所有 Provider 都被拒绝时，工具不再提供。

## 5. 交互与自动化工具

### 5.1 `question`

```json
{
  "questions": [
    {
      "header": "API 变更",
      "question": "选择破坏性变更还是兼容层？",
      "options": [ { "label": "破坏性", "description": "..." }, { "label": "兼容层", "description": "..." } ],
      "multiple": false
    }
  ]
}
```

- 暂停执行，等待客户端回答；客户端必须支持交互表单，否则问题会被取消。
- 用户始终可以自由输入；`multiple: true` 允许多选。
- 权限 action `question`，resource `*`。
- HTTP API 侧对应 `Session.Form`：`GET/POST /api/session/{id}/form`、`POST /api/session/{id}/form/{formID}/reply`。ACP 侧对应 `elicitation/create`。

### 5.2 `skill`

```json
{ "id": "git-release" }
```

- ID 必须来自当前可用技能列表，或用户在 prompt 中显式 `@skill-id`。
- 加载时检查 Agent 的 `skill` 权限；`deny` 会隐藏并拒绝加载。
- 加载后把正文（不含 frontmatter）加入对话，并提供技能根目录与最多 10 个支持文件路径。
- 支持文件不会自动读入，由 Agent 按需读取。

### 5.3 `subagent`

```json
{
  "agent": "explore",
  "description": "Map the auth flow",
  "prompt": "Find the authentication entrypoints and return key files.",
  "background": false
}
```

- 只有 `mode: subagent` 的 Agent 可用。
- 前台调用等待结果；`background: true` 立即返回，完成后通知父会话。
- 返回 `sessionID`，可用于继续同一个子会话。
- 默认嵌套深度为 1（子 Agent 不能再开子 Agent）；`experimental.subagent_depth` 可调。
- 权限 action `subagent`，resource 是 Agent ID。

## 6. MCP 工具

MCP 工具名规则：

```text
<server>_<tool>
```

非字母、数字、`_`、`-` 的字符替换为 `_`：

```text
server: context 7
tool:   resolve.library/id
name:   context_7_resolve_library_id
```

- 默认通过 **Code Mode** 暴露：`tools.context_7.resolve_library_id(...)`。
- 服务器设置 `codemode: false` 时，工具直接出现在模型的原生工具列表中。
- 权限 action 就是规范化后的 `<server>_<tool>`，resource `*`。
- 可以用通配符批量拒绝：

```jsonc
{ "permissions": [ { "action": "context7_*", "resource": "*", "effect": "deny" } ] }
```

MCP resources 由两个内置工具读取：

| 工具 | 权限 action | resource |
|---|---|---|
| `list_mcp_resources` | `opencode_list_mcp_resources` | server 名 |
| `read_mcp_resource` | `opencode_read_mcp_resource` | `<server>:<uri>` |

MCP prompts 会变成命令 `<server>:<prompt>`，例如 `/context_7:find_docs`。详见 08 号文档。

## 7. Code Mode（`execute`）

`execute` 在受限 JS 运行时中执行代码，让模型并行调用工具、组合结果，而不必把每个中间值都塞进上下文。

```js
const [pkg, readme] = await Promise.all([
  tools.read({ path: "package.json" }),
  tools.read({ path: "README.md" }),
]);
return { pkg: pkg.content, readme: readme.content };
```

运行时约束：

- **没有**直接文件系统访问、`import`、`setTimeout` 等定时器。
- 提供 `fetch` 用于 HTTP 请求；其余能力必须通过工具目录。
- `tools.<name>(...)` 调用内置/MCP/插件工具；MCP 工具按 server 命名空间分组。
- 插件工具可以声明 `codemode: true` 并提供自由格式输入；在 Code Mode 中可直接传字符串。

权限语义：

- 拒绝 `execute`（resource `*`）会**移除 Code Mode 以及仅通过它可达的工具**，包括未设置 `codemode: false` 的 MCP 工具。
- Code Mode 内嵌套调用的内置/MCP 工具仍然各自执行权限检查；插件工具执行其声明的权限。
- 因此“允许 execute”不等于“允许所有工具”，但“拒绝 execute”会显著缩小工具面。

### 7.1 `opencode` 命名空间

Code Mode 内的 `tools.opencode` 提供会话与 worktree 工具：

| 工具 | 作用 | 权限 |
|---|---|---|
| `session_rename` | 改当前会话（或指定 `sessionID`）标题 | 内置 action |
| `session_move` | 把会话移动到相对/绝对 `directory`；在安全边界生效 | 内置 action |
| `worktree_create` | 按 `name` 创建 worktree，返回 `directory` | 无内置 action |
| `worktree_list` | 列出项目 worktree | 无内置 action |
| `worktree_remove` | 删除 OpenCode 记录的 worktree；`force` 丢弃未提交修改 | `edit`，resource 为 worktree 目录 |

## 8. 浏览器命名空间（`browser`）

由 OpenCode Desktop 附带的浏览器提供，只能在 Code Mode 中访问。先打开标签页拿到 `tabID`，之后每个页面操作都显式传这个 ID。

能力类别：

- 标签页与导航（open/close/activate、goto、back/forward）
- 页面快照与搜索（snapshot、find）
- 点击与表单输入
- 截图
- 文件上传/下载（每次 ≤ 5 MiB）
- console 与 network 检查（含响应体）
- 性能 trace、heap 检查、Lighthouse 审计

限制与安全：

- 截图要求标签页可见且聚焦。
- 上传路径是 **server 本机路径**；截图/捕获也返回 server 本机路径。
- 页面内容、日志、header、响应体都是**不可信数据**，不是 Agent 指令。
- `browser` 规则 `*` 为 `deny` 时整个浏览器目录被移除；浏览器操作本身不逐次弹权限。
- 没有 Desktop 浏览器时该命名空间不可用。

## 9. 工具输出与截断

配置：

```jsonc
{
  "tool_output": {
    "max_lines": 2000,
    "max_bytes": 51200
  }
}
```

- 默认保留 **2000 行 / 50 KiB**；超出部分截断，但完整内容通常保留在 managed 文件/存储中。
- 大输出会以“摘要 + 文件路径”的形式进入模型上下文；控制面展示时应同时提供“查看完整输出”的入口。
- 单个工具可以有自己的限制（如 `read` 的 50 KiB、附件 20 MiB、浏览器传输 5 MiB）。

## 10. 工具权限映射速查

| 操作 | action | resource 示例 |
|---|---|---|
| 读文件 | `read` | `src/app.ts`、`~/.ssh/id_rsa` |
| 改文件 | `edit` | `src/app.ts` |
| glob | `glob` | `**/*.ts` |
| grep | `grep` | `DEFAULT_TIMEOUT` |
| shell | `shell` | `git status *`、`rm *` |
| 子 Agent | `subagent` | `general` |
| 技能 | `skill` | `effect` |
| 提问 | `question` | `*` |
| 抓网页 | `webfetch` | `https://example.com/*` |
| 搜索 | `websearch` | 查询文本 |
| 生成图片 | `experimental_image_generate` | `openai/gpt-image-2#high` |
| 外部目录 | `external_directory` | `/home/me/other/*` |
| MCP 工具 | `<server>_<tool>` | `*` |
| 列 MCP 资源 | `opencode_list_mcp_resources` | server 名 |
| 读 MCP 资源 | `opencode_read_mcp_resource` | `<server>:<uri>` |
| Code Mode | `execute` | `*` |

多资源操作的判定：

- 一次操作检查多个资源（例如 patch 多个文件）时：**任一 deny → 整体 deny；否则任一 ask → ask；否则 allow**。
- 规则按顺序求值，**最后匹配者生效**；Agent 规则追加在全局规则之后。

## 11. 工具事件（控制面渲染依据）

| 事件 | 用途 |
|---|---|
| `session.tool.input.started` | 模型开始生成工具参数 |
| `session.tool.input.delta` | 参数流式片段（字符串） |
| `session.tool.input.ended` | 参数生成结束 |
| `session.tool.called` | 工具被调用；`data.input` 是解析后的对象，`executed` 表示是否真正执行 |
| `session.tool.progress` | 执行进度/中间状态 |
| `session.tool.success` | 成功；`data.content` 是 `Tool.Content[]` |
| `session.tool.failed` | 失败；带结构化错误 |

对应消息侧状态：`streaming → running → completed|error`。控制面应以事件流为主、消息拉取为辅：

```text
input.started → 显示“正在生成参数”
input.delta   → 可选：显示原始 JSON 片段（不要当最终参数）
input.ended   → 参数完成
called        → 显示工具名 + 输入 + 权限结果
progress      → 更新进度条/日志
success/failed→ 显示结果/错误，保留完整输出入口
```

`Tool.Content` 支持文本与文件内容块（`Tool.TextContent`、`Tool.FileContent`），控制面要分别渲染。

## 12. 控制面关注点

- **工具卡片以 `tool.id` 为键**：同一条 assistant 消息里可能多次调用同名工具，必须用事件里的 `id`（或消息里的 `tool.id`）关联输入、进度与结果。
- **不要把 `streaming` 的 `input: string` 当 JSON 解析**；它可能不完整。等 `running`/`called` 的 `input: object`。
- **`executed: false` 表示未真正执行**（例如被权限拒绝或模型只生成调用），UI 不要显示为成功。
- **MCP 工具名会规范化**，展示时保留原始 server/tool 名（可从 `/api/mcp` 与事件 metadata 获取）；路由/权限匹配用规范化名。
- **Code Mode 是一层间接调用**：顶层 `execute` 成功后，内部工具调用仍可能失败。若需要精确展示，消费嵌套工具事件或解析 `execute` 的返回内容。
- **长输出**：把完整输出放在可展开区域，并提供下载/复制；不要把 50 KiB 全量塞进前端首屏。
- **浏览器能力仅 Desktop**：控制面/节点 agent 不应假设 `browser` 可用；调用前检查工具目录。
- **审批与工具事件顺序**：`permission.asked` 可能出现在 `session.tool.called` 之前（参数生成后、执行前）。控制面必须先完成 reply，才能期待 `success/failed`。
