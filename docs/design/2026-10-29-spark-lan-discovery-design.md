# Spark 局域网发现与连接设计

状态：用户已确认增量实施，第一版已接入私有化桌面端并完成 macOS 开发态实机发现。本文包含后续设计，当前实现范围以实施记录为准；Spark 常驻服务已由用户安装并确认 active/enabled。

## 已确认的产品边界

- 基于 v0.7.1（3a608be0）开发，当前分支 feat/spark-lan-discovery。
- 第一阶段只解决笔记本与 Spark 同一局域网（含 Wi-Fi）的连接；热点和有线直连配网另行处理。
- 自动发现是新增入口。手动输入后端地址始终可用，首次连接页和设置页都保留。
- 已配置地址继续使用，不因发现广播被覆盖，不强制用户重新选设备。
- Spark 使用私有化版。运维预置默认组织和管理员，管理员添加成员；不新增自助注册、邀请码、设备认领或创建组织流程。
- 双机提供同一个 Lework 服务时只呈现一个入口；发现对象是服务部署，不是每个模型 Worker。

## 实查依据

- 本机 Electron 桌面端已有 PrivateDeploymentGate 和 PrivateServerSettingsCard；共享实现位于 frontend/packages/app-ui/components/private-deployment。
- frontend/packages/store/api/config.ts 将地址规范化到 /v1，使用无登录凭据的 GlobalConfig 请求测试服务。
- API_BASE_URL 和 apiClient 在模块加载时固定；现有设置保存后刷新应用。
- authStorage 使用单份 leros-auth-user，当前并未按后端隔离凭据。切换服务时必须清理旧登录状态。
- Spark 当前服务为 http://172.16.0.64:38081，GlobalConfig 返回 enterprise；远端镜像为 v0.6.5 企业版，不能将本地代码版本当作远端版本。
- Spark 的 Avahi 已运行，当前用户网络接口为 wlP9s9；双机互联和 Kubernetes/Docker 使用其他网段。现有 Avahi 仅有 ssh.service。
- 用户已使用管理员账号登录。此阶段不修改账号库、组织、认证服务或模型配置。

## 技术方案与取舍

第一版采用方案 1；后续能力按阶段验证。

1. 推荐：Spark 宿主机发布 mDNS/DNS-SD 服务，Electron 主进程浏览，渲染进程显示设备列表。可复用 Avahi，兼容当前后端，IP 变化由本地域名解析处理。
2. 仅提供固定 .local 地址：部署较小，但用户仍要知道并填写名称，无法满足打开客户端即发现设备。
3. 扫描网段或自定义广播：需要猜测网段和端口，且本机是 /16 网络；不采用。

第一版能力放在私有化 Electron 客户端。普通网页保持手填入口，不承诺浏览器直接发送 mDNS；共享组件通过可选能力接口接入，避免网页依赖 Electron。

## 用户行为

| 状态 | 行为 |
| --- | --- |
| 未配置 | 显示“附近的设备”并自动搜索；同屏保留手填输入框和测试保存按钮，无需等搜索超时 |
| 发现一个服务 | 展示名称、地址、可连接状态；用户点击连接，不自动选中并登录 |
| 发现多个服务 | 列表展示，按部署标识合并双栈/多接口记录；同名不同标识显示短编号 |
| 已手填且可连接 | 沿用保存地址和既有登录流程，不阻塞等待发现 |
| 已通过发现连接 | 优先沿用保存的稳定主机名 URL，后台重新搜索同一部署；同 URL 下沿用既有登录状态 |
| 搜索无结果或权限被拒绝 | 明确提示“暂未发现”，允许重试和手填；不把搜索失败判断为后端不可用 |
| 保存地址不可达 | 展示连接失败及重试、发现、手填选项；不清空保存值和登录凭据 |
| 用户主动切换地址 | 无凭据测试通过后保存；URL 不变则保留会话，URL 改变则清除旧认证并重新登录 |

设置页保留完整手填能力，并提供“搜索局域网设备”。手动操作优先于异步搜索结果。运行中的任务遇到断线时沿用既有断线处理；不后台切换地址或强制刷新。用户主动保存新地址前提示会重新加载。

## 服务发布

- 服务类型约定为 `_lework._tcp.local.`，作为产品内部协议，协议版本 `v=1`。
- SRV：可解析的稳定 .local 主机名、对用户开放的端口；当前端口为 38081，不发布容器端口或 Pod IP。
- TXT 仅包括 `v`、`id`（一次生成并持久化的部署 UUID）、`scheme`（http/https）、`path`（当前 /v1）。设备名称由服务实例名称提供。
- 不发布邮箱、组织成员、密码、令牌、模型密钥。部署 ID 用于去重和定位，不是认证证明。
- 同一套双机仅由提供用户访问入口的主机发布，Worker 不发布。此阶段不增加主备切换。
- 宿主机安装工具须校验参数、XML 转义、保留 UUID、支持重复执行和卸载。只操作自己拥有的服务定义及状态，不覆写现有 ssh.service。
- 发布限定用户网络接口，排除双机互联、Docker、CNI、VPN 等接口；优先通过 Avahi D-Bus 按 interface index 注册，避免改动全局 Avahi 配置影响其他服务。发布进程由 systemd 托管，重启及接口恢复后重新注册。
- 运维显式指定接口名称；第一阶段不自动切换 AP/STA，不创建路由或 DHCP 服务。
- 为兼容旧后端，不新增必须的 API/数据库字段。静态广播不代表服务健康，客户端仍执行 GlobalConfig 测试。

## 桌面实现边界

- Electron 主进程持有唯一发现实例，使用成熟 DNS-SD 库，具体依赖选型由实施计划确定；不手写 DNS 包解析器。
- 新增独立 discovery shared types 和 preload API，提供开始/停止、快照、订阅；只允许受信任应用窗口调用，不能由渲染进程传入任意扫描目标或 shell 命令。
- 生命周期：首次连接界面自动搜索；设置页主动搜索；窗口/订阅退出时释放监听与 UDP 资源。重新搜索和网络变化时清理过期结果，不累积监听器。
- 建议搜索窗口 8 秒，GlobalConfig 测试沿用现有 8 秒上限；候选验证并发上限 3、列表上限 32，单候选缓存避免广播导致请求风暴。
- 候选严格解析：限制协议版本、长度、端口、scheme、path；不接受凭据、查询串、片段或任意 URL。以 SRV host 与声明端口构造地址，不接受 TXT 整段覆盖 URL。
- 发现接口返回候选记录，不携带或读取认证凭据。验证请求不走带 Authorization/自动刷新令牌的 apiClient；禁用凭据、拒绝重定向。
- 发现路径优先保存 .local 主机名 URL；解析不可用时，允许用户手填可达 IP，不静默改用 IP 并发送旧凭据。
- 重复 ID 但 host/port 冲突时标记冲突并禁止自动选择，保留手填。
- macOS 安装包增加本地网络权限说明及 Bonjour 服务声明，并在打包应用实测；Windows 验证防火墙限制，Linux 验证 UDP 5353 共存。失败时手填仍可用（前提是系统允许目标服务的单播访问）。

## 连接记忆与兼容

- 保留现有 leros-server-base-url 键及历史键迁移逻辑，增加独立、带版本号的发现记录：source、deploymentId、displayName、canonicalUrl、lastSeenAt。
- 没有发现记录的旧配置视为 manual，包括用户现有 172.16.0.64:38081；不自动绑定广播身份或改写地址。
- 手动保存与发现保存使用同一个连接切换入口，统一清理认证和刷新，防止某个入口遗漏。
- 本地校验完成、地址及关联元数据保存成功后才能刷新。存储异常不得留下新 URL 与旧令牌混用状态；保存失败保留旧配置并报告错误。
- 重启恢复只对记录的 URL 使用原有登录恢复。发现同一 ID 但 URL 改变时，需要用户明确选择，清除会话后重新登录；单靠 mDNS ID 不允许迁移旧令牌。
- 同一稳定主机名解析到新 IP 不要求改写 URL。mDNS 和当前明文 HTTP 都不提供密码学设备认证；此阶段不声称能抵御局域网主动伪装。更强身份保证需要另行规划受信任 TLS/设备身份方案。
- 无发现能力时（旧客户端、普通网页或操作系统限制），现有手填连接保持可用。
- 首次配置完成前不挂载需要登录的业务页面；对已有配置不新增强制等待。若将来支持自动跨 URL 迁移，需先改造启动引导和凭据隔离，本次不实现。

## 验收与发布

1. 无配置时发现入口与手填入口同时可用；搜索过程不锁住输入框。
2. 单设备/多设备/重复广播/同名/冲突 ID/设备离线分别覆盖；仅可达且协议兼容的服务可连接。
3. 使用现有 v0.6.5 enterprise GlobalConfig 完成连接；现有管理员登录可用，成员由管理员维护。
4. 原有手填配置不变；无 mDNS、权限拒绝、非法广播、验证失败均能回退手填。
5. 地址不变保留登录；主动换地址清除认证；后台发现不改配置、不发送旧令牌、不刷新业务页。
6. Wi-Fi 重连、地址变化、应用重启后，稳定主机名路径可恢复；URL 改变提示重新选择登录。
7. 核对搜索/验证请求无 Authorization、cookie 或刷新令牌；拒绝重定向、超时请求可取消。
8. 运行相关 Vitest、TypeScript 检查及桌面构建；对 macOS 打包应用和实际 Spark 做联调。未在 Windows/Linux 验证前明确标注未验证。
9. 实机发布先备份本次涉及的宿主机服务定义，验证新广播，再用测试客户端验证；不改 Wi-Fi、组织、现有后端镜像或中断运行任务。卸载发布服务即可撤销广播，客户端仍可手填。
