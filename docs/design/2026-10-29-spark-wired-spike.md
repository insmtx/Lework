# Spark 网线直连最小验证

目标：笔记本通过网线访问 Spark，Wi-Fi 保持互联网连接；继续复用 mDNS/DNS-SD 与手填保底。

## 实查与配置冲突

用户接好网线后，笔记本 USB 千兆网卡 en5 链路 active，MAC 94:05:bb:10:a1:47；手动 IPv4 为 172.16.0.65/16，无网关。Wi-Fi en0 为 172.16.0.162/16，默认网关 172.16.0.1。

Spark 对端为 enP7s7（用户 RJ45），原活动连接“有线连接 3”，UUID 6b864655-27f4-3c72-b22e-8ce1d7dfd5e5，手动 IPv4 为 172.16.0.64/16，网关 172.16.0.1。有线和 wlP9s9 同 IP / 同网段；Spark 对 172.16.0.162 的返回路由实际优先走 enP7s7，导致普通 SSH 超时。绑定 Mac en5、源地址 172.16.0.65 的 SSH 与后端 GlobalConfig 成功（HTTP 200），确认物理直连可用。

不能据当前静态地址连接成功声明即插即用已经成立。双机高速互联为其他两个接口的 10.100.216.0/24 和 10.100.217.0/24，保持原样。

## 本次最小方案

用户已要求逐场景验证，沿用临时脚本方式：Spark 指定用户网口启用 IPv4 link-local / IPv6 link-local、never-default；笔记本有线改为 DHCP，未找到 DHCP 服务后由系统采用 169.254.x.x 自分配地址。两端均不在直连链路提供默认网关，Wi-Fi 继续上网。

替代方案是 Spark 在专用网段提供 DHCP，但需要额外服务与默认路由/DNS 选项控制。本轮先验证系统原生链路本地方案，其局限是首次等待自动地址可能较慢。当前并非跨系统最终选型。

`deployments/spark/wired-smoke.sh`：

- check：只读验证明确指定的用户网口 enP7s7、carrier、现有连接 UUID 与发现依赖。
- start：需 sudo；仅创建不落盘的临时连接，测试期间优先自动重连，不更改原连接内容；systemd 独立运行，10 分钟后删除测试连接并恢复。内存连接不会跨主机重启保留。
- run：激活指定网口的 link-local 配置并发布现有部署 UUID；不修改 Wi-Fi、集群、默认网关或防火墙。
- cleanup：删除临时连接，若用户未另行切换此网口，则恢复原活动 UUID；恢复失败报错并保留运行目录以供处理。

恢复原配置会再次出现之前的重叠网段，因此最终验收后应拔掉测试网线，或另行确定专用有线配置；不会擅自覆盖原配置。当前有线 SSH 在切换时会中断，服务和清理不依赖 SSH 继续在线。

## 首次拔插发现与修正

15:05:15 拔线，15:05:37 插回；NetworkManager 日志证明此时激活了原“有线连接 3”，而非临时连接。原因是首版临时连接设置 autoconnect=no，拔插后不会被自动选中。15:05:45 测试时限触发，临时连接成功删除，原 UUID 保持活动；本轮不能认定拔插恢复通过。

脚本修正为 save no + autoconnect=yes + priority=999：仅测试期间优先自动重连，退出时仍删除内存配置并恢复原活动 UUID。该修改待重新启动和真实拔插验证。
