# Spark 发现第一版实施计划

**目标：** 将已验证原型接入私有化桌面端，保留手填、测试和保存；交付可开机发布的宿主机工具。
**设计：** [局域网发现设计](2026-10-29-spark-lan-discovery-design.md)。本次按用户“小规模验证后继续”的要求增量交付，不实现后台切换、设备迁移或账号改造。
**架构：** Electron 主进程进行有限时长 DNS-SD 搜索，受限 IPC 返回候选。共享 UI 接受可选发现插槽。选中候选仅填写地址，保存仍复用原流程。
**技术：** Electron / React / TypeScript / bonjour-service 1.4.4 / Python D-Bus / systemd。

## 约束

- 基于 v0.7.1 当前分支，不复制或覆盖其他未提交文档。
- 手填始终可用；已有配置不自动更改，不将发现 ID 当身份凭据。
- 地址变更清理旧登录，原地址不变则保持；广播与验证不带凭据。
- 宿主机仅在指定用户接口广播；不改网络、认证、组织或后端镜像。
- 新的长期系统服务先完成本地验证；安装需具备宿主机 sudo 权限。

## 重点边界

1. 搜索超时或失败，手填仍可用。
2. 网络广播不能诱导发送凭据或任意远程 IPC。
3. 同一 ID 多地址冲突不能默认选用。
4. 异步搜索不能覆盖用户输入，页面卸载不能泄漏 UDP 资源。
5. 新地址保存失败时不能把旧令牌留给新地址。
