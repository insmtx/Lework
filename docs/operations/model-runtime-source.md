# 模型列表：来源与实际状态

模型列表区分三个概念：

| 字段 | 含义 |
| --- | --- |
| 来源 | `Spark` 为运维明确绑定的本机模型；`配置` 为其他已保存的模型接口配置 |
| 实际状态 | Spark 的已就绪、启动中、停止中、已停止、异常、未知；配置模型的未检测、可用、不可用、未知 |
| 启用状态 | 管理员是否允许选择此配置，与模型进程运行状态独立 |

列表可见时每 15 秒静默刷新，后台刷新不弹提示、不显示加载动画。Spark 状态来自本机管理代理的只读 `/model`，不发起推理；快照超过 30 秒或读取失败显示未知。已就绪表示本机模型健康，不等同于任务准入已开放，也不保证已登记的代理地址、密钥有效；端到端调用仍可使用“测试连接”验证。

“配置”模型不会自动发起可能计费的推理请求。管理员点击“测试连接”后，该客户端显示检测结果，60 秒后转为未知。修改模型配置、退出登录或切换组织后不复用旧检测结果。未知或失败均不自动禁用模型或切换默认项。

## 后端配置

升级后端后，在现有 `spark` 配置下增加 `model_bindings`，保留原主机、组织、模型控制、socket 和维护配置。例如：

```yaml
spark:
  org_id: 1
  model_control: true
  # 其他原有 Spark 字段保持不变
  model_bindings:
    - llm_model_id: 1
      model_id: qwen
      model_name: Qwen3.6-35B-A3B
      base_url: http://10.42.0.1:58089
    - llm_model_id: 2
      model_id: qwen
      model_name: Qwen3.6-35B-A3B
      base_url: http://10.42.0.1:58089
```

此处 ID 和地址仅为本次现场示例，安装前须核对：

1. `llm_model_id` 是该组织数据库中的模型配置 ID，每个 ID 只能登记一次。
2. `model_name`、`base_url` 必须匹配该条配置保存的值（地址仅忽略末尾 `/`），不能仅凭名称关联。
3. `model_id` 必须匹配 `/etc/leros-spark/model.json` 的模型标识。管理代理实际返回不同模型时，只显示未知。
4. 应用后端配置并重启后端服务，打开组织管理 → 模型管理验证。此变更不要求重启管理代理、Worker 或模型。

没有登记绑定时，模型归类为“配置”，即使它恰好与 Spark 模型同名。旧后端不返回新字段时，客户端显示来源/实际状态“未知”，提示升级，不猜测来源。

## 验收

- 已绑定的 Qwen 对话、翻译两行显示 Spark 和管理代理观察到的状态。
- DeepSeek 或同名云端接口显示配置；启用不能被当成在线。
- Spark 停止/启动的状态随后台刷新更新；设备不可达或状态过期显示未知。
- 配置模型测试结果过期、列表刷新失败、切换组织时不会残留“可用”结论。

代码与本地测试完成并不代表现场已升级。部署记录应单独记录后端镜像、绑定配置及现场列表验收结果。
