# Spark 桌面连接与管理发布验收

适用范围：私有化桌面客户端、当前连接的一台 Spark、已登记的本机模型。系统关机和双机模型不在本次发布范围。本文是发布门槛，不代表所有项目已经验收通过。

## 部署一致性

1. 后端、桌面和设备管理代理分别记录构建版本，按同一发布清单安装；只升级桌面无法增加现场后端能力。
2. 后端 `spark.device_id` 与宿主机 `/var/lib/leros-discovery/id` 使用相同部署标识；`spark.device_name` 使用用户可识别名称。Wi-Fi 和用户直连口广播相同标识。标识用于归并与比对，不代替认证。
3. 设备管理绑定当前宿主机和预置组织；只有管理员能够变更服务。普通成员不应读取容器清单、Worker 内部状态或操作接口。
4. 用户直连口自动取址，不配置默认网关或 DNS，不影响笔记本 Wi-Fi 上网，不改双机互联或 Kubernetes 网络。当前安装器面向已验证的 `enP7s7`，其他硬件网口须单独适配验收。
5. 运维预置组织及管理员。用户无需 SSH、手动配置 IP 或自行注册组织；发现失败时保留手动连接入口。

每个平台分别记录安装包版本、系统版本、适配器型号、网络环境和测试结果。开发模式不替代签名安装包测试。

## 管理与诊断验收

- 未连接或普通后端不显示 Spark 管理；仅搜索到设备不视为连接成功。手填连接的 Spark 也按后端能力识别。旧后端缺少 `GlobalConfig.device` 时，仅当前已登录服务的管理员可通过严格验证的只读 Spark 状态接口兼容识别；不向发现候选发送凭据。旧版普通成员仍需后端升级提供公开设备声明。
- 已确认设备断线时保留离线说明和重试，所有操作禁用；账号、组织或后端切换后旧请求不能覆盖新状态。
- 主界面能分清设备连接、模型是否就绪、是否接受新任务；不出现关机按钮和关机预检。
- 启停须验证本机模型真实健康/正常退出。重复点击、响应丢失、页面关闭、服务重启均不得重放未知操作或解除他人的维护。
- 诊断默认折叠，可复制白名单信息；不导出访问令牌、模型密钥、用户资料、容器环境或原始响应。
- 启停失败或状态未知时，保留可定位的操作记录；不得用清除状态文件或强制停止来伪造完成。

- 使用新版发现代码做只读局域网扫描，发现一台 Spark，归并为同一设备的 IP 与 `.local` 候选；未发送登录凭据，未切换现有会话。

- 桌面全量 113 项、状态层 115 项、连接组件专项 15 项及 Python 64 项通过；桌面 web/node、共享 UI 和状态层类型检查通过。设备声明、连接切换、旧认证请求隔离、权限、进度与诊断均有回归覆盖。
- Go vet、普通构建及 enterprise 构建通过；Spark、数据库及 Spark HTTP 专项 race 通过。全量 Go 测试仍有既有 `TestComputeOccurrenceWindow_IntervalAnchorGrid` 失败。
