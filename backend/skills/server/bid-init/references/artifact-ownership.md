# 产物职责与权威关系

## 工作区

```text
input/       用户原始文件，只增不改
work/        项目过程、候选文件和独立审查
output/      仅保留通过最终审查的 DOCX 与待补充清单
```

## 最小业务区域

| 区域 | 负责人 | 主要对象 |
|---|---|---|
| `work/项目/` | 项目负责人 | 项目身份、投标事实、材料索引、待补项 |
| `work/招标/` | 合规分析师 | 输入清单、来源关系、模板路线、规范化来源、原子要求、覆盖结论 |
| `work/投标文件/` | 文档工程师 | 锁定目录、可填写底板、填写说明、完整候选 DOCX |
| `work/填充内容/` | 内容主笔 | 按最终目录叶子组织的动态 Markdown 内容 |
| `work/独立复核/` | 独立审查官 | 完整候选 DOCX 的最终审查报告 |
| `work/.tmp/` | 任意阶段 | 可再生渲染件和临时文件；唯一允许自动清理的区域 |

## 权威对象

| 对象 | 权威位置 | 说明 |
|---|---|---|
| 项目身份 | `项目/project.json` | 项目根、项目名称和工作区基本信息。 |
| 用户确认 | `招标/template-route.json`、`项目/bidder-facts.json`、`项目/pending.json`、`投标文件/目录.json` | 确认结果直接写入其对应业务产物。 |
| 投标事实和待补 | `项目/bidder-facts.json`、`项目/material-index.json`、`项目/pending.json` | 未确认事实只能以 `【待补充：具体内容】` 出现在内容中。 |
| 招标要求 | `招标/requirements.json`、`招标/coverage.json` | 原子要求和来源覆盖的机器权威。 |
| 最终目录 | `投标文件/目录.json` | 用户确认后锁定；每个叶子对应一个 `填充内容/` 子目录。 |
| 模板规则 | `投标文件/填写说明.md` | 唯一保存技术定位、逐章来源、填写规则、保护范围和验收结论。 |
| 章节动态内容 | `填充内容/<目录叶子>/**/*.md` | 简单章节可维护 `内容.md`；复杂章节按实际逻辑拆分 Markdown。 |
| 候选与验收 | `投标文件/候选投标文件.docx`、`独立复核/最终审查报告.md` | 最终判断基于完整候选 DOCX 及其渲染。 |

## 禁止依赖

- 章节 Markdown 是动态正文的权威来源；DOCX 回填不反向改变其内容。
- `.tmp/` 用于可重建临时文件；业务与验收依据以工作区中的权威产物为准。
- `output/` 交付最终 DOCX 与待补充清单。
