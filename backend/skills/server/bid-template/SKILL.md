# 可填写模板

由投标文件工程师主导。目标是得到可重复回填、可保护固定格式的 DOCX 底板，以及说明模板填写位置、内容形态和填写规则的唯一填写说明；本阶段不写入实质性投标内容，也不登记具体素材或待补事项。

## 进入闸门与阶段产物

进入前：模板来源、章节边界和最终目录已确认；`bid-init` 已交接规范 DOCX 和模板边界。本阶段不要求具体投标事实、素材清单或待补清单。

| 产物       | 路径                                 | 作用                                               |
| ---------- | ------------------------------------ | -------------------------------------------------- |
| 可填写底板 | `work/投标文件/模板/可填写底板.docx` | 每次回填的唯一 DOCX 起点                           |
| 填写说明   | `work/投标文件/填写说明.md`          | 唯一的模板结构、填写目标、内容形态、规则和保护说明 |

## 按需加载本地资料

| 情形                                        | 读取内容                                           |
| ------------------------------------------- | -------------------------------------------------- |
| 选择提取、沿用或自拟路线、识别模板边界      | `references/template-identification-extraction.md` |
| DOCX 编辑、字段、表格、分页、附件和保护规则 | `skills/bid-backfill/references/filling-rules.md`  |
| 输出项目填写说明                            | `templates/填写说明.md`                            |
| 从冻结 DOCX 提取指定正文范围                | `scripts/extract_template_range.py`                |

以 `skills/bid-backfill/references/filling-rules.md` 和本 Skill 当前说明为准；不得为了凑齐路径创建重复规则文件。

## 执行流程

### Step 1：复核模板来源、章节边界与锁定目录

读取 `template-route.json`、`input-manifest.json` 中的规范 DOCX 信息、`目录.json` 和用户确认的模板来源/章节边界。若来源、边界或目录仍为未确认状态，停止；不要以“先做个样稿”绕过闸门。

确认模板来源属于以下哪一条路线：

| 路线     | 适用条件                                                     | 操作                                                       |
| -------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| 直接沿用 | 冻结来源本身就是完整、可填写的官方/用户模板                  | 复制为底板，保留全部结构，并在填写说明中记录来源和保护范围 |
| 直接提取 | 招标 DOCX 中只有一段连续正文是投标模板，且用户已确认起止边界 | 提取范围，再进行结构、边界和页面验收                       |
| 自拟底板 | 无可用底板且用户已明确确认自拟路线                           | 按锁定目录创建底板，并在填写说明中明确其非官方格式属性     |

任何与固定模板冲突的目录问题必须退回 `bid-plan`，不得在底板中偷偷重排目录。

### Step 2：制作底板

对官方或用户模板，无论沿用还是提取，都必须保留原有段落、表格、页眉页脚、页码、固定文字、签章线、日期分段、下划线、目录和样式。不得用“从零新建 DOCX”替代可用的官方底板。

直接沿用时复制冻结来源；直接提取时使用本 Skill 的脚本；自拟路线按用户确认的目录和格式要求制作。所有操作遵守 `filling-rules.md` 中的 `DOCX-EDIT` 和 `TEMPLATE-PROTECT`。

### Step 3：直接提取 DOCX 模板（仅直接提取分支）

先列出冻结来源的正文对象，结合 Word/PDF 可视核对确认模板起止范围。索引是辅助定位，不能只凭文本摘要猜测边界。

```bash
python3 skills/bid-template/scripts/extract_template_range.py \
  --project-root "$PROJECT_ROOT" \
  --input "input/<已冻结的招标DOCX>" \
  --list-body
```

确认边界后提取。`--to` 为排他结束索引；脚本拒绝覆盖既有底板。

```bash
python3 skills/bid-template/scripts/extract_template_range.py \
  --project-root "$PROJECT_ROOT" \
  --input "input/<已冻结的招标DOCX>" \
  --from <起始索引> --to <结束索引>
```

脚本只在标准输出中返回来源、输出路径和正文范围，供模板工程师核对提取操作；不生成独立记录文件。脚本会保留 DOCX 包内的关系部件，并使正文级节属性位于提取结果末尾；但不能替代人工确认复杂分节、文本框、域、页眉页脚和嵌入对象。

提取后立即验证：底板正文与确认范围严格一致，没有多余或缺失章节；首页、尾页、表格、签章区、页眉页脚、分节、附件和关键渲染页面完整。验证失败时丢弃底板，重新确认边界或改用其他路线，不得继续编写填写目标。

### Step 4：编写唯一的项目填写说明

使用 `templates/填写说明.md` 作为结构起点，直接填写 `work/投标文件/填写说明.md`。填写说明必须覆盖：

1. 按模板顺序为每个章节建立一个独立表格；
2. 在该章节表格中同时记录章节位置、字段/表格/附件/正文插入点、需要填写的内容类型、填写规则、固定内容保护和版式检查要求；
3. 将章节前置分页、标题层级、目录要求和相邻页面要求写入同一个章节表格；
4. 缺失信息统一使用 `【待补充：具体内容】` 的占位规则。

“填写规则”列只能引用 `filling-rules.md` 中的规则名称，例如：

- `FIELD-UNDERLINE`：字段、下划线和制表位；
- `MIXED-RUN`：多 Run 或混合格式槽位；
- `TABLE-FILL`：表格填写与模板样本行追加；
- `SECTION-INSERT`：自拟正文或章节插入；
- `SECTION-LAYOUT`：标题、目录和分页；
- `ATTACHMENT-SIGN`：附件、签字和盖章；
- `TEMPLATE-PROTECT`：固定内容与结构保护；

不得在项目说明中重新创造“普通填充”“按模板处理”等无法执行的模糊规则名。

### Step 5：检查并补齐大章节分页和填写目标

逐一核对并补齐每个大章节标题前的明确分页，不能只依赖内容恰好换页。发现缺失分页时，必须在本模板阶段立即增加分页，不能只在填写说明中记录“待处理”，也不能把分页问题留给内容回填阶段。根据模板复杂度选择合适的打开、局部结构或渲染检查；填写说明只记录章节位置、分页要求和填写方式，不记录最终内容或材料。增加分页时优先使用合适的文档编辑方式；不得删除分节符、页眉页脚或目录结构。

每个需要动态填写或保护性处理的字段、表格、正文插入点、附件和签章区至少在所属章节的唯一表格中有一行。未列为可编辑目标的内容均视为受保护内容；不得为同一章节另建字段表、表格表、分页表或保护表。

### Step 6：保护性自检与交接

打开并检查可填写底板，确认模板没有因提取或生成而丢失页、表、固定文字、页眉页脚、签章区、样式或目录；将高风险对象和人工操作限制直接写入 `填写说明.md`。

完成后只交接 `可填写底板.docx` 和 `填写说明.md` 给 `bid-content` 与 `bid-backfill`。

## 强制边界、恢复与完成标准

- 固定表单只能按填写说明中的目标和填写规则填入；
- 不得使用 `python-docx` 编辑底板。优先使用 `docx` skill；该 Skill 不可用时，解包后仅直接、局部修改填写说明已唯一定位的 `word/` XML，再基于原包重新打包、校验和渲染。
- 禁止跨对象遍历替换、正则、字符偏移、批量重建或重排 Word XML。
- 直接提取出现边界不完整、节/页眉页脚异常、域或文本框丢失时，丢弃提取底板，重新人工确认范围或改用直接沿用/人工处理方式。
- 提取验证、边界人工验收、章节分页验证或关键页面渲染任一未通过时，不得完成 `template` 阶段。
- 底板损坏、样式丢失或目录与填写说明不一致时，回到原模板或本阶段临时文件重建；不要修补正式候选 DOCX。
- 模板路线或目录发生变化时，从最早受影响阶段失效并重做底板、填写说明和下游产物。

完成条件：存在可打开的 `可填写底板.docx`；直接提取时已通过提取操作检查；填写说明按模板顺序为每个章节建立唯一表格，并覆盖填写目标、内容形态、填写规则和固定保护；每个大章节标题前已实际增加或确认明确分页，且分页经打开或渲染检查通过；缺失信息占位规则已说明；`template` 已登记为 `completed`。
