# 商务和技术偏差表编写

## 一、作用与生成时点

商务偏差表和技术偏差表建立单一来源条款、实际响应位置和偏差结论之间的逐条对应关系。偏差表不是需求正文、证明材料清单、待补清单或内部审查记录。

在商务承诺、技术方案、实施、服务、培训、验收、报价交付和必要附件说明均形成真实候选内容后生成偏差表。响应位置必须已经存在于锁定目录和正式 Markdown 中。

## 二、分类与范围

按正式文件的章节属性和条款实质分类：

- 商务偏差表逐条列出核心商务义务，包括交付、价格税费、有效期、付款、保证金、合同履约、保密、安全、知识产权、违约、争议、终止和禁止分包等；
- 技术偏差表逐条列出功能、性能、部署、兼容、接口、数据安全、实施、测试、验收、培训、运维、售后和技术交付物等可响应要求；
- 资格条件、文件格式、平台操作和评审程序不进入两类偏差表，仍须在资格、格式、程序或其他对应位置完成覆盖。

同一要求不得重复进入两张偏差表，除非正式模板明确要求双重填写。

## 三、绝对行粒度

以正式文件中的独立小节、子项或表格行作为最小展示单位。一个来源条款只对应一条要求记录和一行偏差表。

禁止：

- 并列多个来源条款、章节号或表格行；
- 以相同主题、响应位置或结论合并相邻来源；
- 用一个概括性条目覆盖多个功能、参数、时限、服务动作或商务义务；
- 用“全部满足”或类似概括代替逐条响应。

来源条款内存在有独立编号、独立小节或独立表格行的下级内容时，继续逐条提取；不得按词语、句子或主观理解制造正式文件中不存在的来源条款。

## 四、字段规则

以当前底板表头为准。表头要求“响应文件章节及条款号”时，该列只填写位置，不填写响应正文。

### 来源条款

逐行填写单一、完整且可定位的正式来源章节、条款、小节、子项或表格行。不得只写上级章节名，也不得使用分号、顿号或范围符号串联不同来源。

### 响应位置

逐行填写锁定目录中的真实章节、节和小节标题。位置必须能够在正式 Markdown 与最终 DOCX 中找到实质响应内容；不得只写笼统章节名、内部编号、文件路径或待补标记。

一条来源条款应有一个唯一响应定位。若正文确实需要跨章节协同，选择承担该条款直接结论和承诺的主响应小节；其他内容只作为正文交叉引用，不在偏差表并列位置。

### 偏差说明

无偏差时使用以下结构：

`完全响应，无偏差。承诺【与本条款直接对应、已确认的履约内容】。`

承诺必须具体说明该条款对应的能力、动作、参数、范围、时限、交付物、责任或控制方式，并与实际正文和已确认事实一致。不得只写“无偏差”，不得复述无关正文，也不得作出未经确认的扩大承诺。

正偏差、负偏差或部分偏差必须逐条写明招标要求、实际提供、差异范围、对功能/交付/验收的影响及已确认替代措施。事实或承诺尚未确认时，不得写“完全响应”，应按正式占位规则处理，并将原因记录到待补清单。

偏差说明不得包含材料缺口、内部编号、审查状态、工作备注或取证任务。

## 五、生成与复核

生成前逐行核验：单一来源条款、单一响应位置、单一偏差说明和所属表类别均已在要求与覆盖关系中登记。

正文、目录或事实变化后，重新核验全部受影响行。正式偏差表 Markdown 只保留底板要求的表名、表头、正式行、固定承诺文字和签章区域说明；不得附加偏差汇总、风险说明、待补清单或内部备注。

## 六、参考材料边界

参考材料只能用于学习逐条映射、分类边界、定位精度和正式表达节奏。不得复制其项目事实、章节号、企业、产品、数值、参数、承诺或行内容。
