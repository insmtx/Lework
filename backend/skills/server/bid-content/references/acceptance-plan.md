# 测试与验收方案

## 一、区分阶段

根据招标要求和项目实际区分：

- 安装/部署验证；
- 功能测试；
- 接口与集成测试；
- 性能与容量测试；
- 安全与权限测试；
- 兼容性或适配测试；
- 用户验收测试；
- 初验、试运行、整改复验和终验。

不得把不同阶段合并成“系统完成后统一验收”。

## 二、验收闭环

每类验收项至少明确：

1. 验收依据和对应要求；
2. 测试对象和范围；
3. 环境、版本、数据、样本和前置条件；
4. 参与角色和职责；
5. 测试步骤和输入；
6. 指标口径、预期结果和判定规则；
7. 原始记录、截图、日志和报告；
8. 缺陷登记、整改和复验；
9. 交付确认和签署材料。

## 三、指标表达

- 招标指标不得降低、删条件或改单位；
- 未有实测材料时，写成验收目标和测试方案；
- 准确率、响应时间、吞吐和可用性要说明统计口径；
- 样本集、负载和硬件条件未确认时不得自行写死；
- 不能宣称尚未发生的验收已经通过。

## 四、验收表格

验收表适合包含：要求位置、测试项、方法、输入/样本、预期结果、判定、证据和责任角色。正文解释测试原则、阶段关系、异常和复验规则，不重复表格。

## 五、交付物

只列招标要求或已确认方案中的交付物，并说明其用途和验收关系。不能为了显得完整自行承诺源代码、全部设计文档、永久支持或其他高风险交付。
