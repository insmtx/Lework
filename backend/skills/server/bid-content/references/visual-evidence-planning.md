# 图示、截图与证据策划

## 一、目的

图和截图是论证工具，不是装饰。核心技术章节应评估是否需要架构图、业务流程图、部署图、数据流图、时序图、技术流程图、产品截图或测试证据。

## 二、图示选择

| 类型 | 适用问题 |
|---|---|
| 总体架构图 | 系统由哪些层和模块组成，如何协同 |
| 业务流程图 | 用户或业务请求如何从发起到结果闭环 |
| 技术流程图 | 数据/任务经过哪些处理步骤 |
| 部署图 | 节点、网络、存储和外部系统如何连接 |
| 时序图 | 接口同步/异步、回调、重试的时间关系 |
| 数据流图 | 数据来源、处理、存储、输出和权限边界 |
| 产品截图 | 证明真实产品界面、配置或结果能力 |
| 测试证据 | 证明真实测试环境、结果和记录 |

## 三、图示要求

- 每张图必须有明确问题和结论；
- 图中主要模块、箭头和边界必须在正文解释；
- 图中文字与正文术语一致；
- 图题准确，正文在图前引入、图后解释；
- 不把未经确认的产品模块画成既有能力；
- 不伪造产品界面、测试数据和检测报告。

## 四、无图时的处理

没有真实截图或无法生成可信图示时：

- 用编号流程、模块职责表或接口时序表完整表达；
- 不在正式正文留下“此处放图”的空洞占位；
- 图示是否必须补充，按项目要求进入待补项；
- 不因缺图降低文字方案的完整性。

## 五、图片资源

正式 Markdown 只引用真实存在、可追溯的资源路径。图片裁切、脱敏、清晰度和版权必须在使用前检查。
