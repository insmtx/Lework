# 服务与售后方案

## 一、服务方案的核心

服务方案应说明发生问题后如何被发现、受理、判断、处理、升级、恢复、确认和关闭，而不是只承诺“及时响应、快速解决”。

## 二、服务流程

```text
服务入口
→ 工单登记
→ 分类与分级
→ 响应和信息收集
→ 诊断与处置
→ 升级和协同
→ 恢复验证
→ 用户确认
→ 回访、关闭和归档
```

每一步说明责任角色、输入、动作、输出和记录。

## 三、时限边界

必须区分：

- 收到请求；
- 首次响应；
- 开始处理；
- 远程诊断；
- 到场；
- 临时恢复；
- 最终解决；
- 工单关闭。

只有招标要求或用户明确确认时才能写具体时限。不能把响应时间写成解决时间，也不能用“第一时间”替代明确边界。

## 四、服务范围

说明质保、免费服务、升级、维护、巡检、备份、咨询、故障、数据、接口和第三方依赖的边界。对采购人环境、第三方系统和非本项目范围的责任应准确区分。

## 五、持续改进

可说明工单统计、问题复盘、知识库、版本建议、巡检报告和服务报告，但不能承诺未确认的固定频次、人数或服务等级。
