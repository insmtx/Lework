# 实施与项目管理方案

## 一、实施方案要回答的问题

- 中标后从什么输入开始；
- 按哪些阶段推进；
- 每阶段谁负责什么；
- 形成什么输出；
- 如何检查可以进入下一阶段；
- 问题、变更、风险和延期如何处理；
- 如何与测试、培训、试运行和验收衔接。

## 二、阶段写法

每个阶段至少说明：

| 要素 | 内容 |
|---|---|
| 阶段目标 | 本阶段需要达成的可判断结果 |
| 前置条件 | 采购人、投标人或环境需要提供的输入 |
| 主要任务 | 具体分析、设计、安装、配置、开发、联调、测试或交接动作 |
| 责任角色 | 使用角色，不虚构姓名和人数 |
| 输出物 | 方案、配置、记录、报告、系统版本或验收材料 |
| 检查点 | 进入下一阶段前必须确认的条件 |
| 问题处理 | 偏差、缺陷、依赖和变更如何登记、处置和关闭 |

## 三、进度计划

- 以招标工期和商务承诺为边界；
- 说明关键依赖和可并行工作，不只给日期表；
- 不在缺少确认时写死具体人员、开始日期和内部资源数量；
- 里程碑必须与交付物、测试、培训和验收一致；
- 若周期短，应说明前置准备、并行推进和关键路径控制，而不是简单压缩时间。

## 四、项目治理

可按项目需要说明：

- 组织角色和职责；
- 例会、报告和问题升级；
- 需求确认和范围控制；
- 配置、版本和发布管理；
- 质量检查和阶段评审；
- 风险登记、触发条件、预防、处置和责任；
- 变更申请、影响评估、审批、实施和验证。

## 五、禁止

- 用一张甘特图或里程碑表代替实施内容；
- 虚构人员姓名、证书、驻场人数或日期；
- 把售后服务写成实施阶段任务；
- 只写“加强沟通、严格管理、确保进度”；
- 在没有依据时承诺无延期、零风险或固定恢复时间。
