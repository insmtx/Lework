# 培训与知识转移方案

## 一、培训目标

培训不是功能演示。应根据不同角色说明培训后需要具备的能力，例如使用、配置、管理、排障、维护或二次建设。

## 二、分层设计

按项目实际区分：

- 业务使用人员；
- 系统管理员；
- 运维人员；
- 技术开发或集成人员；
- 管理和审计人员。

每类对象对应不同目标、内容、实操和考核，不机械复制同一课程。

## 三、培训闭环

```text
培训需求确认
→ 对象与课程设计
→ 环境和材料准备
→ 理论讲解与演示
→ 实操练习
→ 考核与反馈
→ 补训与答疑
→ 培训记录和知识移交
```

说明讲师角色、培训材料、环境、签到、考核、反馈、问题清单和知识移交。

## 四、事实边界

人数、次数、时长、地点、讲师姓名、考核分数和固定答疑周期只有在招标要求或确认事实明确时写具体值。否则写组织机制和确认方式。

## 五、知识转移

根据招标和交付范围说明手册、配置说明、接口文档、运维指南、常见问题、培训课件和操作记录。不得自行承诺不在交付范围内的源代码、全部底层设计或无限期支持。
