# 投标内容合同

## 1. 内容权威

所有正式内容只能建立在以下来源之上：

1. 正式招标文件、补遗和澄清；
2. `requirements.json` 与 `coverage.json`；
3. `目录.json`；
4. 标书底板及 `填写说明.md`；
5. `bidder-facts.json`；
6. `material-index.json`；
7. `pending.json`；
8. 用户明确确认的信息。

参考标书、行业资料和产品通用资料只能在其被明确标记的用途内使用，不能覆盖正式招标要求，也不能自动成为当前项目事实。

## 2. 内容节点合同

每个目录叶节点必须先确定内容类型：

- 叙述型正文；
- 固定表单；
- 简单字段；
- 普通数据表；
- 要求映射表；
- 商务/技术偏差表；
- 附件或证明材料说明。

不同类型使用不同的生成方式。不得用同一套“完全响应 + 功能说明”处理全部章节。

## 3. 叙述型正文最小闭环

每个实质内容单元至少形成：

```text
要求或项目约束
→ 我方响应结论
→ 实现方法或责任安排
→ 处理过程与关键控制
→ 适用边界和异常处置
→ 输出、记录、交付物或验证方式
```

“完全响应、满足、无偏差”只能是结论，不能代替具体响应。

## 4. 表格内容合同

每个表格必须先建立字段语义分析，至少明确：

- 表格名称；
- 原始表头；
- 列顺序；
- 合并单元格关系；
- 一行代表的对象；
- 每列的数据类型；
- 每列的数据来源；
- 缺失值处理；
- 禁止写入内容；
- 是否依赖最终章节或页码。

表头文字决定字段语义。不得将响应内容写入“响应文件章节及条款号”，不得将材料缺口写入“偏差说明”。

## 5. 偏差表内容合同

偏差表必须建立：

```text
招标条款
→ 响应文件真实位置
→ 实际偏差结论
```

其中：

- 响应文件位置必须来自锁定目录和已生成正文；
- 无偏差时只写项目统一的无偏差表述；
- 实际偏差必须准确写明差异；
- 证据缺失和能力未确认必须与偏差状态分开；
- `PEND-*`、`REQ-*`、`FACT-*`、`OUT-*` 不得进入正式表格；
- 待补材料写入待补清单，不写入偏差说明。

## 6. 不得混淆的内容

- 招标要求与投标人既有能力；
- 产品已有能力与本项目拟采用设计；
- 实施阶段动作与已完成结果；
- 验收目标与已通过检测；
- 证据缺失与能力不具备；
- 真实偏差与待确认事项；
- 响应内容与响应文件位置；
- 证明材料位置与偏差说明；
- 参考标书事实与当前项目事实。

## 7. 正式内容边界

正式内容中不得出现：

- 内部 requirement/fact/material/pending/output ID；
- 章节研究、字段分析、写作提示、完成检查和模型说明；
- 未经确认的肯定性事实；
- 伪造截图、证书、报告、签章、页码和测试结果；
- 为迎合评分而虚构的案例、人员、能力和服务等级；
- 待补事项汇总、风险说明或审查备注，除非底板明确要求该字段。
