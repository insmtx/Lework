# 覆盖验证

## 来源闭环公式

`来源单元总数 = 已拆分 + 重复 + 背景 + 定义 + 采购人义务 + 有依据排除`

未处理数必须为 0。

## 不能自证

不能用“已提取要求全部有响应”证明没有漏提。审查必须从来源单元向要求、响应映射、内容和 DOCX 逐层下查。

## 偏差表逐条闭环

对 `deviation_display.table` 为 `commercial` 或 `technical` 的每一条要求，逐条验证：

1. `source_clause` 是一个单一、可定位的正式来源条款；
2. 该来源单元只对应一条要求记录和一行偏差表；
3. 偏差表第二列只展示该来源条款，不并列其他来源；
4. `response_clause` 指向已经形成实质内容的唯一响应小节；
5. `deviation_note` 与该条款、正文和已确认承诺一致。

资格、格式、平台操作和评审程序应存在对应覆盖关系，但不得伪装成商务或技术偏差表行。

## 数量异常

不设置项目固定条款数量。根据以下信号判断异常偏少：

- 大量编号项/表格行只对应少数要求；
- 商务或技术候选池为空但来源存在相关章节；
- 评分/合同/模板回流为零但正式来源包含相应内容；
- 多要求连接词频繁但拆分比例异常低；
- 服务、实施、培训、验收被各概括为单条。

异常必须回查来源，不能为了数量机械拆字词。
