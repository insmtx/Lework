# 待补项规则

## 统一格式

文档占位符：`【待补充：具体事项】`。

`work/项目/pending.json` 每项至少包含：ID、事项、类型、来源要求、目标章节、占位符、影响、提交前是否必须补齐、状态和用户处理结果。

## 分类

- `field`：名称、金额、日期、联系方式等字段；
- `material`：证书、合同、报告、截图等证明；
- `fact`：产品参数、人员、服务时限等事实；
- `signature`：签字、盖章、骑缝章；
- `attachment`：需附但未提供的附件。

## 规则

- 待补项不能作为要求的响应位置；
- 占位符必须出现在最终 DOCX 的实际目标位置；
- 待补清单必须由 `work/项目/pending.json` 生成；
- 解决后更新章节 Markdown，重新完整回填并重新最终审查；
- 不允许把风险性不满足伪装为普通待补。
