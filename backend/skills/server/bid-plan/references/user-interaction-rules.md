# 用户交互规则

## 固定确认

1. `bid-init`：确认模板来源（招标方模板、用户模板或自拟）及其章节边界；未确认不得提取或生成可填写底板。
2. `bid-plan`：集中核对投标主体、关键承诺和材料冲突。
3. `bid-plan`：确认最终目录名称、层级和顺序；确认后目录锁定。

确认直接写入对应权威产物：模板来源与章节边界写入 `work/招标/template-route.json`；事实确认写入 `work/项目/bidder-facts.json` 与 `pending.json`；目录确认写入 `work/投标文件/目录.json`。允许自拟、未找到模板、用户未反对或之后确认目录，都不构成自拟模板确认。

## 异常澄清

以下情况立即询问：正式招标版本冲突、标包不明、资格适用性无法判断、模板路线冲突、用户资料与强制条款直接矛盾。

报价、联系人、证书、业绩、部分参数或签章材料未提供时，可进入待补，不逐项打断流程；但否决项、资格条件、核心评分项或合同承诺的缺失不得伪装为普通待补。
