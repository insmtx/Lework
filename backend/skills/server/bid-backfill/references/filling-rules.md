# DOCX 填写规则

本文件只说明如何安全填写和局部修改 DOCX。项目级 `work/投标文件/填写说明.md` 在每个填写目标的“填写规则”列引用下列规则名称，不在本文件中记录项目阶段或章节状态。

## 规则使用方式

填写说明中的“填写规则”必须使用本文件中的规则名称，例如 `FIELD-UNDERLINE`、`TABLE-FILL` 或 `SECTION-INSERT`。一个目标可以同时引用多个规则，使用逗号分隔。规则名称不能自行创造；确有新类型时，先补充本文件，再更新项目填写说明。

规则只说明如何安全操作，不能替代项目事实、材料或来源 Markdown。不能确认的内容使用 `【待补充：具体内容】`，不得通过常识或其他项目资料补齐。

来源为 Markdown 时，Markdown 语法处理属于回填时的处理方式，不是填写说明中的规则名称；读取 [markdown-to-word.md](markdown-to-word.md) 了解结构识别和样式映射思路。它不授权改变目录、表格、锚点或模板保护范围。

## DOCX-EDIT：既有 DOCX 的编辑路径

- 处理既有 DOCX 时保留未触及的部件、关系、样式、节、页眉页脚和媒体。
- 优先使用可保留原始 DOCX 结构的文档编辑能力；不得使用 `python-docx` 整份打开、重建或保存既有模板。
- 没有合适的文档编辑能力时，才解包 DOCX，直接、局部修改 `word/` 下已唯一定位的 XML，再基于原包重新打包、打开、校验和渲染。
- 禁止整份文档批量重建、跨对象遍历替换、正则或字符偏移修改 Word XML。无法唯一定位或会影响相邻对象时，停止并请求重新确认模板定位。

## FIELD-UNDERLINE：普通字段、下划线和制表位

- 只修改填写目标槽位，不删除前后标签、固定文字、下划线、制表位、单位、括号或标点。
- 填写后检查字体、字号、颜色、对齐、段落属性、下划线长度和单位归属；过长值按模板允许方式换行或调整，不挤压其他槽位。

## MIXED-RUN：多 Run 或混合格式槽位

- 不得使用整段文本替换或 `paragraph.text = ...` 清空段落。
- 依据前后锚点，只修改槽位覆盖的 Run 文本，保留原有 `w:rPr`、固定内容、下划线和相邻对象。
- 找不到唯一前后锚点、槽位跨越不可安全拆分的域或文本框时，停止，不猜测字符位置。

## TABLE-FILL：表格填写与追加

- 保留表头、列顺序、合并关系、边框、列宽、单元格边距、垂直对齐、行高和分页属性。
- 填写说明必须先标明表格标题行、复合表头行、数据起始行、可复制的模板样本行和不可编辑区域。不能把“表格第一行”默认当作数据行。
- 复合表头包括跨列/跨行合并单元格、多行表头、单元格内换行、表头标题行和带单位/说明的组合字段。表头及其合并关系、换行、字体、对齐、边框和行高均属于受保护结构。
- 表头文字可能由普通文本 Run、符号 Run、换行或其他 Word 对象组成；不能因为某个 XML 文本抽取结果为空，就把该单元格判定为空白可填写区。结构识别必须结合 DOCX 对象和渲染结果确认。
- Markdown 表格的表头只用于字段对应校验，不得覆盖 Word 表头；列数、列顺序、单位或字段语义不一致时停止，退回内容或模板阶段处理。
- 只在填写说明授权的数据起始行写入内容。追加数据行必须深复制完整的模板样本行 XML，并保留行级分页、重复表头、单元格合并和段落属性；数据行不得使用固定精确行高，应允许单元格换行并根据内容自动增高，不能截断或遮挡文字。模板明确的最小行高可以保留，但不能阻止内容继续扩展。禁止用 `table.add_row()` 重建复杂表格，禁止先清空表头或数据行再重建。
- 不得拆分、取消合并、重排或重建复合表头；不得把表头标题、单位说明、合计标签或模板占位行误当成数据。
- 填写后逐项核对：表头文本和结构与底板一致，`gridSpan`/`vMerge` 等合并关系未变，数据行起点正确，行数、单元格数量、合计关系、单位、数字格式、自动换行、按内容自适应的行高和跨页效果正确；表格数据必须能回溯到确认材料或章节内容。

### 复合表头填写说明

凡模板表格存在标题跨列、跨行合并、多行表头、单元格内换行、单位说明或组合字段时，填写说明必须在该表格行中明确：

- 表格标题行和复合表头行的范围；
- 数据起始行和可深复制的模板样本行；
- 表头、合并关系、列顺序、单位、固定说明和占位行等不可编辑区域；
- 表头文字可能以换行、符号或其他 Word 对象保存，不能仅根据纯文本提取结果判断表头是否为空；
- Markdown 字段与 Word 表头字段的对应关系；
- 填写后需核对的行数、合计、跨页和表头保真要求。

Markdown 表头不得直接覆盖 Word 表头。无法确认数据起始行、样本行或字段对应关系时，必须停止回填并退回模板填写说明阶段。

## SECTION-INSERT：自拟正文或章节插入

- 仅在填写说明明确的插入锚点之间写入对应内容；保留章节标题、固定提示、节设置、页眉页脚和后续章节顺序。
- 标题文字、级别和顺序以锁定目录节点为准；Markdown 标题只能用于校验内容归属，不能覆盖目录标题、创建新目录节点或改变父子关系。
- 一个插入锚点可以承载一个目录子树；按目录顺序输出节点标题及正文，不要求每个叶节点有独立文件夹或独立锚点。
- 标题、正文、列表和表格优先使用填写说明已确认的模板样式，不把结构化内容拼成一段纯文本；没有直接对应样式时，按填写位置继承相邻同类样式并自适应转换。只有稳定锚点或目标结构不明确时才停止并退回模板阶段。
- 不得借插入正文删除固定章节、固定提示或已确认的目录结构。

## DIRECTORY-SUBTREE：目录子树与内容归属

- 以 `目录.json` 的 `chapter_id`、层级、`order` 以及项目已有的父子关系字段确定节点关系；不得由 Markdown 的 `#` 层级或文件名序号推断新的目录结构。
- 内容文件夹可以对应一个父节点及其多个后代节点。必须根据填写说明、文件名和首标题把每个 Markdown 唯一归属到已有节点；无法唯一归属时停止。
- 目录标题可带展示编号，但编号由目录或模板编号规则产生；不得把 Markdown 中的手写编号再次写入使用自动编号的 Word 标题。
- 目录、填写说明和模板目标发生不一致时，回到拥有该产物的阶段修复；不在回填阶段新增临时映射文件掩盖不一致。

## SECTION-LAYOUT：标题、目录与分页

- 标题级别以项目填写说明中的定位为准，不以字体大小或视觉相似度猜测。
- 大章节必须有明确的前置分页；发现缺失时必须在模板阶段补加，不能只记录问题或留给回填阶段。使用分页符或节，不用连续空行制造分页。
- 优先保留并更新既有目录域。无法安全更新域时，使用可审查的手工目录，并在项目填写说明中注明限制。

## ATTACHMENT-SIGN：附件、签字与盖章

- 按填写说明中的附件目标插入文件或图片，插入前检查清晰度、方向、裁切、页边距、敏感信息和页序。
- 缺少附件时保留明确占位，不伪造扫描件；签字、盖章和人工日期不能由 AI 代签或伪造。
- 保留签章线、签字提示、日期分段和固定说明；插入附件后仍要检查页眉页脚、分页和可读性。

## TEMPLATE-PROTECT：模板固定内容与结构保护

- 未在项目填写说明中明确为可编辑目标的内容，均视为受保护：封面固定文字、响应函固定条款、表头、编号定义、样式、书签、目录域、节设置、页眉页脚、签章线和日期结构。
- 只执行填写说明允许的局部操作；不得为方便填充而删除固定文字、清空整段、改变表头、破坏合并或重排章节。
- 发现固定文本或结构异常时停止当前操作，保留上一份可用文件，重新确认填写目标和局部操作方式。
