# 投标文件回填流程

由投标文件工程师执行。该 Skill 只规定回填流程、输入依赖、单元推进和验收边界；DOCX 的具体填写规则统一见 `references/filling-rules.md`，不在本文件重复展开。

目录树决定回填顺序，`bid-template` 产出的项目填写说明决定当前项目的目标、位置、填写方式和保护范围，来源 Markdown 只提供已准备好的内容。不得在回填阶段重新设计目录、解释招标条款、改写内容或猜测模板结构。

## 进入条件与依赖

进入前必须确认以下产物已经由所属阶段完成：

| 依赖 | 用途 |
|---|---|
| `work/投标文件/模板/可填写底板.docx` | 每次回填的 DOCX 起点 |
| `work/投标文件/填写说明.md` | `bid-template` 产出的项目级目标、锚点、内容形态、规则引用、保护范围和版式要求 |
| `work/投标文件/目录.json` | 已确认的目录节点、层级和顺序 |
| `skills/bid-backfill/references/filling-rules.md` | 通用 DOCX 字段、表格、正文、附件和保护规则 |
| `skills/bid-backfill/references/markdown-to-word.md` | Markdown 结构处理思路、Word 映射和模板样式统一原则 |
| `work/填充内容/` | `bid-content` 已准备的唯一实质性内容来源 |
| `work/项目/待补充清单.md` | 待补事项和占位边界 |

`work/投标文件/填写说明.md` 不存在、未完成，或与底板/锁定目录不一致时，停止并退回 `bid-template`；不得用临时映射或自拟规则绕过闸门。

## 执行流程

### 1. 建立本次回填清单

读取目录、项目填写说明、来源 Markdown、待补清单和通用填写规则，在当前执行中建立回填清单：回填单元、目录顺序、内容来源、项目填写目标、保护范围和验收要求。清单只在本次执行中使用，不另存 JSON 或其他中间文件。

回填单元可以是字段、表格、附件，也可以是由一个 DOCX 正文目标承载的目录子树。共享内容文件夹中的 Markdown 必须能够依据项目填写说明和目录唯一归属；归属不清、目标缺失、规则未引用或保护范围不明时，停止并退回所属阶段。

### 2. 创建当前单元临时候选

按目录顺序选择当前未完成的回填单元：

- 没有最新候选文件时，从可填写底板复制到 `work/.tmp/`；
- 已有最新候选文件时，从该文件复制到新的单元临时路径；
- 临时文件不能覆盖底板、上一份已验证候选文件、`output/` 或正式交付文件；
- 本单元失败时关闭并丢弃临时文件，保留上一份已验证候选文件。

### 3. 按规则回填当前单元

先读取本单元在 `work/投标文件/填写说明.md` 中的目标行和规则引用，再读取 `references/filling-rules.md` 中对应规则；来源为 Markdown 时，继续读取 `references/markdown-to-word.md`，最后处理该单元的来源内容。

回填时只执行项目填写说明授权的局部操作。标题层级、字段槽位、表格数据区、复合表头、正文插入区、附件位置、签章区和分页均按项目填写说明及通用填写规则处理；遇到规则未覆盖、目标不唯一或模板结构无法安全保留的情况，停止，不作猜测性降级。

处理来源 Markdown 时，先按 `markdown-to-word.md` 的思路识别结构并确认与目标 Word 对象的对应关系，再局部写入。字体、字号、颜色、段落和列表样式优先继承标书模板的同类对象；无法直接沿用模板样式时，按填写位置、相邻同类内容和模板整体版式选择最近样式，自适应转换为 Word，并清除所有 Markdown 标记。只有目标结构不明确或会破坏受保护边界时才停止。

不得使用 `python-docx` 重建既有 DOCX；具体编辑方式、样本行复制、保护内容和占位处理以 `references/filling-rules.md` 为准，Markdown 的结构处理和样式选择以 `references/markdown-to-word.md` 为准。

### 4. 完成本单元验收

保存并重新打开单元临时候选，至少核对：

- 当前单元写入了正确目标，未越过稳定锚点或影响相邻单元；
- 目录顺序、标题层级、字段标签、固定文字、页眉页脚和分页符合项目填写说明；
- 表格数据从授权区域开始，复合表头、合并关系、列顺序、单位、样本行和跨页结构保持不变；
- Markdown 的块级/行内节点顺序与来源一致，标题、列表嵌套、强调、链接、图片、代码、硬换行和表格均已按处理说明表达；
- 没有可见 Markdown 标记、伪列表、竖线表格、丢失的链接/图片目标或未经授权的降级；
- `【待补充：具体内容】` 仍位于对应目标，未被删除、隐藏或替换为虚构内容；
- DOCX 能重新打开，当前页和相邻页渲染后可读，未出现溢出、截断、空白页、乱码或结构错位。

验收不通过时，定位到来源内容、项目填写说明、底板或操作方式，丢弃本单元临时文件后修复；不得修改上一份已验证候选文件。

### 5. 原子推进候选文件

本单元验收通过后，原子替换：

```text
work/投标文件/候选投标文件.docx
```

该文件成为下一单元唯一输入起点。每个回填单元都必须完成“复制输入 → 回填 → 验收 → 原子推进”，不能以批量处理结果代替单元验收。

### 6. 全部单元完成后交接

所有锁定目录节点及其内容子树按顺序完成，且候选文件通过整体可读性检查后，交接候选 DOCX、项目填写说明、目录、待补清单和来源内容给 `bid-final-review`。候选文件未经独立终审不得复制到 `output/`。

## 失败恢复与完成标准

| 故障 | 处理 |
|---|---|
| 项目填写说明缺失、未完成或与底板/目录不一致 | 退回 `bid-template`，不进入回填 |
| 来源 Markdown 缺失、归属不唯一或内容结构无法转换 | 退回 `bid-content` 或依据规则停止，保留上一份候选 |
| DOCX 目标、表格数据区、样本行或保护边界无法唯一确认 | 退回 `bid-template`，不猜测位置 |
| 本单元回填或渲染失败 | 丢弃单元临时文件，保留上一份候选并从问题所属阶段修复 |
| 目录、模板、填写说明或来源内容发生变化 | 从最早受影响阶段重新生成下游产物和候选文件 |

完成条件：所有目录节点按顺序处理；每个回填单元均有独立验收并原子推进；候选 DOCX 结构和版式可读；固定模板元素和复合表格结构保全；未通过独立终审前不发布正式文件。
