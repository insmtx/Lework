# 输入资料映射

## 人员底表

优先读取：姓名、部门/分公司、部门/项目、性别、岗位、人员类别。匹配键为归一化后的“姓名 + 项目 + 人员类别”。去除姓名空格和末尾括号备注。表内无项目或人员类别时，可用文件名中的项目前缀和用工类别短语补充；不得凭常识猜测未在文件名或表内出现的名称。更具体的用工类别（如「某某外包」）与泛称「外包」视为兼容。

“在册”人员不进入外聘工资计算，但要进入忽略清单。考勤出现而底表不存在的人员不得静默丢弃。

## 历史工资表

提取姓名、岗位名称、工作天数、基本工资、绩效工资、工龄工资、施工补贴、交通补贴、话费补贴、加班标准/天数/金额、降温费和人工应发工资。表头中的“基本工资”就是工资规则中的“岗位工资”，不能因为不存在名为“工资标准”或“岗位工资”的字面列而判定工资基准缺失。`双休日加班`下的“标准/个数/金额”是加班字段组，`1-3月话补`是话费补贴字段，`降温费`是高温补贴候选字段。

优先读取 Excel 公式及明确金额；公式列之间矛盾时记录警告，不用公式形状替代业务规则。合计行、项目小计行和空白模板行不得当作人员工资基准。

固化为工资基准：岗位工资（基本工资）、绩效标准、工龄/职称工资、施工补贴日标准、话补金额和适用期、高温补贴及是否计入应发、交通补贴、特殊加班日标准和是否参与加班。若历史表中的施工补贴是“工作天数×日标准”的月金额，必须先除以历史工作天数还原日标准。只有人员行缺少用于某一分项的字段时，才标记该分项缺失；仍应使用其他已识别字段继续核算。

## 当月考勤

扫描 PDF 或图片通常没有文本层，需要视觉识别。PDF 先用 Skill 脚本 `scripts/extract_attendance.py` 渲成页图，再由当前多模态模型直接看图。保存项目、月份、页码、行号、姓名、每日标记、实际出勤、休息和请假汇总。`8` 通常表示正常出勤；`休`、`调`、`走`、`/` 等符号必须依据识别结果和规则字典处理，未确认时进入复核。

## 输出

至少包含：工资计算结果、工资基准缺失清单、差异清单、人工复核提示、每项来源证据和最终金额。缺失基准人员不应阻塞其他可计算人员；整个月份缺少基础工作日规则时，只停止加班分项并提示，不得因此阻塞其他已确认工资分项。
