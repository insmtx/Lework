# 标书整体格式校验

本文件只校验候选 DOCX 相对可填写底板和项目填写说明的整体格式保真，不替代内容、事实、要求覆盖或待补项审查。

## 校验基准

必须同时读取：

- `work/投标文件/模板/可填写底板.docx`：模板结构和固定格式基准；
- `work/投标文件/填写说明.md`：本项目允许填写的目标、数据区、锚点、保护范围和版式要求；
- `work/投标文件/目录.json`：锁定目录的标题、层级和顺序；
- `work/投标文件/候选投标文件.docx`：待校验候选文件。

不能根据自拟格式、Markdown 的视觉层级或抽取文本结果推断模板格式。没有底板或项目填写说明时，整体格式校验不能通过。

## 底板自身一致性

在比较候选文件前，先检查底板自身是否自洽：

- 目录中的章节标题、正文中的章节标题和项目填写说明中的标题一致；
- 底板中的章节顺序、前置分页、表格位置、固定标签和填写说明目标互相对应；
- 同一固定标题、表头、签章提示或单位说明不存在互相冲突的版本。

底板自身存在冲突时，不能把候选文件对底板的忠实保留判为回填错误；应将问题记录为模板基准问题，退回 `bid-template` 修复底板和项目填写说明后，再重新回填和终审。

## 整体结构校验

- DOCX 可以打开、重新打开，包内 XML、关系、样式、编号、媒体和节结构完整；
- 封面、目录、主要章节标题、章节顺序和固定标题与底板及项目填写说明一致；允许新增内容必须位于已授权目标或目录子树内；
- 底板已有的页眉、页脚、页码、分节、页面尺寸、方向、页边距和大章节前置分页保持有效；页数可以因填写内容增加，但不能以空行堆叠或意外分页替代模板要求；
- 固定文字、标签、单位、编号定义、签章线、日期分段、固定提示和保护区域未被删除、覆盖、改写或移动；
- 标题层级和编号没有因 Markdown 手写编号、Word 自动编号或样式继承而重复、错级或串号。

## 表格格式校验

按照项目填写说明逐表核对，不以“表格能打开”作为通过条件：

- 表格顺序、数量、列顺序、列宽、表格宽度、边框、单元格边距、对齐和分页属性与底板一致；
- 标题行、复合表头行、数据起始行、模板样本行和不可编辑区域与填写说明一致；
- 跨列/跨行合并、多行表头、单元格换行、单位说明、组合字段、合计标签和固定占位行保持不变；
- 新增数据行来自完整模板样本行，未以新建无样式行替代，也未把 Markdown 表头写入 Word 表头；
- 不能仅根据 `w:t` 文本是否存在判断表头为空；需结合 `w:sym`、换行、文本框或其他 Word 对象以及渲染页面确认；
- 表头结构、`gridSpan`/`vMerge` 等合并关系、数据行起点和跨页效果与底板及填写说明一致。

## 页面和视觉校验

候选 DOCX 必须渲染后逐页检查：

- 页眉、页脚、页码、章节标题、表格、图片、附件和签章区没有被裁切、遮挡、溢出或挤出页面；
- 没有异常空白页、连续空段落造成的假分页、标题孤行、表格断裂、表头丢失、字体替换或乱码；
- 重点检查每个回填单元及其相邻页面，并覆盖全文页码范围；不能只抽查技术方案或最后几页；
- 对比底板时以结构和视觉格式为基准，不要求候选页数、正文长度或动态数据内容与底板相同。

## 结论和返修路径

每个格式问题必须在最终审查报告中记录文件页码/章节/表格或对象位置、底板对照证据和返修路径；不另建 JSON 检查结果。

- 底板本身缺少必要结构、样式、分页或填写目标：退回 `bid-template`；
- 候选文件破坏了底板结构、超出目标或装配错误：退回 `bid-backfill`；
- 来源内容导致合法布局溢出或需要重新组织内容：退回 `bid-content` 或 `bid-backfill`，不得在终审阶段直接改候选文件。

整体格式校验通过的条件是：候选文件保留底板的固定结构和视觉格式，所有差异都能由项目填写说明授权的填写内容解释，且渲染页面逐页可读。
