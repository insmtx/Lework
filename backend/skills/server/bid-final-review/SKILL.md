# 最终独立审查

由独立投标质量审查官执行。审查对象是完整候选 DOCX、原始正式文件、锁定目录、要求覆盖关系、确认事实、待补清单和填写说明；审查结论基于最终候选文件及其渲染结果。审查者不得编辑候选文件、模板或 Markdown。

## 进入闸门、独立性与输出

进入前：候选文件、锁定目录、要求覆盖关系、确认事实、待补清单和填写说明完整存在，且审查者未参与内容、模板或回填生产。

| 产物 | 路径 | 要求 |
|---|---|---|
| 审查报告 | `work/独立复核/最终审查报告.md` | 唯一审查结论载体；面向项目负责人列出范围、证据、问题、返修路径和结论 |
| 渲染审阅记录 | `work/独立复核/` 下的本次记录 | 记录页码/页面对象/可见问题，不能只写“已检查” |
| 正式输出 | `output/` | 仅通过后的一份 DOCX 与一份待补充清单 Markdown |

## 执行流程

### Step 1：锁定审查对象和输入版本

读取候选 DOCX、原始正式文件、目录、要求覆盖、事实基线、材料索引、待补清单和填写说明。确认候选文件是在当前锁定目录、底板和 Markdown 基础上生成；如果其中任一项在回填后变化，终审无效，应从最早受影响阶段重新执行。

审查范围必须覆盖完整文件，包括资格、商务、技术、报价/表单、附件、目录、页眉页脚、页码、签章和待补提示，不得只抽查内容章节。

### Step 2：执行结构化独立审查

独立审查官先按 `references/overall-format-check.md` 对候选 DOCX 与可填写底板、项目填写说明进行整体格式对照，再按 `references/final-checklist.md` 执行内容、事实、待补项和交付检查。两类检查均须形成可定位证据。

格式对照和内容审查至少覆盖：

1. 强制项、否决项、评分项、合同义务和固定表单是否有正确响应位置；
2. DOCX 声明是否与确认事实、材料和待补项一致，是否存在虚构、矛盾、过期或未标识占位；
3. 填写说明和最终候选是否一致，是否有 Markdown 漏回填、错位或误入固定区域；
4. 输出是否可提交，且待补项是否明确区分“可保留”与“提交前必须补齐”。
5. 商务、技术偏差表是否从原始正式文件逐条闭环到要求记录、单一表格行、真实 Markdown 小节和 DOCX 单行。

每个问题必须附可观察证据：页码/章节/表格单元格/字段位置，以及对应的来源要求、确认事实或待补项。禁止给出没有定位的“建议再优化”。

### Step 3：进行渲染与视觉审阅

将候选 DOCX 渲染为可逐页检查的形式，检查文字截断、空白页、表格跨页、目录页码、页眉页脚、签章区域、图片/附件、页码连续性、字体替换和可读性。只在“渲染成功且逐页检查完毕”后记录渲染审阅结果；不能把文件能打开视为视觉通过。

候选文件一旦发生任何内容、格式或重新回填变化，旧终审和旧渲染记录立即失效，必须重新执行本阶段。

### Step 4：形成结论与返修路径

写入 `work/独立复核/最终审查报告.md`。报告必须包含审查范围、审查者、问题计数、逐项 findings、可验证摘要、返修路径和唯一结论行。结论行使用固定格式：`审查结论：通过`、`审查结论：需要修改` 或 `审查结论：不通过`。

存在任一 blocking 或 major 问题时，结论不得为“审查结论：通过”。审查官只提出返修位置与证据：内容问题退回 `bid-content`，模板/填写说明问题退回 `bid-template`，DOCX 装配问题退回 `bid-backfill`，目录/要求问题退回 `bid-plan`。不得自行修订候选文件。

返修后，从最早受影响阶段重新建立受影响产物，重新回填并从头终审；不能只修改旧报告中的结论或问题计数。

### Step 5：发布正式交付物

只有 `最终审查报告.md` 中存在固定结论行 `审查结论：通过`，且候选 DOCX 与待补充清单都存在时，才可发布：

```bash
python3 skills/bid-final-review/scripts/publish_output.py \
  --project-root "$PROJECT_ROOT"
```

发布后 `output/` 必须且只能包含一份正式 DOCX 与一份待补充清单 Markdown。不得把审查草稿、渲染页、临时 DOCX 或多个候选副本放入 `output/`。

## 阻塞、恢复与完成标准

| 情况 | 处理 |
|---|---|
| 阻断或重大问题 | 写入证据和返修路径，退回最早拥有问题产物的阶段。 |
| 用户必须决定是否接受风险 | 明确说明风险、受影响位置和可选处理；未获明确决定不得宣称可提交。 |
| 渲染失败或视觉问题 | 不发布；修复 owning artifact 后重新回填和重新审查。 |
| 输出目录已有旧文件 | `publish` 只在报告通过后事务化更新；不要手工混放或增删多个正式版本。 |

完成条件：审查报告存在且结论为“审查结论：通过”；没有 blocking/major 问题；完整候选已通过结构、语义和逐页渲染审查；`output/` 恰有一份 DOCX 和一份待补清单。
